# v0.1.0 数据、来源、外发与保留策略

## 决策边界

v0.1.0 假设当前配置的本地模型、国内模型、MinerU 和 Gildata MCP 已由公司批准并满足安全要求。
产品不在首版内验证 provider 物理位置、数据出境路径或供应商合规资质。

`public` 及当前任务中由 data_owner 提供或明确授权的 `internal` 材料可以发送到这些批准 provider。
该授权不扩展到 `confidential`、`restricted`、凭据、未授权个人敏感信息或任务范围外的内部资料。

## 数据分级矩阵

| 分级 | 外部模型 | 外部 MinerU | MCP | 默认降级 |
| --- | --- | --- | --- | --- |
| `public` | 允许使用批准 provider。 | 允许使用批准 provider。 | 允许授权查询。 | provider 不可用时等待或使用本地处理。 |
| `internal` | 仅当前任务 data_owner 已提供或授权的内容允许。 | 同左，仅限文件解析所需内容。 | 仅授权 server、tool 和 query 范围。 | 删除非必要字段，或等待 data_owner 缩小范围。 |
| `confidential` | 默认禁止；v0.1.0 不提供模型自行申请例外。 | 默认禁止。 | 仅明确批准的内部 MCP 路径。 | 等待 data_owner 与信息技术部共同批准替代路径。 |
| `restricted` | 禁止。 | 禁止。 | 默认禁止；只允许专项批准的内部确定性工具。 | fail closed，停止相应步骤。 |

下列内容无论材料分级如何都不得进入模型、MinerU、日志或 trace：token、secret、完整 response_url、
签名下载 URL、私钥、数据库连接串、宿主绝对路径和未授权的个人敏感信息。

## 来源与许可规则

| 来源 | 必须保存 | 正文或快照边界 |
| --- | --- | --- |
| Gildata MCP | server/tool id、query 摘要或加密 query、数据版本、时间、result digest、许可说明。 | 许可允许才保存 excerpt；禁止复制时只保存 digest 和稳定复核信息。 |
| 用户上传内部材料 | data_owner、分级、用途、file digest、访问名单、保留期。 | 只在任务 scope 内解析；不把 original 写入 prompt、日志或 trace。 |
| 公开网页 | locator、retrieved_at、发布主体、许可、snapshot status、digest。 | 尊重版权、robots 和来源条款；长篇正文不进入报告资产。 |
| 公司披露和监管文件 | 文件版本、发布日期、章节或页码定位、digest。 | 许可允许时保存受控快照；引用保留定位和必要 excerpt。 |

每个关键 Claim 至少绑定一个 Evidence。无快照且无法稳定复核的关键 Claim 必须标记风险；
来源冲突必须形成 EvidenceConflict，不使用 last-write-wins 消除分歧。

## Provider 与传输要求

- provider 必须在配置 allowlist 中，endpoint、模型和用途可审计；
- 传输使用 TLS，凭据只从 secret store 注入；
- provider 的批准和供应商安全审查属于部署前置条件，不由模型或运行时自行判断；
- egress 事件只记录 provider id、分类、规则版本、decision、payload digest 和 error type；
- 发送前做字段级最小化，完成后不在应用层缓存完整请求或响应；
- 外发被拒绝时生成可解释状态，不允许模型覆盖策略决定。

provider registry 至少保存以下字段：

| 字段 | 含义 |
| --- | --- |
| `provider_id` | 稳定 provider 标识。 |
| `endpoint` / `model` | 受控 endpoint 和允许模型。 |
| `approval_ref` | 公司批准记录的受控引用。 |
| `approved_data_classes` | provider 获准处理的数据分级和字段范围。 |

运行时只执行 allowlist 和数据分级决定，不重新评估公司已完成的 provider 安全审批。

## 保留期

以下值是 v0.1.0 的产品默认值。公司档案制度要求更长期限时，以公司制度覆盖默认值：

| 对象 | 建议保留期 | 到期动作 |
| --- | --- | --- |
| response capability 明文 | 最长至创建后 1 小时，成功消费后立即删除。 | 只保留不可逆 digest 和最小发送事件。 |
| 任务工作文件和未提交草稿 | 交付或终止后 30 天。 | 删除 original、解析缓存、临时转换文件和未提交中间稿；保留审计摘要。 |
| 许可允许的来源快照与 Evidence | 180 天。 | 到期删除正文；按需保留 locator、digest 和许可记录。 |
| Gildata 查询结果 | 按商业许可，默认不保存完整结果；query/digest 建议 180 天。 | 删除结果正文，保留最小复核记录。 |
| 已提交评审的草稿和 ReviewComment | 3 年。 | 与对应 WorkItem 和 artifact version 一起转档或删除。 |
| 已批准报告、来源清单和证据清单 | 3 年。 | 转档或按公司制度删除。 |
| WorkItem、WorkEvent、批准记录和安全审计 | 3 年。 | 转档或按公司制度删除。 |
| secret、token、签名 URL | 0 天。 | 不进入持久业务存储、日志或 trace。 |

以上是产品默认值。公司档案制度要求更长期限时，以公司制度覆盖默认值，不在 v0.1.0 内建设通用监管档案引擎。

## M0-05 冻结证据

战略发展部委派人于 2026-07-12 确认：

1. 接受 `public`、授权 `internal`、`confidential`、`restricted` 四级矩阵；
2. 当前配置的本地模型、国内模型、MinerU 和 Gildata MCP 视为已批准且安全；
3. 接受 30 天临时文件、180 天来源证据、3 年评审版本和正式记录的默认保留期；
4. Gildata 按当前授权使用，query、excerpt 和结果快照继续受现有许可约束；
5. token、secret、签名 URL 和完整 response_url 不进入持久业务存储、日志或 trace。

信息技术部 Agent 运维负责把批准 provider、secret store、TLS、日志和 artifact store 边界落实到生产配置。

## M1 实现验收

- 至少一个允许和一个拒绝的 egress fixture 通过确定性策略测试；
- 临时文件、来源证据、评审版本和批准版本分别命中 30 天、180 天和 3 年保留规则；
- 未提交草稿与已提交评审草稿不会进入同一清理路径；
- provider、模型和 MCP 不能绕过 allowlist、数据分级、最小化、日志脱敏和审计。
