## 状态定义

| 状态 | 含义 |
| --- | --- |
| `OPEN` | 决策、材料或验证证据尚不完整。 |
| `READY` | 建议决策和验收标准已完整，等待责任人签定。 |
| `FROZEN` | 责任人已确认，证据位置和冻结版本已登记。 |
| `NO_GO` | 关键条件不成立；必须缩减范围、替换方案或停止进入 M1。 |

## M0-03 企业微信短连接延迟回复

### 已确认决策

| 字段 | 冻结值 |
| --- | --- |
| channel mode | 保持当前 AI Bot 短连接回调，不在 v0.1.0 切换长连接。 |
| capability | 使用新鲜回调携带的 `response_url` 做一次延迟回复。 |
| 有效期 | 官方有效期 1 小时；每个 URL 只能调用一次。 |
| 执行预算 | 默认任务执行上限 50 分钟，通知预留 5 分钟，不以 60 分钟作为可用预算。 |
| 超时行为 | 50 分钟仍未完成时停止继续研究，用唯一一次延迟回复发送超时/部分结果状态。 |
| 文件交付 | 延迟 Markdown 提供受控下载入口；不宣称 `response_url` 可以直接推送 DOCX。 |
| 长任务 | 超过 1 小时的任务不进入 v0.1.0 首版。 |
| 后续演进 | 长连接 AI Bot 和自建应用主动消息均后置。 |

### 必须完成的探针

| 探针 | 通过条件 | 证据位置 |
| --- | --- | --- |
| 当前 stream | 测试口令立即完成当前 stream。 | `V0.1.0_M0_WECOM_RESPONSE_URL_PROBE.md`，等待 Mac mini 结果。 |
| 延迟回复 | 10 秒后同一 AI Bot 会话收到第二条 Markdown。 | `V0.1.0_M0_WECOM_RESPONSE_URL_PROBE.md`，等待 Mac mini 结果。 |
| 一次性 | 一个 URL 只发送一次，不做重复消费。 | 自动化测试 + Mac mini 消息计数。 |
| 过期 | 过期或已消费 URL 失败关闭，用户改用任务查询。 | `TBD` |
| 安全 | URL 不进入 model context、日志或 trace，只记录状态和 error type。 | 自动化测试 + Mac mini 脱敏检查。 |

### 决策分支

| 探针结果 | 冻结决策 |
| --- | --- |
| 延迟回复通过 | 50 分钟内任务使用一次性完成/超时通知；DOCX 使用受控下载入口。 |
| 延迟回复失败 | v0.1.0 降级为当前 stream 内完成，或由用户查询任务和下载产物。 |
| 任务超过预算 | 终止本次执行并交付已完成部分；不静默继续占用过期 capability。 |

### 通过条件

- 技术证据来自公司网络 Mac mini 的真实测试。
- 回调 msgid、WorkItem、response capability digest 和 artifact 均可审计。
- 降级方案由战略发展部委派人明确接受。

### 来源类型登记

| 来源类型 | 必填决策 |
| --- | --- |
| 企业 MCP | 首版使用 Gildata MCP server；保存授权范围、查询摘要、数据版本、result digest 和保留期。 |
| 商业数据库 | 许可条款引用、query 保护、excerpt 权限和复核方式。 |
| 公开网页 | locator、抓取时间、快照策略、robots/版权约束和保留期。 |
| 用户上传文件 | data_owner、保密等级、用途、保留期和删除规则。 |
| 内部文件 | 访问名单、外发禁令、快照位置和审计要求。 |

### 强制规则

- 每个 SourceRecord 记录 locator、`retrieved_at`、许可说明和 result digest。
- 商业来源记录 query；敏感 query 加密保存，日志只保留 digest。
- 许可允许时保存 Evidence excerpt。
- 许可禁止摘录时记录 `excerpt_status=prohibited`，不复制受限正文。
- 无快照且无法稳定复核的关键 Claim 必须在质量门中标记风险。
- egress policy 在调用模型、MinerU、MCP、消息和文件交付前执行。

### 通过条件

- 四级数据的允许 provider、禁止 provider 和降级路径均已填写。
- 每种验收来源都有许可、快照和保留决策。
- requester/data_owner 对任务输入范围完成确认。
- 信息技术部确认密钥、日志、trace 和 artifact 存储边界。

## M0-06 评审 UX 与任务路由合同

### 评审 UX

| 项目 | 冻结值 |
| --- | --- |
| 锚点 | 稳定 `section_id`，不使用可变章节序号作为唯一键。 |
| 显示 | `S03 核心能力`、`C02 关键结论` 等稳定编号和标题。 |
| 绑定 | ReviewComment 绑定 WorkItem、artifact version、section_id 和当时标题。 |
| 动作 | 提交意见、通过提纲、退回修改、批准最终版。 |
| 后置能力 | Word 批注导入。 |
| 确认记录 | 战略发展部委派人于 2026-07-12 确认。 |

### 路由合同

满足任一条件时必须创建 WorkItem：

- 产生或修改已登记的正式 artifact；
- 进入 `waiting_external`、`waiting_input`、`waiting_review` 或 `waiting_approval`；
- 跨多个 turn、系统或可恢复 phase；
- Playbook 或 tool contract 声明 `work_mode=required`；
- requester 明确要求建立、跟踪或审计正式任务。

同步写操作只有同时满足以下条件才允许 DirectTurn：

- tool contract 声明 `work_mode=direct_allowed`；
- confirmation 已完成；
- idempotency 已启用；
- MCP audit 已启用。

tool contract 最小字段：

```text
work_mode = required | optional | direct_allowed
side_effect = read | write | risky
supports_idempotency = true | false
```

### 通过条件

- runtime 可以确定性判断 DirectTurn 或 WorkItem，模型不能修改 `work_mode`。
- 正式报告任务始终创建 WorkItem。
- ReviewComment 在章节重排后仍指向原 section。
- 批准只对明确的 artifact version 生效。
