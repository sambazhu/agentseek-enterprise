### 状态边

```text
draft -> queued | cancelled
queued -> running | failed | cancelled
running -> waiting_external | waiting_input | waiting_review | waiting_approval
running -> succeeded | failed | cancelled
waiting_external -> queued | failed | cancelled
waiting_input | waiting_review | waiting_approval -> queued | cancelled
succeeded | failed | cancelled -> terminal
```

### PostgreSQL 建模建议

- **WorkItem 表**：标量字段 → 列（VARCHAR / TIMESTAMPTZ / INT / ENUM-or-VARCHAR）；`brief` → `JSONB`；`input_file_ids`/`source_ids`/`artifact_ids`/`skill_digests` → `VARCHAR[]` ARRAY（v0.1.0 首版简单）或 junction 表（需 FK 查询时）；`version` → 乐观锁 `UPDATE … WHERE work_id=$1 AND version=$expected`。
- **WorkEvent 表**：append-only；`event_id` PK（UUID）；`work_id` FK + index；`occurred_at` index / 按月分区（保留期到期删除）。`(work_id, work_version)` 唯一约束防重复事件。
- **WorkBudget 表**：`budget_id` PK；`WorkItem.budget_id` FK。
- **idempotency**：`(tenant_id, idempotency_key)` 唯一约束。
- **lease**：`lease_owner` + `lease_expires_at` → worker claim 后定时扫描过期 lease → 回收。

### 一项设计观察（非阻断）

- `transition_work_item` 的 `phase` 参数允许在**任意** transition 改 phase（含 WAITING_*→QUEUED）。M0 设计意图是 phase 只在进入新阶段（RUNNING）时变；当前允许在恢复（QUEUED）时改 phase。这依赖调用方自律，不是状态机约束。**建议**：M1-02 repository 层的 `resume` 方法不传 `phase` 参数（保持 `item.current_phase`），只有显式推进阶段才传。

### 结论：**PASS — 允许进入 M1-02**

10 项合同复核全 PASS（1 项 ⚠️ 非阻断建议）。models.py + state_machine.py 的状态边、终态、乐观锁、attempt 语义、timezone 约束和审计字段均与 M0 freeze 一致，适合作为 PostgreSQL schema 基础。
agentseek-work 保持通用，不含域逻辑。MappingProxyType brief 的 JSON 摩擦和 phase 参数自律建议已在上方记录，供 M1-02 repository 实现时注意。

## Slice M1-02：PostgreSQL ledger repository

### 已实现

| 能力 | 合同 |
| --- | --- |
| 初始 schema | `enterprise_work_budgets`、`enterprise_work_items`、`enterprise_work_events` 和 schema version 表。 |
| PostgreSQL 类型 | `brief`、skill/file/source/artifact id 快照使用 JSONB；状态使用 VARCHAR + CHECK，避免 native enum 迁移锁定。 |
| 初始 migration | revision 1 幂等创建 schema，并拒绝高于当前代码支持版本的数据库。 |
| tenant scope | WorkItem 读取、事件读取和状态更新都要求 `tenant_id`。 |
| 幂等创建 | `(tenant_id, idempotency_key)` 唯一；并发唯一约束竞争后读取并返回原 WorkItem。 |
| 乐观并发 | `UPDATE ... WHERE tenant_id AND work_id AND version=expected_version`；更新行数不是 1 时 fail closed。 |
| 原子事务 | WorkItem update 和 WorkEvent insert 使用同一事务；事件约束失败时状态更新回滚。 |
| append-only event | repository 不提供 WorkEvent update/delete；`(work_id, work_version)` 唯一。 |
| JSON 边界 | `MappingProxyType` 显式转 `dict`，所有 JSON 文档在写库前执行严格 round-trip；拒绝 object、NaN 等值。 |
| phase 约束 | phase 只能在进入 `running` 时改变；waiting 恢复到 queued 不能偷换 phase。 |

### 数据库约束

- WorkItem 主键：`work_id`；
- WorkItem 幂等唯一键：`tenant_id + idempotency_key`；
- WorkEvent 主键：`event_id`；
- WorkEvent 版本唯一键：`work_id + work_version`；
- WorkEvent `work_id` 外键：`ON DELETE RESTRICT`；
- WorkStatus、ActorType、非负 version/attempt 和 WorkBudget 数值范围使用 CHECK；
- tenant/status、next_poll_at、lease_expires_at、work_id/occurred_at 建索引。

## Slice M1-03a：Lease and recovery service

### 已实现

| 能力 | 合同 |
| --- | --- |
| queued claim | 按 priority 降序、created_at 升序选择；PostgreSQL 使用 `FOR UPDATE SKIP LOCKED`。 |
| finite lease | claim 原子进入 running，设置 `lease_owner`、`lease_expires_at`，增加 version 和 phase_attempt，追加 WorkEvent。 |
| renew | 只有当前 owner 且 lease 未过期时可续租；续租只更新操作元数据，不推进业务 version，不写业务 WorkEvent。 |
| worker commit | 只有未过期 lease owner 可提交 phase 结果；状态更新、lease 清除和 WorkEvent 插入保持一个事务。 |
| waiting release | running 进入 waiting_external/review/input/approval 或终态时清除 lease，释放 worker slot。 |
| external wakeup | `next_poll_at <= now` 的 waiting_external 原子转 queued；保留 external_task_id，清除 next_poll_at。 |
| graceful abandon | shutdown 前把当前 lease 到期时间设为 now，不伪造业务状态或成功事件。 |
| crash recovery | 过期 running 任务由新 worker 接管，保持 phase，增加 attempt/version，追加 `lease_recovered`。 |
| bounded retry | 初次 attempt 之外最多恢复 `max_retry_count` 次；耗尽后原子转 failed 并释放 lease。 |
| cancellation | requester/operator 按冻结状态图取消任务；活动 lease 同时清除并追加 `work_cancelled`。 |
| tenant scope | claim、wakeup、recover 可限定 tenant；读取、commit 和 cancel 始终校验 tenant。 |

### 事件与 version 边界

| 动作 | version | WorkEvent |
| --- | --- | --- |
| queued claim -> running | +1 | `work_claimed` |
| lease renew | 不变 | 不写业务事件 |
| graceful abandon | 不变 | 不写业务事件 |
| expired lease recovery | +1 | `lease_recovered`（running -> running 操作恢复事件） |
| retry exhausted | +1 | `retry_exhausted`（running -> failed） |
| waiting_external due -> queued | +1 | `external_poll_due` |
| worker phase commit | +1 | phase runner 提供的业务事件 |
| requester cancel | +1 | `work_cancelled` |

`lease_recovered` 是恢复控制事件，不是新增业务状态边。它保持 running 和 current_phase，
只固定新的 attempt、owner、lease 和 version，避免引入 M0 未冻结的 `running -> queued` 转换。

| unit tests | 32 passed |
| claim | priority、有限 lease、单次领取 |

### 并发与 kill/recovery 核心结论

- **claim**：PostgreSQL `FOR UPDATE SKIP LOCKED` + priority DESC + created_at ASC → 高优先级先领、不重复领取、原子进 running + 设置有限 lease + 唯一 `work_claimed` 事件。
- **renew**：只校验 `lease_owner=worker AND lease_expires_at > now`，不增 version、不写事件 → 运维心跳，不影响审计。
- **kill/recovery**：`lease_recovered` 是 running→running 操作恢复事件（非业务状态边），保持 current_phase、增加 attempt/version、改 owner、设新 lease → 与 M0 freeze 状态机一致（不引入 running→queued）。
- **bounded retry**：`phase_attempt <= max_retry_count` 继续 recover，否则原子转 failed + `retry_exhausted`。终态后 lease 清空、不可再 claim/recover。
- **tenant**：claim/recover/wakeup/get/commit/cancel 全部 scope 到 tenant_id，跨 tenant fail closed。

### 预算事务边界

```text
claim queued WorkItem + finite lease
-> resolve exact Playbook version
-> validate brief and plan resource ceiling
-> reserve budget before any model/external call
-> run one resumable phase
-> validate output and deadline
-> settle actual usage
-> atomically commit WorkItem + WorkEvent and release lease
```

预算不足路径：

```text
reserve rejected
-> do not call Playbook
-> running -> waiting_approval
-> event=budget_extension_required
-> release worker lease
```

崩溃路径：

```text
worker dies with active reservation
-> lease expires
-> recovery charges reserved ceiling as forfeited usage
-> increment attempt/version
-> retry remains bounded by both WorkBudget and max_retry_count
```

`forfeited` 是安全上界，不宣称它等于 provider 的精确账单。这样会在极端崩溃时保守多计，
但不会通过反复 kill/retry 绕过模型、Token 或外部查询预算。

### phase 与 agent turn 边界

- 模板 Playbook 的 `run_phase()` 才能调用 DeepAgents、Skills、MCP 或文件 service；

- LangGraph checkpoint 仍只保存同一 phase attempt 内的 step 级状态；

## Slice M1-05：Profile composition、硬路由和企微任务工具

### 路由合同

| 条件 | 确定性结果 |
| --- | --- |
| 正式 artifact、waiting、跨 turn/system/phase、requester 要求跟踪 | `WorkItem` |
| Playbook 或 tool 的 `work_mode=required` | `WorkItem`，模型不可降级 |
| 无副作用的读取或普通对话 | `DirectTurn` |

| `direct_allowed` 写操作 | 只有 confirmation、幂等、MCP audit 和合同幂等能力全部成立才是 `DirectTurn` |

`ToolContractRegistry` 由服务端代码创建。模型可以选择已注册工具，但不能提供或修改
`work_mode`、`side_effect` 和 `supports_idempotency`。

### 隔离 composition root

| 能力 | 合同 |
| --- | --- |
| opt-in | `AGENTSEEK_WORK_ENABLED=false` 为默认值；禁用时 v0.0.9 turn 完全不变。 |

| runtime merge | 只增加 `digital_employee` 和 `work`，保留原 `enterprise` mapping。 |
| current work | repository 按 tenant、requester、digital employee 查询最近的非终态任务。 |
| message idempotency | `load_state` 在原始回调仍可见时把企微 msgid 转成 namespace-scoped message key；随后与 session HMAC key 组合。数据库和 LangGraph state 都不保存原始 msgid、员工或 channel 标识。 |
| factory | requester/reviewer/approver/data_owner/beneficiary 固定为同一 requester key；绑定 PackSnapshot、Profile、Skill、Playbook、预算和 runtime release。 |

- `create_industry_report_work` 固定为 `required/write/idempotent`，只能创建正式 WorkItem；

- context schema 显式包含 enterprise、digital_employee 和 work，避免运行时 context 类型漂移。
