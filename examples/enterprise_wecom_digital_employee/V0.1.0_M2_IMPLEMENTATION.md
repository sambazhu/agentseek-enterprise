## 决策冻结

### ReportBrief 采用渐进式澄清

首版 ReportBrief 不是一张长表。员工只需先说明报告主题。
系统从消息、岗位 Profile 和 Playbook 默认值补全其余字段。

首版合同字段：

| 字段 | 规则 |
| --- | --- |
| `title` | 必填；报告主题。 |
| `target_audience` | 确认前必填；可以从上下文推断，也可以向员工追问一次。 |
| `coverage_period` | 报告覆盖期；允许明确指定、系统推断或使用 Playbook 默认值。 |
| `coverage_period_source` | `explicit`、`inferred` 或 `playbook_default`。 |
| `output_formats` | 默认 `docx`；首版允许 `markdown`、`docx`、`pdf`。 |
| `delivery_sla_minutes` | 默认 50；来自岗位 Playbook，不要求员工逐次填写。 |
| `confidentiality_level` | 默认 `internal`。 |

`ReportBrief.missing_fields` 首版只返回缺失的 `target_audience`。
覆盖期缺失不会阻断 intake。系统使用“截至请求时间的最新可得数据”。

### 合同与研究的边界

```text
自然语言请求
-> provisional ReportBrief
-> 必要时澄清目标受众
-> 委派人确认具体版本
-> 正式研究
```

- provisional 合同可以随 WorkItem 在 `draft/intake` 中持久保存。
- 未确认合同不得启动正式知识检索、外部搜索或报告编写。
- 合同确认只允许 WorkItem requester 执行。
- 确认后发生实质变化时，旧版本进入 `superseded`，新版本重新从
  `provisional` 开始。
- `WorkItem.brief` 保留为 M1 兼容字段，不作为 M2 合同真相源。

### 部门知识库采用 MCP 边界

正式部门知识库由外部知识库平台管理，通过 MCP 接入。
本地 PostgreSQL + pgvector 仅用于开发和合同模拟，不成为第二套生产知识平台。

首版不增加逐员工授权表。行业报告数字员工的 Profile 已固定
`owning_org: 战略发展部`，知识库工具按当前数字员工 Profile 和部门 scope
执行服务端约束。

建议的检索顺序：

```text
list/glob 元数据
-> keyword/grep 候选
-> semantic 补充
-> hybrid 排序
-> read 选定片段
```

知识库平台应提供关键词检索。关键词检索适合精确术语、文件名、代码、指标和专有名词；
向量检索适合语义改写和概念问题。默认使用 hybrid，而不是把全部文档注入模型。

当部门知识库不能覆盖关键问题时，系统向员工展示缺口，再让员工选择：

- 允许使用 Gildata 或公开搜索；
- 上传补充材料；
- 保留缺口继续生成。

## Slice M2-01：Lightweight ReportBrief and versioned contract ledger

### 通用 work 合同

`agentseek-work` 新增通用 `WorkContractSnapshot`，不包含报告领域字段。
其他数字员工可以用同一机制保存差旅合同、会议合同或审批合同。

| 能力 | 合同 |
| --- | --- |
| 状态 | `provisional`、`confirmed`、`superseded`。 |
| 版本 | `(work_id, contract_type, contract_version)` 复合主键。 |
| 当前版本 | 同一 `work_id + contract_type` 最多一个非 superseded 版本。 |
| payload | JSON 文档，由具体岗位定义 schema。 |
| 确认 | requester-only，带 expected version。 |
| 修订 | 当前版本原子 supersede，并追加下一 provisional 版本。 |
| 幂等 | 相同版本和相同内容可以安全重放。 |
| 租户边界 | 所有读写同时校验 `tenant_id` 和 `work_id`。 |

schema revision 6 新增 `enterprise_work_contracts` 和
`uq_work_contracts_current_type` partial unique index。
迁移在建索引前检查重复 current contract；发现脏数据时 fail closed。

### 行业报告合同

行业报告字段位于 example/template 的 `report_brief.py`。
`ReportBrief.to_contract()` 将领域合同转换为通用 WorkContract payload；
`ReportBrief.from_contract()` 按 schema version fail closed 还原。

### 本切片不包含

- 模型自动抽取或澄清 ReportBrief；
- 企微确认工具和状态推进；
- 部门知识库 MCP 调用；
- pgvector 本地知识库模拟器；
- Gildata 或公开搜索授权；
- Source、Evidence、Claim 或报告写作。
