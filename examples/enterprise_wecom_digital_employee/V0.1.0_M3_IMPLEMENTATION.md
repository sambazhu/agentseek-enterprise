# v0.1.0 M3 Implementation Log

## M3-00A: WeCom session backpressure

Status: implementation complete; awaiting Mac mini live verification.

M3 starts with a runtime admission slice before report outline and draft
generation. It keeps the existing per-session FIFO single-flight worker and
adds explicit backpressure around it.

### Runtime contract

- One active turn per `session_id`.
- At most `AGENTSEEK_WECOM_SESSION_QUEUE_MAXSIZE` pending messages; default 3.
- Different sessions retain coroutine-level concurrency.
- Accepted pending streams immediately show their one-based queue position.
- A message above the pending limit finishes immediately and never reaches the
  agent or model.
- A pending message expires after
  `AGENTSEEK_WECOM_QUEUE_WAIT_TIMEOUT_SECONDS`; default 240 seconds. Expired
  messages are skipped when the worker reaches them.
- `查看消息队列` and `查看排队状态` bypass the model and return active count,
  approximate active age, and pending count.

### Observability

The channel emits redacted structured events:

- `wecom_turn_queued`
- `wecom_turn_started`
- `wecom_turn_queue_rejected`
- `wecom_turn_queue_wait_timeout`
- `wecom_turn_queue_status`

Events contain hashed runtime scope through the enterprise observability layer,
counts, limits, and durations. They do not contain message text, OA account,
employee name, or model output.

### Boundaries

M3-00A does not implement `取消当前处理`, `清空等待消息`, hard preemption of a
blocking LLM call, or forced process exit under load. Those belong to M3-00B.
Long report generation remains a WorkItem concern and must not become a large
chat queue.

### Deterministic acceptance

Automated tests cover:

1. Eight distinct messages remain FIFO and single-flight when the configured
   pending limit permits them.
2. With the default policy, one active plus three pending messages are accepted
   and the next message is rejected.
3. Queue positions are 1, 2, and 3.
4. Queue status bypasses the agent in both busy and idle sessions.
5. A pending message expires without entering the agent and pending count
   returns to zero.
6. Different sessions remain concurrent.

Mac mini live verification should send one slow message followed by four rapid
distinct messages, verify three queued positions and one rejection, query queue
status while busy, and confirm that no rejected or expired message produces a
model turn.
