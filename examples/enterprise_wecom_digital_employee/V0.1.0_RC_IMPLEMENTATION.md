# v0.1.0 RC reliability closeout

## Frozen product scope

v0.1.0 RC adds no product capability. The delivery contract remains the M4-02
callback-mode `text_notice` card with a short-lived, recipient-bound, one-time
signed-link grant. Browser OIDC/SAML or WeCom web authorization is deferred
until a real enterprise identity provider and HTTPS callback domain are chosen.
PDF and direct-file delivery remain disabled.

The frozen schema is revision 11. The current Pack/Profile/report-writing
versions remain `1.9.3` / `1.8.3` / `1.5.3`.

## Deterministic employee guidance

The render and publication tools already return exact ledger-derived next-step
commands. The output guard now provides the final deterministic boundary when a
model paraphrases or omits them:

- a successful `render_report_docx_artifact` turn appends the exact current
  `发布 ReportArtifact vN` command when absent;
- a successful `publish_report_artifact` turn appends the exact current
  `交付 ReportArtifact vN 给我` command when absent;
- an already relayed exact command is not duplicated;
- the version is parsed only from the successful tool result in the latest
  human turn, never from model prose or conversation memory.

This behavior is mirrored in the enterprise-wecom cookiecutter template and
does not weaken Artifact, Publication, or Delivery ledger guards.

## Automated RC gates

The following tests form the RC reliability gate:

1. The report lifecycle integration test creates the WorkItem and ReportBrief,
   performs internal research and gap resolution, confirms the Outline and
   Draft, approves content, renders, publishes, delivers, redeems once, rejects
   replay with 410 semantics, and makes Approval/Artifact/Publication/Delivery
   stale after an upstream revision.
2. Artifact render and publication replays return the existing immutable
   records without adding rows, events, or WorkItem versions.
3. A deterministic two-thread race forces one Artifact registration conflict;
   both callers receive the same immutable identity and no duplicate survives.
4. A cold process composition boot registers the download resolver before any
   model turn. Clearing the composition cache and rebuilding against the same
   database repeats registration without PackSnapshot conflict.
5. A clean database migrates from no schema to revision 11 and contains the
   delivery ledger. The latest schema constant is asserted as 11.
6. Artifact, publication, and delivery events are digest-only. The lifecycle
   assertion rejects grant tokens, storage keys, employee names, and OA account
   material in those event records.
7. Output-guard tests cover deterministic nudge insertion, no duplication,
   ledger-backed allowance, fake versions, stale-current contradictions, and
   unverified delivery claims.

## Mac mini RC live gate

Automated tests do not replace the final quasi-production pass. Mac mini must
run one fresh end-to-end WeCom lifecycle, confirm visible nudge text, click and
hash-check the DOCX, observe a 410 replay, revise an upstream contract, verify
all downstream records become non-current, restart the gateway, and repeat a
download endpoint probe before the first model turn. Logs and ledgers must show
zero unhandled traceback, duplicate side effect, plaintext identity, credential,
grant token, storage key, or host path.
