# v0.1.1 M1 Job Charter 实现记录

## 一、交付范围

M1 为现有行业报告数字员工增加版本化岗位章程和确定性服务发现。
产品身份从“单一报告 Bot”扩展为“战略发展部数字员工”，内部技术身份仍为
`industry-report`。

本轮完成：

- Profile v2：员工编号、展示名称、身份范围、使命、服务目录、行为准则和 Policy 引用；
- Profile v1 兼容：未声明 `profile_schema_version` 时使用旧字段生成兼容默认值；
- 引用校验：服务必须绑定已声明 Playbook，行为 Policy 必须来自 Pack；
- 确定性回答：`你是谁`、`你能做什么`、`有哪些服务`、`怎么使用你`；
- 人机身份分离：`我是谁` 不进入 Job Charter 路径；
- 示例工程与 Cookiecutter 模板同步；
- Pack `1.10.0`、Profile `1.9.0`。

本轮仍只启用 `securities-industry-report@1`。Playbook Registry、第二个测试型
Playbook 和确定性路由属于 M2/M3。

## 二、运行路径

企微消息先经过既有身份与 Work 状态装配，再进入 LangChain `RunnableSpec`：

```text
WeCom callback
-> enterprise identity
-> Work Profile authorization
-> Job Charter exact matcher
   -> matched: server-rendered response
   -> unmatched: existing DeepAgent path
```

`RunnableSpec.direct_response` 同时支持 invoke 和 stream。命中时不构建 Agent
输入、不调用模型，也不暴露工具。未命中时原有模型、工具和 Output Guard 路径不变。

Job Charter 只接受有限的精确命令。带业务任务的复合消息、天气等无关请求和
`我是谁` 都不会被截获。企微信封只有在具备可信 `channel=$wecom` 与日期标记时
才会被剥离。

## 三、岗位合同

当前岗位身份：

| 字段 | 值 |
| --- | --- |
| 展示名称 | 战略发展部数字员工 |
| 员工编号 | `DE-SD-001` |
| 技术身份 | `industry-report` |
| 身份范围 | `department` |
| 正式服务 | 证券行业正式报告 |
| 生产 Playbook | `securities-industry-report@1` |

服务目录同时保存工作过程与入口示例。回答内容来自当前 PackSnapshot 对应的
Profile，不由模型补写。部门知识优先、显式外部检索、证据可追溯、精确版本确认和
禁止自动越级继续由工具、合同和 Policy 强制执行。

## 四、兼容与安全边界

- schema revision 保持 `11`；
- ReportBrief 到 ReportDelivery 的合同和状态机不变；
- `digital_employee_id=industry-report` 不迁移；
- Profile v1 单 Playbook 项目继续加载；
- 未声明 Playbook、重复服务 ID、未知 Policy 和非法 Profile schema fail-closed；
- 未通过部门身份授权时不返回岗位服务目录；
- `digital_employee_service_discovery` 事件只记录 intent、技术 ID、Profile 版本和
  既有哈希会话范围，不记录员工原文、姓名、OA、凭据或 Prompt；
- MCP Policy、MCP 工具适配和确认回退保持既有基线零差异。

## 六、Mac Mini 活体验收

M1 关闭前需要验证：

1. `你是谁` 返回展示名称、`DE-SD-001`、部门、使命和工作边界；
2. `你能做什么` 只列出“证券行业正式报告”和真实工作过程；
3. `怎么使用你` 返回可直接发起的示例，不创建 WorkItem；
4. `我是谁` 继续返回经过认证的人类员工身份；
5. 三个 Job Charter 请求均无 `langchain_model_call`，有脱敏的
   `digital_employee_service_discovery`；
6. 未授权部门员工 fail-closed，不获得服务目录；
7. 现有活动或已交付报告状态查询不回归；
8. 0 Callback 重传风暴、重复投递、Traceback、IntegrityError、PII 或凭据泄漏。

M1 活体通过后进入 M2 Playbook Registry。M2 才移除运行时的单 Playbook 假设，
并保持当前证券报告 Binding 的全部 v0.1.0 行为。
