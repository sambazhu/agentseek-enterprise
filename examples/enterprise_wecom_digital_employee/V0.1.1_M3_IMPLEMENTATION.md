# v0.1.1 M3 确定性内部路由实现与验收

## 一、切片目标

M3 在部门数字员工内部增加确定性 Playbook 路由。路由不调用模型，不使用分类置信度，
不把所有 Playbook 工具合并后交给模型选择。

生产 Pack 仍只启用：

```text
securities-industry-report@1
```

第二个 Playbook 只存在于自动化测试夹具。它用于验证多 Playbook 的选择、权限和上下文
隔离，不代表第二项部门正式服务上线。

## 二、路由合同

### 2.1 选择顺序

每条消息按以下顺序匹配：

1. 精确合同、Artifact、Publication、Delivery 或任务状态命令；
2. 员工使用“使用、选择、进入、启动 + 服务别名”的显式选择；
3. 只有一个活动 Playbook 时的“继续当前任务”等续接命令；
4. 唯一命中的确定性业务词；
5. 正式流程信号无候选或出现多个候选时，返回服务端澄清；
6. 普通消息无候选时留在部门 DirectTurn，不启动 WorkItem。

优先级只决定候选显示顺序，不能替代歧义澄清或授权。

### 2.2 状态合同

`playbook_route` 是公开 LangGraph state 字段：

```yaml
route_status: selected | clarification_required | out_of_scope | forbidden
digital_employee_id: industry-report
playbook_ref: securities-industry-report@1
reason_code: active_work | exact_action | explicit_service | deterministic_match | ambiguous | no_match | requester_forbidden
candidate_playbook_refs: []
profile_version: 1.11.0
pack_snapshot_id: pack_snapshot_sha256_...
```

该字段显式进入 `EnterpriseAgentState` 和 runnable input。它不依赖下划线私有字段，避免
LangGraph 序列化丢失选择结果。

### 2.3 观测事件

`digital_employee_playbook_routed` 只记录：

- 数字员工 ID 和 Profile 版本；
- route status 和 reason code；
- Playbook ID、候选 ID 和 PackSnapshot ID；
- 已有脱敏 session scope。

事件不记录员工原文、姓名、OA、Prompt、凭据、工具参数或文件路径。

## 三、运行时隔离

Agent 启动时为部门 DirectTurn 和每个 Playbook Binding 分别构建 runnable：

```text
RoutedAgentRunnable
|- department direct agent
|- securities-industry-report@1 agent
`- test-only second Playbook agent
```

选中一个 Playbook 后只调用对应 runnable。每个 runnable 只绑定该 Binding 的工具和
Output Guard。未选中 Playbook 时只提供 Profile 允许的部门直接能力。

Registry 先执行公共 Profile 员工授权，再解析每个 Binding 的活动任务。只有选中的
Binding 可以加载消息状态、发布 `current_work` 和扩展运行时上下文。测试型 Playbook
不能读取证券报告任务，也不能调用证券报告工具。

## 四、Pack 与兼容

| 项目 | M3 值 |
| --- | --- |
| Pack | `1.12.0` |
| Profile | `1.11.0` |
| Pack schema | `1` |
| Profile schema | `2`，兼容 `1` |
| Work schema | revision `11`，无迁移 |
| 生产 Playbook | `securities-industry-report@1` |

Profile v2 的每个 Playbook 必须显式声明 `routing`。Profile v1 缺少该字段时获得空路由
默认值，保持旧单 Playbook 配置可加载。

路由元数据包括显式别名、确定性业务词、所属命令词和显示优先级。修改这些不可变内容
必须升级 Pack/Profile 版本并注册新 PackSnapshot。

## 五、M2 反馈收口

- `你是谁` 和 `你能做什么` 增加业务化能力概览：授权文件分析、部门知识检索，以及经
  员工同意后使用外部数据或公开信息；不显示工具 ID、grant 或 MCP server 名；
- `我是谁` 的模型上下文不再展示内部员工哈希；姓名、OA、组织和岗位仍来自认证身份；
- `查看当前 ReportBrief/Outline/Draft/Approval/Artifact/Publication/Delivery` 由报告
  所属命令词确定性路由到报告 Binding；报告 Prompt 同时要求使用对应只读账本工具。

日志 sink 跨 turn 不一致继续作为独立可观测性 backlog，不在 M3 改动。

## 六、自动化验收

### 6.1 Loader 与路由

- Profile v2 缺少路由声明时 fail-closed；
- Profile v1 空路由兼容；
- 企微信封中的精确合同命令正确路由；
- 显式服务别名和唯一业务词正确选择；
- 一个活动任务允许续接，多个活动任务必须澄清；
- 多候选不按 priority 静默选择；
- 未授权员工 fail-closed；
- 普通消息保留 DirectTurn，未匹配正式请求确定性澄清。

### 6.2 工具与上下文

- Routed runnable 只调用选择的 agent；
- Registry 只调用选择的 Binding 状态增强；
- 工具集合按 Binding 查询，不形成工具并集；
- Output Guard 只作用于返回结果所属 Binding；
- `playbook_route` 从 Bub aggregate state 进入 LangGraph schema 和 runnable input。

### 6.3 身份体验

- Job Charter 能力概览来自 Profile，不暴露隐藏工具名；
- 人类员工上下文不含内部 employee hash；
- Job Charter 精确请求继续零模型调用；
- 路由澄清文案来自 Service Catalog，不复述员工原文。

## 七、Mac mini 验收 Oracle

1. 注册 Pack `1.12.0` / Profile `1.11.0`，保留旧快照，schema 仍 revision 11；
2. `你是谁`、`你能做什么` 展示业务化能力概览，零模型调用；
3. `我是谁` 不展示内部哈希，仍返回认证员工信息；
4. `查看当前 ReportArtifact 和发布交付状态` 命中报告 Binding，并调用只读账本工具；
5. `使用证券行业正式报告，研究利率变化的影响` 以 `explicit_service` 选择报告 Playbook；
6. `请制作一份新能源市场报告` 返回服务选择或证券适用域澄清，零 WorkItem；
7. 双 Playbook 测试探针覆盖 exact、explicit、active、unique、ambiguous 和 no-match；
8. 歧义候选不创建 WorkItem，不加载任一 Playbook current work，不调用模型；
9. 证券报告现有 delivered Work 状态、Guard、MCP、队列和 signed-link 不回归；
10. 路由事件脱敏，MCP protected zero-diff，零 SIGBUS、Traceback、IntegrityError、
    PackSnapshot conflict 和真实 HTTP non-200。

## 八、退出条件

M3 只有在测试型双 Playbook 路由、工具隔离、上下文隔离、授权边界和歧义澄清均通过，
且 Mac mini 确认现有证券报告链路无回归后关闭。关闭后进入 M4 发布加固与 v0.1.1 RC。
