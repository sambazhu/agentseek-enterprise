# v0.1.1 M4 发布加固实施记录

## 一、目标

M4 不增加新的业务 Playbook，不重做 v0.1.0 已完成的报告账本、审批、发布和交付。
它负责在 v0.1.1 RC 前收紧部门数字员工的员工体验和确定性边界，并完成全生命周期兼容回归。

M3 Mac mini 复核发现三个需要在 RC 前关闭的问题：

1. 精确的“查看当前 ReportArtifact/发布/交付状态”已经路由到报告 Playbook，但模型可能不调用
   `get_current_*` 工具，随后被 Output Guard 正确拦截；
2. Job Charter 把正式服务、辅助能力和执行边界混排；
3. Job Charter 的能力概览来自静态文案，可能宣称部署中并未配置的 MCP 能力。

模型调用日志跨 turn 丢行属于独立可观测性问题，不与本轮员工功能改动耦合。

## 二、M4-00：确定性状态与运行时能力目录

### 2.1 只读报告状态下沉到 Playbook Binding

新增受限的只读命令识别器。它只接受带“查看/查询/显示/告诉我”和“当前”的精确状态请求，
并复用已认证的企微信封剥离逻辑。发布、交付、渲染等动作命令不会被截获。

```text
企微消息
-> 确定性 Playbook 路由
-> 已选 Binding.direct_response
-> WorkComposition.current_work_summary
-> 服务端账本状态渲染
-> 直接回复员工
```

该路径不调用模型，也不依赖模型选择 `get_current_*` 工具。响应只展示选择的合同状态字段，
不展示 ReportDraft 正文、storage key、grant hash、下载 token 或宿主路径。普通工具调用仍复用同一渲染器，
避免直接路径与工具路径产生两套状态口径。

支持的首批状态包括 ReportBrief、缺口决策、ReportOutline、ReportDraft、ReportApproval、
ReportArtifact、ReportPublication 和 ReportDelivery。完整任务状态返回全部部分；员工只询问 Artifact、
发布和交付时，只返回对应部分。

新增脱敏事件 `digital_employee_playbook_direct_response`，只记录数字员工、Profile、Playbook、session
和响应类别，不记录员工原文或账本正文。

### 2.2 Job Charter 分段渲染

“你是谁”和“你能做什么”按以下业务结构服务端渲染：

```text
数字员工身份 / 正式服务

协助能力

工作准则 / 执行边界
```

员工能够区分正式 Playbook 服务、辅助能力和治理边界，不再看到混排的技术说明。

### 2.3 能力目录按部署配置求交

身份响应中的辅助能力由以下事实求交生成：

```text
Profile 声明
∩ Playbook 有效 tool grants / data scopes
∩ 当前 MCP 配置中的 server 标识
```

能力目录只读取 MCP 配置的 server 名，不读取、输出或记录命令参数、URL、token 和凭据，也不会为一次
身份查询主动连接 MCP。这里表达的是“当前部署已配置且已授权”的能力快照，不是实时健康检查；实际调用
仍需通过 MCP policy、员工授权和工具级错误处理。

对员工只展示“文件分析”“部门知识”“外部数据”“公开搜索”等业务能力名称，不显示工具 ID、grant、
MCP server 名或内部路径。配置缺失或 JSON 无效时 fail-closed，不宣称对应能力。
