# v0.1.2 M0.1：企微协议基线

## 为什么插入 M0.1

v0.1.2 M0 已完成平台路线冻结，原计划下一步是 M1 组织授权与
Identity Provider 抽象。在进入跨部门身份工程前，需先修正企微渠道的会话
和消息语义基线，否则群聊会话可能按发送人串联，并且引用消息会在
进入 Agent 前丢失。这两个问题会直接影响 M1 的授权边界，因此将 M0.1
作为 M1 的前置切片。

## 官方协议基线

- [AI 机器人回调与消息回复](https://developer.work.weixin.qq.com/document/path/100719)：
  区分单聊与群聊，群聊以 `chatid` 定位会话；回调包含文本、混合、
  引用和媒体等语义。
- [response_url 异步回复](https://developer.work.weixin.qq.com/document/path/101138)：
  URL 仅可使用一次，有效期一小时，仅支持 Markdown 和模板卡片。
- [AI 机器人长连接](https://developer.work.weixin.qq.com/document/path/101463)：
  `aibot_respond_msg` 是对入站消息的回复；`aibot_send_msg` 的主动发送仅支持
  Markdown 和模板卡片，且需要用户曾在对应会话中联系机器人。
- [open_userid 转 userid](https://developer.work.weixin.qq.com/document/path/101521)：
  用户身份解密是成员身份层能力，不得覆盖群聊会话边界。
- [自建应用发送消息](https://developer.work.weixin.qq.com/document/path/90236)
  与[接收消息](https://developer.work.weixin.qq.com/document/path/90238)：
  自建应用可按成员、部门或标签主动推送多种消息，但不支持流式回复。

| 渠道 | 入站 | 对当前会话回复 | 主动发送 | 当前实现 |
| --- | --- | --- | --- | --- |
| AI 机器人 callback | 单聊、群聊；文本、混合、引用、媒体等 | 回调流式回复；`response_url` 一小时内一次 Markdown/模板卡片 | 无任意成员主动推送 | 已实现，本切片修正会话和引用语义 |
| AI 机器人长连接 | 单聊、群聊与媒体 | `aibot_respond_msg` 支持流、卡片、Markdown 和媒体 | `aibot_send_msg` 仅 Markdown/模板卡片，且需用户先联系 | 未实现，仅冻结能力声明 |
| 企微自建应用 | 应用消息回调 | 无流式回复 | 可按成员、部门、标签发送多种消息 | 未实现，后续独立立项 |

## 本切片范围

1. 群聊 session 使用 `aibotid + chatid` 隔离，不再使用发送人作为群聊
   会话主键。
2. 明文 `userid` 回填只更新成员身份，不改写群聊 session 和
   `chat_id`。
3. 引用文本、混合消息和语音转写进入 Agent 正文；引用媒体只保留
   安全元数据，不重新下载历史签名 URL。
4. 安全回调上下文保留 `chatid` 和引用语义，仍排除 `response_url`
   和媒体签名 URL。
5. 修正长连接能力矩阵，明确“回复类型”和“主动发送类型”不同。

## 不在本切片

- 不实现 AI 机器人长连接 transport；
- 不新增企微自建应用 channel；
- 不改造持久化 inbox/outbox、租约和多实例恢复，这些仍属于 M4；
- 不改变 M1 的组织授权与 Identity Provider 目标。

## 验收门槛

- 同一发送人在不同群聊中产生不同 session，同一 `chatid` 在不同
  `aibotid` 下也不共享 session；
- 单聊仍使用 `wecom:{userid}`，现有记忆兼容；
- userid 解密后群聊 session 不变；
- 引用消息进入 Agent 可见正文，且上下文中无 response capability
  和签名 URL；
- callback 与 long-connection 能力声明有协议测试；
- `contrib/agentseek-wecom` 和企微数字员工样例回归通过。

## 后续顺序

M0.1 通过后回到原路线 M1。长连接实现和自建应用渠道分别立项，
先补齐持久化 inbox/outbox、幂等、重启恢复和多实例所有权，再打开
新 transport 的生产开关。
