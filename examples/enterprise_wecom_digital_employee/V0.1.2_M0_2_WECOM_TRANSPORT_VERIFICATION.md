# 如何复验企微 M0.2 Transport Kernel

用于确认 Callback Transport 拆分没有改变现网行为。代码基线是
`b0eae36178de51c785a938ad3c4d4530148f3314`，父生产基线是
`7b2a9f15f8a057499da7150de1139a5bbca9e163`。

## 前置条件

- 使用分支 `enterprise/v0.1.2-wecom-transport-kernel`。
- 保留验证机现有 `.env`、JDBC、MCP、模型和反向代理配置。
- 停止其他机器上的同一机器人实例。
- 不迁移共享数据库，不启用 Work 或长连接。

   ```bash
   git diff --check 7b2a9f15f8a057499da7150de1139a5bbca9e163..HEAD
   ```

6. 核对部署健康。

   - `:12000` 只有一个监听 PID。
   - `/health` 响应仍为 `{"ok":true,"channel":"wecom","enabled":true}`。
   - `gateway.log` 权限仍为 `600`。
   - 启动窗口没有 Traceback 或 ERROR。

7. 发送一条单聊消息并检查地址。

   ```text
   M0.2 单聊回归：请只回复“Callback Transport 正常”
   ```

   只允许一条终态回复。身份解析成功后，session 仍为
   `wecom:{plaintext_userid}`。安全事件或受控诊断只记录地址字段，不记录
   `response_url`、响应码或签名 URL。

8. 使用同一成员在两个群聊分别发送唯一文本。

   ```text
   群 A：M02-ALPHA，只记住 ALPHA-M02
   群 B：M02-BETA，只记住 BETA-M02
   ```

   分别追问后，群 A 只能回答 ALPHA-M02，群 B 只能回答 BETA-M02。
   两个 session 必须不同，明文 userid 解析不得改写群聊 session。

9. 引用一条唯一文本并要求复述。

   ```text
   引用原文：REFERENCE-M02-ONLY
   追问：请复述我引用的消息内容
   ```

   回复应包含唯一文本，不得包含 raw payload、URL、响应码或内部字段。

10. 扫描本次启动和消息窗口。

    只报告敏感模式的命中数量，不输出命中原文。模型 Key、企微凭据、
    数据库密码、`response_code`、下载 URL、媒体 URL、Traceback 和 ERROR
    必须全部为零命中。

## 故障处理

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| Callback 路由返回 404 | Transport 未挂载现有 Callback 路径 | 停止验证并报告路由和 HEAD |
| `/health` 增加或缺少字段 | Callback 兼容合同发生漂移 | 判为 BLOCKED，不修改验证机代码 |
| 单聊 session 保留密文 | 地址未随 Identity 解析更新 | 判为 BLOCKED并记录安全事件摘要 |
| 群聊 session 变成成员 ID | 地址层覆盖了群聊边界 | 判为 BLOCKED并停止后续消息 |
| 重复终态回复 | Callback 和 `response_url` 所有权回归 | 判为 BLOCKED并记录 msgid 哈希 |

失败时切回部署前提交并使用相同脚本重启。以下命令未在本机执行。

```bash title="not executed in this run"
git switch production
git merge --ff-only company-gitlab/production
```
