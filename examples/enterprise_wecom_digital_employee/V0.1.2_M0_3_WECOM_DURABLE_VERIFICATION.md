# 如何复验企微 M0.3 持久化消息基座

用于确认 Callback 在 SQLite 模式下具备跨重启去重和恢复能力，并保持
M0.2 活体行为。代码提交链是 `6fa02d1`、`c9f395b`，父生产基线是
`ebf14c8c5dfbc857ec23103075d6a543ec54718d`。

## 前置条件

- 使用分支 `enterprise/v0.1.2-wecom-durable-messaging`。
- 保留验证机现有模型、企微、JDBC、MCP、反向代理和业务开关。
- 停止其他机器上的同一机器人实例。
- 不迁移共享数据库，不启用 Work、长连接或自建应用 Transport。
- 新增一个独立的 M0.3 加密材料；这不是模型 API Key 轮换。

   ```bash
   git merge-base --is-ancestor ebf14c8c5dfbc857ec23103075d6a543ec54718d HEAD
   git diff --check ebf14c8c5dfbc857ec23103075d6a543ec54718d..HEAD
   ```

2. 运行组件和样例门禁。


   本地基线为 105 passed。允许出现 FastAPI TestClient 的既有弃用警告。


   本地基线为 329 passed、1 skipped。

3. 运行静态门禁。

   ```bash
   uv run ruff check contrib/agentseek-wecom examples/enterprise_wecom_digital_employee
   ```

   ```bash
   PYTHONPATH=examples/enterprise_wecom_digital_employee/src uv run ty check contrib/agentseek-wecom/src contrib/agentseek-wecom/tests examples/enterprise_wecom_digital_employee/src
   ```

4. 生成独立加密材料。以下命令输出的是待写入验证机 `.env` 的新值。

   ```bash
   openssl rand -base64 48
   ```

   不要把输出提交到 Git、验证文档、日志或聊天。不要复用模型 API Key、企微
   Token、EncodingAESKey、AppSecret 或 namespace secret。

5. 在验证机 `.env` 增加以下配置。`<M0.3-独立随机值>` 是明确的假占位符，
   必须替换为上一步的输出。

   ```env
   AGENTSEEK_WECOM_DURABLE_MODE=sqlite
   AGENTSEEK_WECOM_DURABLE_SQLITE_PATH=runtime/wecom-messages.sqlite3
   AGENTSEEK_WECOM_DURABLE_SECRET=<M0.3-独立随机值>
   AGENTSEEK_WECOM_DURABLE_RECOVERY_LIMIT=100
   AGENTSEEK_WECOM_DURABLE_LEASE_SECONDS=600
   ```

6. 执行生产预检。

   ```bash title="not executed in this run"
   uv run python examples/enterprise_wecom_digital_employee/scripts/prod_check.py --env-file examples/enterprise_wecom_digital_employee/.env
   ```

   本机替代验证已执行，但本机现有 `.env` 仍是 memory 模式，并存在 M0.3
   之外的 DM 执行模式失败和 4 个既有告警。Linux 验证必须以其最终配置单独
   记录 OK/WARN/FAIL，不得修改共享数据库来消除告警。

7. 部署研发分支并重启唯一实例。以下命令未在本机执行。

   ```bash title="not executed in this run"
   git fetch company-gitlab enterprise/v0.1.2-wecom-durable-messaging
   git switch enterprise/v0.1.2-wecom-durable-messaging
   git merge --ff-only company-gitlab/enterprise/v0.1.2-wecom-durable-messaging
   ```

   TODO：Linux 验证人使用现有 `run_gateway.sh` 重启唯一实例。

8. 核对健康和本地文件。

   - `:12000` 只有一个监听 PID。
   - `/health` 仍返回 `{"ok":true,"channel":"wecom","enabled":true}`。
   - `runtime/wecom-messages.sqlite3` 存在且权限为 `600`。
   - 启动窗口没有 Traceback 或 ERROR。
   - 共享 PostgreSQL schema revision 没有变化。

   ```bash title="not executed in this run"
   stat -c '%a %n' runtime/wecom-messages.sqlite3
   ```

9. 发送一条单聊终态回归。

   ```text
   M0.3 单聊回归：请只回复“持久化消息正常”
   ```

   只允许一条终态回复。身份解析后的 session、群聊隔离和事件脱敏必须与
   M0.2 一致。

10. 执行一次优雅重启恢复。

    先发送一条已知会超过首包等待时间的只读任务。收到“已收到”终态确认、
    且最终答案尚未出现时，使用现有脚本优雅停止并立即启动网关。新实例应恢复
    同一 inbox，并通过原 `response_url` 发送一次最终 Markdown。不得再次发送
    同一业务请求到 Agent 工具。

    如果无法稳定制造活体慢任务，以
    `test_pending_inbox_is_recovered_and_delivered_on_start` 和
    `test_graceful_owner_release_makes_inbox_immediately_recoverable` 作为确定性
    Oracle，并在记录中把活体项标为未执行，不能伪造 PASS。

11. 核对持久化去重和密文。

    可重放同一 `msgid` 的受控 Callback 样本时，Agent 接收次数必须仍为一。
    没有安全重放工具时，以 `test_completed_message_is_not_dispatched_again_after_restart`
    作为 Oracle。

    扫描数据库只报告命中数，不输出回调正文或回复能力。测试中的唯一明文、
    `response_url`、原始 `msgid` 和实际凭据必须为零命中。

12. 记录 M0.3 明确边界。

    - Markdown outbox 自动恢复。
    - 模板卡片重启恢复标记 `blocked`，留给 M0.4。
    - 无 `response_url` 的旧 Callback 重启后标记 `blocked`。
    - 强制终止后需等待 lease；优雅停止会立即释放 lease。
    - 长连接和自建应用未启用，分别进入 M0.5、M0.6。

## 故障处理

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 启动提示 durable secret 长度不足 | 新加密材料缺失或仍是占位符 | 停止启动，生成独立随机值 |
| envelope authentication failed | SQLite 文件和加密材料不匹配 | 恢复匹配的 `.env` 与数据库备份，不删除数据库掩盖问题 |
| schema revision unsupported | 数据库来自未知版本 | 判为 BLOCKED，不手工改 revision |
| 重启后同一消息调用 Agent 两次 | inbox 去重或 lease 失效 | 判为 BLOCKED，保留脱敏状态和时间线 |
| 最终 Markdown 重复 | outbox 投递边界回归 | 判为 BLOCKED，记录 outbox 状态，不输出 URL |
| 模板卡片在重启后自动发送 | M0.3 fail-closed 边界被破坏 | 判为 BLOCKED，停止活体复验 |

失败时恢复部署前代码和原 `.env`，再用现有脚本重启。以下命令未在本机执行。

```bash title="not executed in this run"
git switch production
git merge --ff-only company-gitlab/production
```

如果需要删除本次 SQLite 文件，先停止网关并将文件移动到权限为 `700` 的受限
归档目录。不要直接删除；其中可能包含尚未投递的加密消息。本切片没有共享
schema 或外部数据迁移。
