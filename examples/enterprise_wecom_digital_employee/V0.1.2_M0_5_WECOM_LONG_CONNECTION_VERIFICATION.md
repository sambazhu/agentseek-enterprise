# 如何用新机器人复验企微 M0.5 AI Bot 长连接

用于在不改变现有 Callback 机器人的前提下，用一个新 AI Bot 和隔离 Linux
实例验证长连接。新机器人是现有 `industry-report` 数字员工的 Transport
canary，不代表创建了第二名部门数字员工。

## 前置条件

- 功能分支是 `enterprise/v0.1.2-wecom-long-connection`。
- M0.5 Transport 代码 HEAD 是 `d05432a378a0dcf7e76c546a1f435bd8c652a5da`。
- 群聊语义记忆隔离修复后，复验 HEAD 至少是
  `fb6e851`（`fix(contextseek): isolate semantic memory across group chats`）。
- 父生产基线是 `0d16633160755472f6f775b49189479c46a6f84f`。
- 企微管理员已创建一个选择长连接模式的新 AI Bot。
- 管理员已把新 BotID 和专用 Secret 写入 Linux canary `.env`。
- 现有 Callback 机器人继续运行 `production`，监听 `:12000`。
- 新长连接实例使用独立 worktree、`:12001`、日志和本地存储。
- 模型 API Key 轮换不属于本轮复验项。

如果新 BotID、Secret 或测试窗口尚未就绪，只完成静态核验。记录
`WAITING_FOR_ADMIN_CREDENTIALS`，不要停止 Callback，也不要输出 Secret。

   ```bash title="not executed in this run"
   git diff --check 0d16633160755472f6f775b49189479c46a6f84f..company-gitlab/enterprise/v0.1.2-wecom-long-connection
   ```

2. 运行确定性门禁。

   ```bash
   uv lock --check
   uv run pytest -q contrib/agentseek-wecom/tests
   PYTHONPATH=examples/enterprise_wecom_digital_employee/src uv run pytest -q examples/enterprise_wecom_digital_employee/tests
   uv run ruff check contrib/agentseek-wecom examples/enterprise_wecom_digital_employee
   PYTHONPATH=examples/enterprise_wecom_digital_employee/src uv run ty check contrib/agentseek-wecom/src contrib/agentseek-wecom/tests examples/enterprise_wecom_digital_employee/src

   uv run pytest -q tests/test_wecom_integration.py
   ```

   本地基线是企微组件 127 passed、数字员工样例 332 passed / 1 skipped、
   模板 5 passed、企微集成 3 passed。允许既有 TestClient 和 Uvicorn
   WebSocket 适配层的弃用警告。

3. 记录新机器人的业务绑定。

   验证记录只保存 BotID 的脱敏指纹，并明确以下映射：

   ```text

   -> deployment_role=M0.5 transport canary
   -> digital_employee_id=industry-report
   -> Profile=战略发展部数字员工
   ```

   当前示例固定加载 `digital_employees/industry-report`。不要仅凭机器人名称
   宣称它是另一部门或另一名数字员工。M0.5 不验证多 Profile gateway。

4. 创建隔离 worktree，不切换现有 production 工作区。

   以下命令未在本机执行。如果本机已经存在同名本地分支，Linux 验证人应
   保持 production worktree 不变，并用等价的 detached worktree 操作。

   ```bash title="not executed in this run"
   git worktree add --detach ../agentseek-m05-long-connection company-gitlab/enterprise/v0.1.2-wecom-long-connection
   ```

   在新 worktree 中安装冻结依赖并运行后续命令。不要让正在运行的 Callback
   进程从被切换的工作区懒加载文件。

5. 创建独立 `.env` 和本地可写目录。

   可以复制现有 Linux `.env` 作为依赖配置基础。目标文件必须不存在且权限
   为 `600`。命令未在本机执行。

   ```bash title="not executed in this run"
   set -euo pipefail
   test ! -e ../agentseek-m05-long-connection/examples/enterprise_wecom_digital_employee/.env
   install -m 600 examples/enterprise_wecom_digital_employee/.env ../agentseek-m05-long-connection/examples/enterprise_wecom_digital_employee/.env
   install -d -m 700 ../agentseek-m05-long-connection/runtime-m05
   ```

   复制只发生在 Linux 本机。不要打印、上传或提交 `.env`。

7. 核对所有可写路径并执行生产预检。

   Linux 验证人应只输出变量名、规范化路径和“是否与 Callback 重合”。不要
   输出 URL 凭据。任何 canary 可写路径与 Callback 重合都判为部署配置
   BLOCKED。

   ```bash title="not executed in this run"
   uv run python examples/enterprise_wecom_digital_employee/scripts/prod_check.py --env-file examples/enterprise_wecom_digital_employee/.env
   ```

   必须是 0 FAIL。不要为消除告警而迁移共享数据库。

8. 启动 canary，并同时核对两个实例。

   从 canary worktree 根目录运行。以下命令未在本机执行。

   ```bash title="not executed in this run"
   AGENTSEEK_ENV_FILE=examples/enterprise_wecom_digital_employee/.env AGENTSEEK_GATEWAY_LOG="$PWD/runtime-m05/gateway.log" nohup examples/enterprise_wecom_digital_employee/scripts/run_gateway.sh >/dev/null 2>&1 &
   curl -fsS http://127.0.0.1:12000/health
   curl -fsS http://127.0.0.1:12001/health
   ss -ltnp '( sport = :12000 or sport = :12001 )'
   stat -c '%a %n' runtime-m05/gateway.log runtime-m05/wecom-messages.sqlite3 runtime-m05/wecom-long-connection.lock
   ```

   Callback `:12000` 必须保持健康。Canary `:12001/health` 必须包含
   `ok=true`、`transport=long_connection` 和 `subscribed=true`。两个端口各有
   一个 PID，canary 日志、SQLite 和 lock 必须为 `600`。

   新 durable SQLite 应直接初始化为 revision 2。不要打开、迁移或复制现有
   Callback durable SQLite。

9. 验证同一数字员工下的员工和群聊隔离。

   - 员工 A 发送 `EMPLOYEE-A-M05`。
   - 员工 B 发送 `EMPLOYEE-B-M05`。
   - A 追问时只能恢复 A，B 追问时只能恢复 B。
   - 群 A 只写 `GROUP-ALPHA-M05`，群 B 只写 `GROUP-BETA-M05`。
   - 两个员工单聊和两个群聊双向零交叉。
   - userid 转明文不能把群聊改写成员工单聊。

   当前 `wecom:<userid>` 在“一实例一数字员工”边界内保持兼容。不要为 M0.5
   把 BotID 或 transport 加进单聊 session。未来多个 `digital_employee_id`
   共享数据库时，短期记忆必须增加 digital-employee 逻辑命名空间。

   Canary 使用独立存储，因此本轮不验证 Callback 与长连接之间的会话连续性，
   也不把两者不能互相回忆作为产品要求。

   `enterprise_user` 模式在单聊中仍使用匿名员工级语义作用域。群聊在该边界上
   追加匿名 `session_key`，防止同一员工在群 A 检索到群 B。群聊缺失有效
   `session_key` 时必须 fail closed，不得退回员工大作用域。作用域中不得出现
   raw userid、chatid、BotID 或 transport 名称。

### 复验 `2e4f3b3` BLOCKED 项

Transport 活体 Oracle 已全部通过。对 `fb6e851` 只重验群聊语义隔离，
不重跑单聊、引用、媒体、主动消息、卡片或 SIGTERM 活体。

1. 快进同名功能分支，确认 `fb6e851` 在 HEAD 祖先链上。
2. 运行确定性作用域回归。

   ```bash
   uv run pytest contrib/agentseek-contextseek/tests/test_plugin.py -k 'enterprise_group_scopes_are_isolated or enterprise_direct_chat_keeps_employee_scope or enterprise_group_scope_fails_closed' -q
   uv run pytest contrib/agentseek-contextseek/tests -q
   ```

   预期定向用例 `3 passed`；ContextSeek 全量 `46 passed, 1 skipped`。

3. 优雅停止并重启 `:12001` canary。保留现有 `runtime-m05` 语义库，不清空旧的
   员工级群聊记忆；这能验证修复后不再读取旧大作用域。Callback `:12000`
   全程不动。
4. 由同一名员工在两个群分别发送新的唯一标识：
   `GROUP-ALPHA-M05R` 和 `GROUP-BETA-M05R`，然后分别追问。
5. 群 A 只能回收 `GROUP-ALPHA-M05R`，不得出现 `GROUP-BETA-M05R`、
   历史 `GROUP-BETA-M05` 或群 B chatid。群 B 反向同理。两群 session/chat key
   仍必须各自稳定且互不相同。
6. 只有双向零交叉时，才在 Linux 记录中追加复验时间线并将 M0.5 改判
   PASS。若仍交叉，保留新证据并继续 BLOCKED。

### 复验 `328ff46` 的本群字面量召回

`328ff46` 已证明新群 C/D 跨群零交叉。它继续 BLOCKED 的原因是群 C
把“标识”误解为技术 ID，两次编造 32 位十六进制串。该问题不改
Transport，也不要用渠道层的确定性 setup 回显掩盖。

1. 确认短期记忆字面量修复 `e81b779` 在 HEAD 祖先链上。
2. 运行定向回归。

   ```bash
   uv run pytest contrib/agentseek-enterprise/tests/test_plugin.py -k 'system_prompt_can_include_short_term_memory or short_term_memory_prompt_preserves_user_literal or short_term_memory_prompt_keeps_newest' -q
   uv run pytest contrib/agentseek-enterprise/tests -q
   ```

   预期定向 `3 passed`，Enterprise 全量 `88 passed`。

3. 只优雅重启 `:12001` canary，保留群 C/D 现有短期记忆。群 C 中的
   GAMMA 用户原文和两条错误十六进制助手回复都不得清理。
4. 在原群 C/D 各发送一次相同追问：
   `请列出你在当前群记住的本轮唯一标识，只列标识。`
5. 群 C 必须逐字回复既有 GAMMA 用户原文，不得回复历史编造的十六进制串。
   群 D 必须逐字回复 DELTA。两群仍必须零交叉。
6. 本轮不要重做 setup，也不要更换模型。验收对象是短期记忆角色标注与
   原文复制规则，而不是特定模型的偶然命中。

### 复验 `5668e2f` 的模型上下文投影

Linux 已确认群 C 三次十六进制回复都等于各次追问自己的 `msgid`。因此本轮
验收对象是渠道 prompt 投影，不再把这些回复判为模型随机编造。

1. 确认 `5668e2f` 在 HEAD 祖先链上，且 `e81b779`、`fb6e851` 仍在同一链。
2. 运行定向与全量回归。测试端口必须避开运行中的 Callback `:12000`。

   ```bash
   AGENTSEEK_WECOM_PORT=12100 uv run pytest contrib/agentseek-wecom/tests -q
   PYTHONPATH=examples/enterprise_wecom_digital_employee/src uv run pytest examples/enterprise_wecom_digital_employee/tests -q
   uv run pytest contrib/agentseek-enterprise/tests -q
   uv run pytest contrib/agentseek-contextseek/tests -q
   ```

   预期分别为 `128 passed`、`332 passed, 1 skipped`、`88 passed`、
   `46 passed, 1 skipped`。
3. 静态检查模型可见 `context_str`：当前消息 `msgid`、BotID、原始 chatid、
   userid 均不得出现；员工文本和引用、媒体、卡片事件等业务语义仍须可见。
   内部上下文必须继续向渠道插件提供消息 ID，两个不同 `msgid` 的相同 Work
   请求仍必须生成不同幂等键。
4. 只优雅重启 `:12001` canary。不要停止或重启 Callback `:12000`，不要改
   `.env`，不要清理群 C/D 的短期记忆、SeekDB 或 durable SQLite。
5. 在原群 C/D 各发送一次：
   `请列出你在当前群记住的本轮唯一标识，只列标识。`
6. 群 C 必须逐字回复既有 GAMMA，群 D 必须逐字回复既有 DELTA。两群不得
   出现对方标识、历史 ALPHA/BETA、任何消息 `msgid`、BotID 或 chatid。
   每群只允许一个终态，session/chat key 必须保持稳定且互不相同。
7. 本轮无需重做 setup、换模型或重测单聊、流式、引用、媒体、主动消息、
   卡片和 SIGTERM。只有本单项 Oracle 通过后，才能将 M0.5 改判 PASS。

10. 验证单聊、活动流、引用和媒体。

    - 单聊发送 `M0.5 单聊：请只回复“长连接正常”`。
    - 首个可见流必须先于模型和媒体 I/O，最终内容只能出现一次。
    - 再发送约 1000 字慢任务。同一 `stream.id` 应持续更新，并在十分钟内完成。
    - 引用文本应进入 Agent；raw payload、URL、`req_id` 和回复能力不得进入上下文。
    - 发送一个可解析 PDF，再立即发送文本。文件回合必须先于后续文本完成。
    - 长连接媒体必须使用媒体 URL 同级 `aeskey`，不能使用 Callback EncodingAESKey。

11. 验证主动 Markdown、主动卡片和卡片事件。

    测试员工精确发送：

    ```text
    M0.5长连接主动消息探针
    ```

    必须先看到当前 stream 完成，随后恰好收到一条主动 Markdown 和一张
    `button_interaction` 卡片。按钮 key 是 `M05_CONFIRM`。

    点击 `确认交互`。必须产生恰好一个卡片事件 Agent 回合，且终态通过
    `aibot_send_msg` Markdown 到达同一会话。不得使用 `aibot_respond_msg`
    或残缺的 `aibot_respond_update_msg` 回应卡片事件。重放同一 `msgid`
    不得再次执行 Agent 或再次主动发送。

12. 验证 SIGTERM、重新订阅和终态恢复。

    只操作 `:12001` canary。发送约 1000 字慢任务，等待 durable inbox 进入
    `processing`，随后在一秒内对 canary PID 执行优雅 SIGTERM。

    - Callback `:12000` 全程健康且 PID 不变。
    - Canary 释放 WebSocket、lease 和 lock。
    - Canary 重启后重新订阅并恢复未完成记录。
    - 同一 `req_id` / `stream.id` 的终态恰好到达一次。
    - inbox 最终 `completed`，outbox 最终 `delivered`。

    异常断网重连、鉴权失败关闭和第二 owner 拒绝由确定性测试覆盖。不要
    修改 Linux 防火墙，也不要启动第二个相同 BotID 的长连接实例。

13. 执行脱敏和收官检查。

    只报告命中数，不输出原文。Canary 日志、events 和 WeCom durable SQLite
    中以下内容必须零明文：模型 Key、长连接 Secret、Callback Token、
    EncodingAESKey、AppSecret、PG/DM 密码、namespace/durable Secret、媒体
    URL/aeskey、`req_id`、员工正文和卡片 action payload。

    Enterprise short-term memory 和本地 ContextSeek 是明确授权的会话内容存储，
    可能包含有界员工对话。不要把预期内容误判为 durable 加密缺陷；应核对其
    文件权限为 `600`、路径只位于 `runtime-m05`，且员工 A/B 查询零交叉。
    所有本地存储仍必须对凭据和回复能力保持零明文。

    确认 canary 所有本地存储都位于 `runtime-m05`，共享 PostgreSQL schema 和
    数据零变化，Callback 文件和数据库零变化。验证完成后清空
    `AGENTSEEK_WECOM_LONG_CONNECTION_PROACTIVE_PROBE_TRIGGER`，只重启 canary，
    再次执行 `prod_check` 和两个 `/health`。

## 通过与阻断标准

以下项目全部满足才判定 PASS：

- 静态门禁全过；
- 新 BotID/Secret 订阅成功，且只有一个长连接 owner；
- Callback 实例全程不受影响；
- 员工 A/B、群 A/B、引用、身份和媒体无交叉；
- 当员工要求复述本会话的字符串或标识时，回复逐字来自历史用户原文，
  不编造 UUID、哈希或内部 ID；
- 活动流复用同一消息并在十分钟内完成；
- 主动 Markdown/Card 只发往已与新机器人交互的会话；
- 卡片事件不误用消息流回复命令；
- SIGTERM 后 lease、lock 和 WebSocket 正确释放并恢复；
- Canary 敏感信息零明文，共享存储和 Callback 数据零变化。

缺少管理员凭据或窗口时记录 `WAITING_FOR_ADMIN_CREDENTIALS`。真实代码缺陷
判定 BLOCKED。可写路径重合属于部署配置 BLOCKED，修正隔离后才能开始活体。

PASS 只能表述为：

> 单个部门数字员工可以通过独立 AI Bot 使用长连接 Transport，并与现有
> Callback 实例并行运行。

不得表述为多 Profile gateway、公共自建应用或任意成员/部门/标签推送已经完成。

## 回滚

1. 优雅停止 `:12001` canary，确认 PID、WebSocket、lock 和端口已释放。
2. 保留 `runtime-m05` 到权限 `700` 的受限归档，不删除 SQLite 或日志。
3. 由管理员停用新测试机器人，或保留它但不启动任何长连接实例。
4. 不切换现有 Callback 机器人，不恢复或修改它的 SQLite。
5. 确认 production `:12000` 健康并完成一条单聊冒烟。
6. 只有在验证记录已提交且运行材料已归档后，才移除 canary worktree。

不 force push，不修改 `production`，不建立 tag，不提交 `.env`、日志或
`runtime-m05`，不迁移共享数据库。

## 故障处理

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `:12001` 启动失败 | 端口、lock 或本地路径与其他实例冲突 | 停止 canary，修正隔离；不要操作 Callback |
| 新机器人不订阅 | BotID/Secret 错误或后台未选择长连接 | 只报告错误类型，请管理员核对凭据 |
| 员工 A/B 上下文交叉 | session 或短期记忆隔离失效 | 判为 BLOCKED，保留脱敏记录 |
| Canary 读到 Callback 历史 | 可写/读取存储没有隔离 | 判为部署配置 BLOCKED，不清库掩盖 |
| 主动消息无法发送 | 会话未先与新机器人交互 | 先由同一会话发送探针，不能绕过资格检查 |
| 公共应用可以发指定人员消息 | 使用了 M0.5 范围外代码或人工 API | 不计入 M0.5；等待 M0.6 Transport |
