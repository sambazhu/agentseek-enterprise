# 如何复验企微 M0.5 AI Bot 长连接

用于把一个已通过 M0.4 的 AI Bot 从 Callback 独占切换到长连接，并验证
订阅、流式回复、恢复、主动 Markdown/Card、卡片事件和媒体解密。

## 前置条件

- 功能分支是 `enterprise/v0.1.2-wecom-long-connection`。
- 代码 HEAD 是 `d05432a378a0dcf7e76c546a1f435bd8c652a5da`。
- 父生产基线是 `0d16633160755472f6f775b49189479c46a6f84f`。
- 企微管理员已准备长连接专用 BotID 和 Secret，并能切换机器人 API 模式。
- Linux 是该机器人的唯一运行实例；Mac mini 同机器人保持停止。
- 当前 M0.4 Callback 在切换窗口前保持运行。
- M0.3 的 durable SQLite 路径和加密 Secret 保持不变。
- 模型 API Key 轮换不属于本轮复验项。

如果管理员凭据或切换窗口尚未就绪，只完成静态核验。记录
`WAITING_FOR_ADMIN_CREDENTIALS`，不要停止 Callback，也不要修改 `.env`。

## 步骤

1. 核对提交和祖先关系。

   以下远端命令等待功能分支发布后由 Linux 执行。

   ```bash title="not executed in this run"
   git fetch company-gitlab enterprise/v0.1.2-wecom-long-connection
   git rev-parse company-gitlab/enterprise/v0.1.2-wecom-long-connection
   git merge-base --is-ancestor 0d16633160755472f6f775b49189479c46a6f84f company-gitlab/enterprise/v0.1.2-wecom-long-connection
   git diff --check 0d16633160755472f6f775b49189479c46a6f84f..company-gitlab/enterprise/v0.1.2-wecom-long-connection
   ```

2. 运行确定性门禁。

   ```bash
   uv lock --check
   uv run pytest -q contrib/agentseek-wecom/tests
   PYTHONPATH=examples/enterprise_wecom_digital_employee/src uv run pytest -q examples/enterprise_wecom_digital_employee/tests
   uv run ruff check contrib/agentseek-wecom examples/enterprise_wecom_digital_employee
   PYTHONPATH=examples/enterprise_wecom_digital_employee/src uv run ty check contrib/agentseek-wecom/src contrib/agentseek-wecom/tests examples/enterprise_wecom_digital_employee/src
   PYTHONPATH=. uv run pytest -q tests/cli_commands/test_templates_render.py -k "enterprise and wecom"
   uv run pytest -q tests/test_wecom_integration.py
   make docs-test
   bash -n examples/enterprise_wecom_digital_employee/scripts/run_gateway.sh
   ```

   本地基线是企微组件 127 passed、数字员工样例 332 passed / 1 skipped、
   模板 5 passed、企微集成 3 passed。允许既有 TestClient 和 Uvicorn
   WebSocket 适配层的弃用警告。

3. 在停机前冻结运行边界。

   - 确认企微后台仍是 Callback 模式。
   - 确认 Linux `:12000` 只有当前 M0.4 实例。
   - 确认 Mac mini 同机器人没有启动。
   - 记录当前 PID、production commit 和健康响应。
   - 确认共享 PostgreSQL schema 与 M0.4 记录一致。

4. 进入切换窗口，优雅停止 Callback。

   使用 Linux 已固化的进程管理方式停止当前网关。不要启动第二个实例。
   停止后确认 `:12000` 无监听，日志包含 Bub channel manager 完整停机记录。

5. 在网关停止时备份 revision 1 durable SQLite。

   以下命令假定 Linux 继续使用已验证路径。它们未在本机执行。

   ```bash title="not executed in this run"
   set -euo pipefail
   install -d -m 700 runtime/restricted-archive
   test ! -e runtime/restricted-archive/wecom-messages.pre-m05-d05432a.sqlite3
   cp --preserve=mode runtime/wecom-messages.sqlite3 runtime/restricted-archive/wecom-messages.pre-m05-d05432a.sqlite3
   chmod 600 runtime/restricted-archive/wecom-messages.pre-m05-d05432a.sqlite3
   ```

   只输出 schema revision，不输出加密记录。

   ```bash title="not executed in this run"
   uv run python -c "import sqlite3; c=sqlite3.connect('runtime/wecom-messages.sqlite3'); print(c.execute(\"SELECT value FROM wecom_durable_meta WHERE key='schema_version'\").fetchone()[0]); c.close()"
   ```

   预期为 `1`。不是 `1` 时停止切换，不自动改表。

6. 切换到功能分支并配置长连接。

   ```bash title="not executed in this run"
   git switch enterprise/v0.1.2-wecom-long-connection
   git merge --ff-only company-gitlab/enterprise/v0.1.2-wecom-long-connection
   ```

   在 Linux `.env` 中设置以下配置。示例中的 `REPLACE_...` 是假值，必须由
   管理员提供真实值后才能启动。不要打印或提交 `.env`。

   ```env title="not executed in this run"
   AGENTSEEK_WECOM_TRANSPORT_MODE=long_connection
   AGENTSEEK_WECOM_LONG_CONNECTION_BOT_ID=REPLACE_WITH_ADMIN_BOT_ID
   AGENTSEEK_WECOM_LONG_CONNECTION_SECRET=REPLACE_WITH_ADMIN_SECRET
   AGENTSEEK_WECOM_LONG_CONNECTION_URL=wss://openws.work.weixin.qq.com
   AGENTSEEK_WECOM_LONG_CONNECTION_HEARTBEAT_SECONDS=30
   AGENTSEEK_WECOM_LONG_CONNECTION_COMMAND_TIMEOUT_SECONDS=10
   AGENTSEEK_WECOM_LONG_CONNECTION_RECONNECT_MIN_SECONDS=1
   AGENTSEEK_WECOM_LONG_CONNECTION_RECONNECT_MAX_SECONDS=30
   AGENTSEEK_WECOM_LONG_CONNECTION_STREAM_INTERVAL_SECONDS=3
   AGENTSEEK_WECOM_LONG_CONNECTION_LOCK_PATH=runtime/wecom-long-connection.lock
   AGENTSEEK_WECOM_LONG_CONNECTION_PROACTIVE_PROBE_TRIGGER=M0.5长连接主动消息探针
   AGENTSEEK_WECOM_DURABLE_MODE=sqlite
   ```

   保留原 durable SQLite 路径和 Secret。Callback Token、EncodingAESKey 可以
   留在 `.env`，但长连接模式不会使用它们。不要改变 Work、Langfuse 或共享
   PostgreSQL 的既有 Linux 决策。

7. 运行生产预检，然后由管理员切换企微后台。

   ```bash title="not executed in this run"
   uv run python examples/enterprise_wecom_digital_employee/scripts/prod_check.py --env-file examples/enterprise_wecom_digital_employee/.env
   ```

   必须是 0 FAIL。随后由管理员把同一机器人从 Callback 切为长连接。
   不要同时保留 Callback 实例，也不要建立第二条 WebSocket 连接。

8. 启动长连接并核对订阅健康。

   ```bash title="not executed in this run"
   AGENTSEEK_GATEWAY_LOG="$PWD/runtime/gateway.log" nohup examples/enterprise_wecom_digital_employee/scripts/run_gateway.sh >/dev/null 2>&1 &
   curl -fsS http://127.0.0.1:12000/health
   ss -ltnp '( sport = :12000 )'
   stat -c '%a %n' runtime/gateway.log runtime/wecom-messages.sqlite3 runtime/wecom-long-connection.lock
   ```

   `/health` 必须包含 `ok=true`、`transport=long_connection` 和
   `subscribed=true`。端口只能有一个 PID，三个文件必须为 `600`。
   启动窗口必须有一次订阅成功，且没有 Traceback、ERROR 或鉴权重试循环。

   启动会把专用 SQLite 从 revision 1 原子迁移到 revision 2。只核对版本：

   ```bash title="not executed in this run"
   uv run python -c "import sqlite3; c=sqlite3.connect('runtime/wecom-messages.sqlite3'); print(c.execute(\"SELECT value FROM wecom_durable_meta WHERE key='schema_version'\").fetchone()[0]); c.close()"
   ```

   预期为 `2`。共享 PostgreSQL schema 必须保持不变。

9. 验证单聊、群聊和活动流。

   - 单聊发送 `M0.5 单聊：请只回复“长连接正常”`。
   - 首个可见流必须先于模型和媒体 I/O，最终内容只能出现一次。
   - 再发送一个约 1000 字的慢任务。企微 UI 应看到同一条 stream 更新，
     `stream.id` 保持不变，并在十分钟内 `finish=true`。
   - 群 A 只写 `ALPHA-M05`，群 B 只写 `BETA-M05`，双向追问零交叉。
   - 引用消息应进入 Agent，但签名 URL、回复能力和 raw payload 不进入上下文。
   - open userid 转明文后，单聊兼容且群聊地址不被成员身份改写。

10. 验证主动 Markdown、主动卡片和卡片事件。

    测试员工精确发送：

    ```text
    M0.5长连接主动消息探针
    ```

    必须先看到探针当前流完成，随后恰好收到一条主动 Markdown 和一张
    `button_interaction` 卡片。卡片按钮 key 是 `M05_CONFIRM`。

    点击 `确认交互`。必须产生恰好一个卡片事件 Agent 回合，且终态通过
    `aibot_send_msg` Markdown 到达同一会话。不得发送
    `aibot_respond_msg` 或残缺的 `aibot_respond_update_msg` 来回应卡片事件。
    重放同一 `msgid` 不得再次执行 Agent 或再次主动发送。

11. 验证长连接媒体密钥。

    从单聊发送一个可解析 PDF，再立即发送一条文本。首个流必须先于下载和
    解析，文件回合必须先于后续文本完成。下载使用该媒体 URL 同级返回的
    `aeskey`；不能回退使用 Callback EncodingAESKey 来解密长连接媒体。

12. 验证 SIGTERM、终态恢复和重新订阅。

    发送约 1000 字慢任务。观察 durable inbox 进入 `processing` 后，在一秒内
    对唯一网关执行优雅 SIGTERM。必须满足：

    - 旧进程完整执行 channel manager 停机并释放 lease；
    - 旧进程不再占有 WebSocket 或本地 lock；
    - 新进程启动后重新订阅，并立即恢复未完成记录；
    - 同一 `req_id` / `stream.id` 的终态恰好到达一次；
    - inbox 最终 `completed`，outbox 最终 `delivered`。

    异常断网后的周期重连、鉴权失败关闭和第二 owner 拒绝由
    `test_long_connection.py` 的确定性 Oracle 覆盖。不要为活体测试修改
    Linux 防火墙或制造第二个生产实例。

13. 执行脱敏和收官检查。

    只报告命中数，不输出原文。`gateway.log`、enterprise events 和 durable
    SQLite 中以下内容必须零明文命中：模型 Key、长连接 Secret、Callback
    Token、EncodingAESKey、AppSecret、PG/DM 密码、namespace secret、媒体
    URL/aeskey、`req_id`、员工原文和卡片 action payload。

    核对 inbox/outbox 均为终态，`wecom_conversations` 地址为密文，且共享
    PostgreSQL 表与扩展清单不变。验证完成后清空
    `AGENTSEEK_WECOM_LONG_CONNECTION_PROACTIVE_PROBE_TRIGGER` 并重启唯一实例。
    清空后再次执行 `prod_check` 和 `/health`。

## 通过与阻断标准

以下项目全部满足才判定 PASS：

- 静态门禁全过；
- BotID/Secret 订阅成功，健康端点真实反映 subscribed；
- 单聊、双群、引用、身份和媒体无回归；
- 活动流复用同一消息并在十分钟内完成；
- 24 小时回复期限与 durable 终态恢复合同成立；
- 主动 Markdown/Card 只发往已交互会话；
- 卡片事件不误用消息流回复命令；
- SIGTERM 后 lease、lock 和 WebSocket 所有权正确释放；
- 敏感信息零明文，共享 schema 零变化。

真实缺陷判定 BLOCKED，并先执行回滚。缺少管理员凭据或窗口只判定
`WAITING_FOR_ADMIN_CREDENTIALS`，不视为代码缺陷。

## 回滚

1. 优雅停止长连接网关，确认进程、`:12000` 和 lock 均已释放。
2. 由企微管理员把机器人切回 Callback。
3. 将 `.env` 的 transport 改回 `callback`，并清空 M0.5 探针触发词。
4. 保留 revision-2 文件用于对账，恢复停机前 revision-1 备份。

   以下命令未在本机执行。执行前确认两个 archive 目标都不存在。

   ```bash title="not executed in this run"
   set -euo pipefail
   test ! -e runtime/restricted-archive/wecom-messages.failed-m05-d05432a.sqlite3
   mv runtime/wecom-messages.sqlite3 runtime/restricted-archive/wecom-messages.failed-m05-d05432a.sqlite3
   cp --preserve=mode runtime/restricted-archive/wecom-messages.pre-m05-d05432a.sqlite3 runtime/wecom-messages.sqlite3
   chmod 600 runtime/wecom-messages.sqlite3
   git switch production
   git merge --ff-only company-gitlab/production
   ```

5. 用现有 `run_gateway.sh` 启动 Callback，复核单实例、健康和一条单聊。

不要让 M0.4 代码直接打开 revision-2 文件。不要删除 revision-2 文件；切换窗口
内的新消息可能需要人工对账。不要迁移共享数据库，不 force push，不改
`production`，不建立 tag，不提交 `.env`、日志或 `runtime/`。
