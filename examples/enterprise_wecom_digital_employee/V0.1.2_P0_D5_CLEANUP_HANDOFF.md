# 清理 v0.1.2 P0 生产复验 D5 合成记忆

将本任务交给 Linux CC。用户已批准只清理本次生产复验产生的三个合成标记：
`D5DM-3308`、`D5GA-4419`、`D5GB-5521`。本任务不授权清理其他数据、重启服务、
修改配置、移动标签或推进 M3。

## 1. 固定边界

- 清理长期 Store、`enterprise_short_term_messages` 和 ContextSeek pgvector 三层中的
  D5 数据；使用现场实际表名和部署报告记录的三个完整 namespace/session/scope。
- durable 预期为一个员工 5 段 namespace 和两个群 7 段 namespace；短期与语义层
  预期为 dm、群 A、群 B 三个已记录范围。不得只凭哈希前缀执行写操作。
- 只允许“完整范围键 AND 三个精确标记”双重命中。禁止仅按 `LIKE '%D5%'`、时间窗、
  员工键、租户键或 namespace 前缀批量删除。
- 明确保留 6 条 Mac 时代口令槽位、`R3DM-6102`、`quarterly_priority` 及所有非 D5
  生产记忆。不得删除整个员工画像、整个群画像、整个会话或整个 scope。
- 不输出连接串、原始员工/群/会话标识、完整画像或聊天原文。报告只保留计数、缩短后的
  哈希和非敏感摘要。

## 2. 只读盘点并设停止条件

1. 核对 GitHub/GitLab 的 `production` 与不可移动标签
   `enterprise-wecom-v0.1.2-hotfix1`；标签必须指向 Codex 回传的精确修订提交，旧
   `enterprise-wecom-v0.1.2-ga` 不得变化。
2. 从生产部署报告及现场脱敏事件中恢复三个**完整**范围键，在内存中核对 dm、群 A、
   群 B 的预期对应关系。不要把完整键写入报告或终端历史。
3. 对三层做只读 SELECT，按“范围 × 标记”记录命中数。另做全库只读查找，确认没有
   D5 命中落在这三个范围之外。
4. durable 层只应命中 `/employee-profile.md` 的三个画像项；每个标记应只存在于其预期
   画像的一条 Markdown 行中。记录删除目标行之外内容的摘要哈希。
5. 任一完整范围无法确认、标记落在范围外、同一画像内命中行数不是 1、表结构与当前代码
   不一致，或无法证明 6 条旧槽位不受影响时，停止并回传 BLOCKED，不执行任何写入。

## 3. 精准清理

- 使用一次性、未提交的维护脚本调用现场数据库驱动；脚本不得读取或打印无关行。所有 SQL
  必须参数化，表名只能取自已校验的生产配置并通过现有标识符校验规则。
- durable：逐个完整 namespace 锁定 `/employee-profile.md` 项，解析 `value_json`，
  仅移除包含该范围对应精确标记的单条 `content` 行，再写回同一项。提交前断言：目标行
  恰好减少 1，其他行内容与顺序的摘要不变；禁止 DELETE 整个画像项。
- 短期记忆：仅删除三个完整 `session_id` 中 `content` 含三个精确标记的消息行。范围键
  与标记条件必须同时出现在 DELETE 谓词中；先锁定并核对 DELETE 返回计数。
- pgvector：仅删除三个完整 `scope` 中 `content` 含三个精确标记的向量行；scope 与
  标记条件必须同时出现。不要重建表、索引或 embedding。
- 每个数据源使用自己的事务。提交前复跑该源的范围内与全库 D5 计数；不满足预期就回滚
  当前事务并停止。跨数据源无法原子提交时，不伪造全局事务；若中途失败，准确报告已提交
  与未执行的层，等待新指令。
- 不通过手机或模型询问 D5 标记来验收，因为新问题本身会再次写入短期/语义层；清理后只做
  数据层只读复核。无需停止或重启网关。

## 4. 复核保护对象

- 三层全库只读查找三个 D5 标记，期望残留均为 0。
- durable 三个画像的非目标行摘要必须与清理前一致；6 条旧 Mac 槽位数量及摘要保持不变。
- `R3DM-6102` 和其他明确保留项仍存在；非 D5 行总数变化只能等于清理前已批准的目标数。
- 生产进程、健康端点、模块加载路径、`.env`、MCP、pack/profile 本地定制、数据库结构
  和 Git 工作树状态均不得因本任务改变。

## 5. 回传结果

- 新建同目录 `V0.1.2_P0_D5_CLEANUP_RESULTS.md`，逐层记录预检计数、实际变更计数、
  清理后残留数、保护对象核对和 PASS/FAIL/BLOCKED；只写脱敏证据。
- 若三层全部通过，提交结果报告并普通推送 `production` 到 GitHub/GitLab，核对两端 SHA
  完全一致。若现场流程还维护 P0 feature 报告 ref，只能快进同步，不得强推。
- 不移动 `enterprise-wecom-v0.1.2-hotfix1` 或旧 GA 标签。清理报告位于标签之后的
  production 提交是预期状态。
- 不提交维护脚本、日志、数据库快照、配置或画像内容；不恢复 M3。
