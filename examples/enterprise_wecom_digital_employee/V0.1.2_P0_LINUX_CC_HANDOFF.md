# 验收 v0.1.2 P0 企业记忆会话隔离补丁

将下面整段任务交给 Linux CC。完成后，将报告路径和报告提交 SHA 回传给 Mac Codex。

## Linux CC 任务提示词

你负责验收 P0（原回归 ISSUES #11、B5），不是部署生产或推进 M3。

### 1. 核对版本并隔离环境

- 仓库：GitHub `sambazhu/agentseek-enterprise`；GitLab `harness_agent/agentseek-enterprise`。
- 目标分支：`enterprise/v0.1.2-p0-memory-scope`。
- 必须包含补丁提交：`9045b1ec0c5a7103a519d4ce56785296090b7972`。
- 基线：`d82c93b0eccf2bc58aa899aa426ce5ddae2519a3`；历史生产代码基线为 `b339228`。
- 先记录当前代码、运行进程、模块实际加载路径和工作树状态，禁止输出凭据。
- 拉取目标分支到独立工作树，核验两个远端分支 SHA 一致，并确认包含上述补丁。
- 不覆盖脏工作树，不切换生产工作树，不修改现有配置或数据库结构。
- 使用隔离虚拟环境及测试数据库。测试不可自动加载生产连接配置。
- 先阅读仓库适用的 AGENTS.md、原 ISSUES #11 和 RESULTS_B。

### 2. 跑离线门禁

- 使用目标工作树的 ContextSeek、Enterprise、LangChain、WeCom 源码。
- 记录这四个模块的实际加载路径，防止 editable install 指向旧工作树。
- 运行四个组件的 tests 目录；合并运行时使用 pytest 的 `--import-mode=importlib`。
- 对补丁三个 Python 文件运行 Ruff（不自动修复），并检查 git diff 空白错误。
- Mac 最后一次结果：327 passed、1 skipped、2 个 websockets 弃用警告。
- 唯一跳过项是 `test_pgvector_real_postgres_roundtrip`，因为未提供测试数据库。
- `test_scope_boundary.py` 的 SeekDB/pgvector 参数化用例使用 mock 客户端，不能写成真实后端验收。
- 记录实际命令、退出码、测试数量、跳过原因、Python 和主要依赖版本。

### 3. 验证真实 pgvector

- 确认专用测试数据库已获准使用，再安全配置 `AGENTSEEK_CTX_PGVECTOR_TEST_URL`。
- 不把 URL、密码或完整环境变量写入命令记录、报告、Git 或外部追踪系统。
- 运行 `test_pgvector_real_postgres_roundtrip`；必须实际 PASS，skip 不算通过。
- 此测试会创建固定表 `contextseek_pgvector_test_items`，并删除其中测试 scope 的数据。
- 因此只能在隔离测试库执行；不得直接指向生产库，也不得并发运行该固定表测试。
- 该 roundtrip 不是完整隔离证明。另做真实数据库的私聊、群 A、群 B 三 scope 交叉检索。
- 写入不同的无敏感合成标记，验证各 scope 只召回自身内容，反向与并发查询也不能串读。
- 清理时仅清理本轮合成测试数据；不删除生产记忆，不扩大到其他表或 scope。
- 缺数据库或权限时标为 BLOCKED，写明缺失条件，不用 mock 结果代替。

### 4. 验证运行时与企微隔离

- 先使用隔离测试实例，不接管生产机器人的连接、端口、锁文件或消息队列。
- 如现有条件必须切换生产、重启网关或复用生产机器人，先停止该步骤并请求用户确认。
- 请求确认时列出影响范围、配置与版本快照、回滚步骤，以及手机端配合要求。
- 未获确认时继续可完成的离线项目，活体项目标为 BLOCKED，不自行部署。
- 每轮使用新生成的合成标记和干净测试会话，避免旧泄漏数据污染判定。
- 不在群聊问题里包含私聊标记本身，也不通过引用、附件或共享知识库带入它。

验收矩阵：

| 项目 | 操作及判据 |
| --- | --- |
| 私聊正向 | 私聊写入标记，再在私聊准确召回；不得因全部禁用记忆而假通过。 |
| 私聊到群 | 群 A、群 B 分别询问私聊标记；均不得披露。 |
| 双群正向与交叉 | 两群分别写入、召回自身标记；不得召回另一群标记。 |
| 群到私聊 | 私聊不得因本补丁扩大 scope 而召回群专属标记。 |
| 并发 | 同一员工的私聊和两个群交错发送，逐回合核对读写范围。 |
| 传输路径 | 验证 LC 群聊和单聊、自建应用单聊；确认私聊间共享仍符合原设计。 |
| 提示词适配 | 原始 build_prompt 被提前返回后，LangChain 二次调用仍保留群范围。 |
| 失败关闭 | 未知、冲突、缺身份、缺群 session_key、跨会话状态及过期 scope 均不读写。 |

- 手机交互由用户配合；只看到服务日志时，不声称已确认手机收到的答案。
- 对每个测试回合核对：入口会话分类、canonical session、短期记忆加载键、语义 retrieve scope、save scope。
- 报告使用 turn-01、dm、group-a、group-b 等脱敏别名；保留等同性关系，不提交真实标识。
- 原事故还出现过短期记忆键不一致。必须核对该现象，不把语义层补丁当成它已修复的证据。
- Mac 已复现“缺群上下文＋不透明 session ID 时退回员工 scope”的代码缺口；尚未证明线上事故根因。
- 若实际入口与该路径不同，记录反证并保留 P0，不迁就预期结论。
- 出现串读立即停止进一步敏感验证；仅保留脱敏证据，不继续向其他群扩散内容。
- 历史泄漏造成的存量污染单独记录并提出处置方案，不擅自删除或迁移生产记忆。

### 5. 写报告并回传

- 新建 `examples/enterprise_wecom_digital_employee/V0.1.2_P0_LINUX_REGRESSION_RESULTS.md`。
- 不覆盖原 B5 FAIL 记录，不删除原 ISSUES #11 证据。
- 报告包含：实际测试 SHA、环境与模块路径、命令及退出码、逐项 PASS/FAIL/BLOCKED/NOT RUN、脱敏证据路径。
- 分开写离线、真实数据库、企微活体结果；说明是否发生任何运行态变更及是否已恢复。
- 每个 FAIL 给出复现步骤、预期/实际结果和最小脱敏证据；不能验证的根因标为未确认。
- 给出 P0 是否具备关闭条件的建议；未完成真实数据库及活体隔离验证时，不写“P0 已关闭”。
- 提交前检查 diff，仅提交报告和必要的脱敏文字证据；不提交环境文件、日志、数据库或聊天原文。
- 报告提交到本任务分支，普通推送到 GitHub 和 GitLab，并核对两端 SHA 一致。
- 如果远端已有新提交或出现非快进冲突，停止并报告，不 force push。
- 不合并主分支，不打发布 tag，不开启 M3，不直接部署生产。
- 最终回传：报告路径、补丁 SHA、实际测试 SHA、报告 SHA、双远端验证结果、通过/失败/阻塞项及所需用户动作。
