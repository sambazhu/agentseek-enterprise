# 部署 v0.1.2 P0 企业记忆隔离修复

将本任务交给 Linux CC。目标是同步 `production`、部署已验收补丁并验证运行态。
本任务不授权移动旧 GA tag、清理额外数据或推进 v0.1.3 M3。

## 1. 核对发布提交

- GitHub 仓库为 `sambazhu/agentseek-enterprise`，GitLab 项目为
  `harness_agent/agentseek-enterprise`。
- Codex 回传消息中的精确 production SHA 是唯一部署目标；按分支名取最新值不够。
- 目标必须包含关闭报告 `08f87a4`、语义修复 `9045b1e` 和 durable 修复 `a22d6d5`。
- 目标必须是原 production `b339228` 的后代；旧 tag `enterprise-wecom-v0.1.2-ga`
  保持不变。
- 先核对 GitHub 的 feature 与 production ref，再将两者普通推送到 GitLab。
- 分别用远端查询核对 GitHub/GitLab 的 production SHA 完全一致。
- 发生非快进、分叉或不明提交时停止，不合并、不变基、不强推。

## 2. 保护生产现场

- 部署前记录当前提交、工作树状态、进程、监听端口、健康状态和模块加载路径。
- 只记录本地定制文件名或脱敏摘要；不要输出 `.env`、连接串、token 或员工标识。
- 生产工作树含未提交的跟踪文件时停止，不 stash、不 reset、不覆盖本地定制。
- `.pth` 曾指向生产 contrib 源码。部署后必须检查 ContextSeek、Enterprise 和企业样例
  三类模块的实际加载路径，不能只看 Git 提交。
- 部署前写明现场实际使用的启动、停止和回滚步骤。无法无损回滚时标 BLOCKED。
- 代码回滚基线为 `b339228` 加现场既有本地定制；回滚不得移动 GitHub/GitLab 的
  production ref，也不得删除新群 namespace 中的数据。
- 补丁没有 schema migration。不要因此执行数据库结构变更或全表清理。

## 3. 请求运行态变更确认

- 在停止或重启生产服务前，向用户列出目标 SHA、预计影响的实例和短暂停机范围。
- 同时列出配置快照状态、回滚基线、回滚方法及手机端配合项。
- 只有用户明确确认本次 production 部署后才执行运行态变更。
- 未确认时可以完成双端同步和只读预检，部署状态写 BLOCKED，不自行切换。

## 4. 部署并验证加载版本

- 使用已核验的 production 精确 SHA，不再用 feature 分支或临时 PYTHONPATH overlay
  作为最终生产状态。
- 保留现有 `.env`、MCP 配置、部门 Pack/Profile 本地定制、数据库和运行目录。
- 按现场标准流程优雅停止并启动网关；不得同时启动第二个长连接持有者。
- 启动后核对进程只运行一份，预期端口和锁归属唯一，两个健康端点正常。
- 检查实际加载文件均来自目标 production 工作树，且目标 SHA 与进程对应。
- 检查启动到验证窗口无 Traceback、数据库错误、重复消费或凭据输出。

## 5. 做最小生产复验

- 使用全新合成标记；不要复用已清理的 R1/R2/R3、DIRECT、KAPPA 等标记。
- 私聊通过 durable 工具写入并召回一个标记，确认落员工 5 段 namespace。
- 两个群分别通过 durable 工具写入并召回自身标记，确认落不同 7 段 namespace。
- 私聊、群 A、群 B 两两交叉询问，六向均不得披露其他范围的新标记。
- 自建应用单聊召回私聊标记，确认与 LC 私聊继续共享员工范围。
- 同时核对短期记忆和 ContextSeek 语义 scope 未回归；群会话不能回退员工桶。
- 以工具事件、数据库落点和手机端最终答案三者共同判定，模型口头“已记录”不算落库。
- 任一串读、模块路径错误或重复回复立即停止，并按预先记录的方法回滚代码。
- 新合成数据的清理需要用户在本轮明确批准；否则仅登记精确范围，保留待处理。
- 不触碰报告所列 6 条更早 Mac 测试槽位，除非用户另行批准清理。

## 6. 记录部署报告

- 新建同目录 `V0.1.2_P0_PRODUCTION_DEPLOY_RESULTS.md`。
- 写明 production SHA、双远端 SHA、部署前后模块路径、健康状态及运行态变更时间。
- 逐项记录 PASS/FAIL/BLOCKED/NOT RUN，并给出最小脱敏证据。
- 说明是否回滚、是否清理本轮合成数据，以及现场本地定制是否保持原样。
- 仅提交报告，不提交配置、日志、数据库、画像内容或聊天原文。
- 报告普通推送 GitHub/GitLab，并核对两个 production ref 和报告分支 ref。
- 报告通过前不创建新正式 tag；通过后由维护者决定新 hotfix tag 名称。
- 不移动 `enterprise-wecom-v0.1.2-ga`，不合并 v0.1.3，不恢复 M3。
