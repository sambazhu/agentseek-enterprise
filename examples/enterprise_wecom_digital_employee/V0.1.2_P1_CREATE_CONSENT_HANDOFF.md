# P1 发布后新建授权边界复测

用于复测 Linux `1b03515` 回执发现的“修订请求自动新建空任务”。本次仅修补新建授权，不改变报告内容协议。
部署完整 SHA 以分发回执为准，不覆盖此前 Linux 结果报告。

## 前置

- 沿用 schema 12，不新增迁移、不恢复迁移前备份；保留既有新写入和备份。
- 核对 P1 分支包含 `1b03515`，双端普通推送核验；同时加载本分支 Work 包与示例代码。
- 不合并 production，不移动标签，不启用交付或生产 MCP，不删除历史数据。
- 本地已验证示例与 Work 账本 **490 passed / 1 skipped**（真实 PostgreSQL 跳过），模板定向 **5 passed**。未执行 Linux、真实模型或手机验证。

## 定向步骤

1. 在本人已有 published / delivered 报告的情况下，请求“修改已发布报告”。确认旧内容未改，**WorkItem 零新增**。若模型尝试创建，工具必须询问是否新建并明确说明本轮未创建。
2. 发送“不需要新建报告任务”、问句、转述以及仅“同意”。均不得新增任务。本版采用无跨轮隐式授权的保守控制：需在当前消息明确写出新建动作；不要把此前同意或引用内容当作本轮授权。
3. 发送“新建报告任务”或“请新建一份报告”。确认恰一条新任务；明确命令无需再确认。同一消息重放不得重复创建。
4. 重放原历史任务的创建消息，确认仍返回原幂等任务，不产生新行；此路径只读取已存在任务，不受新建门禁误拦。
5. 第三个活动同类任务仍拒绝；旧 published / delivered 内容与发布记录不变。不要为复测原位改动旧合同，测试新任务登记待处置。
6. 恢复 WORK=false / PRODUCTION_MCP=false，核对单实例、双健康与错误增量。异常时关闭 Work、保留新库，不回退 schema。

明确命令使用限定句式（新建／创建新的＋报告／行业报告／报告任务，可带“请”“确认”“同意”）。其他自然表达会要求使用明确句式，不依赖模型判断绕过门禁。
工具只从运行时最近一条用户消息取授权文本，不提供模型可填写的确认布尔值或授权话术参数。
