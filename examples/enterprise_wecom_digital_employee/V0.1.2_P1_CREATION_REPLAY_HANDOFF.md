# P1 历史创建消息重放隔离复测

用于复测 `6e7a0f9` 回执中的偏差：原创建消息重放被其他活动任务吸收并写入 Brief。
本轮必须验证零写入，不能只检查 WorkItem 行数不增加。

## 前置

- 核对 P1 分支包含基线 `6e7a0f9`，部署 SHA 以分发回执为准；双端普通推送核对。
- 同时加载新 Work 包与示例代码。沿用 schema 12，无迁移、不倒库、不改备份。
- 保留 production、GA、hotfix1、M3、交付和 MCP 配置，不清理历史测试数据。
- 本地示例与 Work 回归 491 passed / 1 skipped；全部模板渲染测试 55 passed，合计 **546 passed / 1 skipped**。跳过项依赖真实 PostgreSQL。
- 本地覆盖已发布旧任务与活动新任务并存、消息标准化后 ID 保留、全账本表快照不变、同文新 ID 不命中、四维身份范围拒绝；真实 Linux 与手机验证待执行。

## 步骤

1. 在受控 Work 窗口准备旧创建消息及其原任务 A，并准备同类活动任务 B。记录 A/B 的合同、事件、来源、证据、claims、审批、artifact、publication、delivery 与预算账本基线。
2. 使用同一渠道消息 ID、同一身份和会话范围重放 A 的原创建消息。不要把手机重新输入相同文字当作重放；新发送通常具有新消息 ID。
3. 确认直接返回 A 的 work_id 和当前状态，且明确没有续接 B。核验模型调用增量 0、工具业务调用增量 0、A/B 账本行数和内容摘要全部不变；当前活动任务仍为 B。
4. 再次重放相同消息，仍只读返回 A；检查状态回显与活动路由澄清不能把请求送进模型。
5. 使用相同文字但新消息 ID，确认不返回重放提示，走正常新请求授权与活动占用规则。不要求该新请求自动创建任务，也不能仅凭文本去重。
6. 验证未知幂等键和跨租户、跨请求人、跨数字员工、跨服务查找均不能返回 A。无合适账号的活体负例标 NOT RUN，并附本地范围隔离测试；不要冒称通过。
7. 复验发布后修订/否定不自动新建、明确新建恰一条、同一新建消息重放只读返回，以及第三活动同类拒绝。新增测试任务登记，不擅自清理。
8. 恢复 WORK=false / PRODUCTION_MCP=false，核对单实例、双健康与错误增量。失败时关闭 Work、保留 schema 12 新库；不得倒库或改旧合同来制造通过结果。

## 判断边界

- 重放键沿用已有会话范围内创建幂等键，不重算历史 ID、不迁移账本。
- 新的前置重放识别要求存在渠道消息 ID；不使用内容摘要兜底判断“历史消息重放”。缺少 ID 的消息不在本轮重放保证内。
- 回显来自服务端身份核验后的只读查询，每轮清空旧回显；不改变当前活动任务选择。
- 本轮不修复上次误写的 Brief、不放宽授权或内容门禁；裸“同意”的文案错配仍是独立 UX 观察。
