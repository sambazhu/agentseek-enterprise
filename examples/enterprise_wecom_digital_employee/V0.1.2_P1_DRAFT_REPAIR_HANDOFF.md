# P1 一次有反馈初稿修复与 MCP 前置核验

## 前置核对

- 核对 P1 基线 `1f5868f`，schema 12 沿用，不合并 production、不改标签。
- 本轮 F4b 仅覆盖 `generate_report_draft_action` 的确定性生成路径。
  手动 `build_report_draft` 工具仍单次校验，不在内部新增模型调用。
- 第一次原句或相关性拒绝允许一次修复；敏感内容、缺证据、越界引用、
  未知章节、重复 Claim、API/解析失败及合同错误不自动重试。
- 修复输入包含零基失败序号、原因、原提案与同一份 Evidence 上下文。
  首个失败不代表其他项有效，第二次必须重新验证全批；最多两次生成器调用，
  不增加检索轮、不自动外搜。底层 provider 自有网络重试设置不在本补修范围内。
- 修复必须保留提案数量、顺序对应的章节及类型，不允许删事实或降级占位。
  引文和引用 ID 可更正，但必须重新通过原有完整证据与章节守卫。
  再失败就退出，无第三次业务重试，无通过项部分保存。
- 生成后复核当前 Work 和确认提纲是否仍是原快照，变化就停止。
  Evidence 准备仍可能登记记录；“零写入”特指失败校验不新增 Claim/Draft，
  不是整个生成动作从未写 Evidence 或审计。底层存储故障事务语义未扩展。
- 新增 `repair_requested` 脱敏事件；现有 received/拒绝事件继续使用。
  重试内容不写入新增审计字段，生成 metadata 只增加 repair_attempt。
  仍须核验现有 callbacks/trace 脱敏配置，不把模型请求原文复制进日志。

## MCP 兼容核对（先于任何线上 WORK 测试）

1. 保留平台六服务权威，不自行回插 department-knowledge，也不只替换 server 名。
2. 要求平台提供获准的知识库工具 schema 和脱敏返回样例，核对下表。
   当前仓库只展示通用知识查询包装，不足以证明研究接口兼容。

| 合同 | 研究管道要求 | 当前证据 |
| --- | --- | --- |
| 搜索 | knowledge_search，query/search_mode/top_k | production_mcp 仅包装信息技术部检索 query/kbCode；战略知识库 schema 尚缺 |
| 排名 | hits 的 document_id、chunk_id、title、score 及可选 keyword/semantic score | 平台返回结构与分数语义未核验 |
| 回读 | knowledge_read_chunks，chunk_ids，返回 chunks/content | 尚无平台按稳定 chunk ID 回读实证 |
| 来源 | 同一集合、稳定标识、内容摘要及可追溯 Source/Evidence | 不能拿自由文本回答冒充原始 chunk |
| 授权 | tenant/员工/知识域约束与内部检索边界 | 不能仅凭服务名推定与旧服务等价 |

3. 如合同不满足，回报缺项及适配建议，停在线上研究入口；不伪造分数、ID 或证据。
   可继续本地固定 Evidence 的 F4b 测试，不将其标记为平台端到端通过。
4. skill-mcp 同步模块的原子配置写入、失败返回状态、异常日志脱敏、非空技能更新
   与模板接入另列审查项。本次只核对，不顺带修改平台同步模块或供应商 SDK。
   F4b 三个代码文件已同步模板；既有 agent.py 平台接入未同步的差异仍保留。

## 复测步骤

1. 先核对完整 SHA 和基线祖先，普通同步 P1 到 GitLab；不修改部署配置。
2. 本地复跑新用例：首次成功只调一次；修复成功最多两次且保存一份；第二次
   仍失败零 Claim/Draft；删除或降级提案拒绝；缺证据与首次 API 失败不重试；
   修复 API 失败不继续；提纲变化停止；成功重放不调用模型或 MCP。
3. 平台合同确认后，回报接入方案、资料集合及测试窗口，等待用户批准部署全链。
   p1-acc3-a 与 acc3-a 清理仍待精确授权，不导入、不删除、不启生产开关。
4. 获准全链时，以新隔离任务验证真实改写拒绝→一次修复→整批通过或明确失败。
   对照六问缺口，逐条人工复核事实原句及问题相关性；不以 Claim 数量判质量。
5. 保持单实例、可恢复方案和诊断脱敏。Langfuse 仅 events-only，不调用任何读取 API。
6. 结束按获准范围恢复开关、运行路径和 MCP，核对双健康与错误增量；历史保留。
