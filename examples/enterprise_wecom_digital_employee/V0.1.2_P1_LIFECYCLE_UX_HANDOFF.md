# P1 生命周期与初稿协议 Linux 复测交接

仅用于独立 P1 分支受控试运行，不是合并或正式发布授权。
本轮部署 SHA 以分发回执中的完整代码提交及远端核对为准，基线为 `0c4060f`。
先阅读 [本地验证记录](V0.1.2_P1_LIFECYCLE_UX_LOCAL_RESULTS.md)，不要重复旧内容清理。

## 部署前置

1. 核对分支祖先包含 `0c4060f`，GitHub/GitLab 普通推送后完整 SHA 一致；保留 production 和两个标签。
2. 在独立干净工作树操作，记录试运行前模型、开关、PID、双通道健康和错误基线；不得回显密钥或账号。
3. **本轮新增 schema 11→12，不再适用上一工单“无新迁移”的判断。** 先盘点数据库版本、活动索引和范围内任务；任何不符先停止。
4. 在停写窗口取得可恢复的一致性数据库备份，并验证备份可读；协调唯一实例停写，禁止迁移与旧版本 Work 写入并行。
5. 使用本分支 `agentseek_work.migrations.apply_migrations` 显式迁移。revision 12 只调整索引：published / delivered 不再占活动名额，历史行不变。记录迁移前后行数与摘要、索引定义、版本和退出结果。
6. 试运行必须同时加载本分支的 `contrib/agentseek-work/src` 和示例源码；核验 repository、migrations、draft_generation 实际加载路径及 schema 常量 12。只覆盖示例 PYTHONPATH 不足以部署此修复。
7. 保持当前 DashScope 模型及 MCP 配置，不换端点、不改权限；按受控窗口启用 WORK。生产 MCP 无必要不启用，仍遵守单实例。

以上为 Linux 待执行步骤，Mac 仅验证了本地 SQLite 11→12 升级与幂等，不代表已完成生产迁移。

## 复测顺序

1. **新建与历史名额。** 使用全新标记任务，不复用 P1REG 修改 Brief。发布后在未启用 signed_link 的条件下新建同类任务，确认旧任务仍 published，新任务独立 work_id；第三个活动同类任务仍拒绝，原创建消息重放不多建任务。
2. **发布后冻结。** 对旧任务尝试取消、修订 Brief / Draft 和新增内容记录，均拒绝；取消提示不再提供不可用操作。盘点旧合同、sources、evidence、claims、审批、artifact、publication 不变。不得为测试直接改生产任务状态。
3. **本人历史访问。** 发送“查看已发布报告 <任务编号>”，确认读取旧任务且不改变当前新任务。跨请求人、跨租户及未知编号统一拒绝；不得泄漏账号或他人报告。
4. **历史交付。** 严格命令为“交付已发布报告 <任务编号> ReportArtifact v<版本> 给我”。交付未配置时拒绝；不得为此擅自启用 signed_link。已获配置授权时补验：新任务存在仍可交付旧版本，旧任务变 delivered，不重新占名额；错版本、非本人和非明确命令拒绝，原摘要与一次性下载校验保留。未配置的下载正例标 BLOCKED，不得冒称通过。
5. **初稿协议。** 使用经授权的反例与相关正例。反例仍零不相关绑定、coverage 0/6，初稿阶段模型调用为 0，所有章节为程序声明。正例仅绑定相应问题；记录模型调用、拒绝/成功次数、facts 的完整原句和 Evidence 引用，缺章节或空 claims 不再要求模型补写章节。空稿是待确认稿，不得计为内容验收通过。
6. **守卫与 UX。** 数字、否定、半句、未知证据、未绑定事实仍整体拒绝且无部分 Claim 新增；风险类型不得成为自由事实绕行。验证中文研究问题、拒绝原因及下一步指引，Draft v999 与 WORK off 三层介绍不退化。无法可靠活体诱导的负例如实标 NOT RUN，并列离线证据。
7. **收尾。** 恢复 WORK=false / PRODUCTION_MCP=false，保留原模型和单实例健康；登记新增测试任务与资料，不删除任何 P1REG/P1CF-POS 数据。回传完整 SHA、实际加载路径、迁移证据、逐项结果、残留账本和错误增量。

## 停止与回退

- 获取不到代码、SHA 不一致、备份不可用、迁移失败、模块仍加载旧包、出现越权或无关事实绑定，立即停止试运行并恢复关闭开关；禁止使用旧 production 替代新代码继续测。
- **不能直接用旧代码搭配 schema 12 重启 Work。** 新版已允许发布历史与新任务并存，旧索引可能无法重建，旧版本也不认识 schema 12。
- 尚无新写入时，可在明确停写且核对范围后按已验证方案恢复迁移前备份与配套代码。
- 已发生新写入时，不自动倒库、不删除任务凑旧唯一约束；保留新数据库，关闭 Work，回传新增写入范围并等待恢复方案授权。
- 不合并 production、不移动 GA/hotfix1、不启用 M3，不把本轮通过等同于内容完整性结案。MCP 后端补测按用户另行安排的窗口执行。
