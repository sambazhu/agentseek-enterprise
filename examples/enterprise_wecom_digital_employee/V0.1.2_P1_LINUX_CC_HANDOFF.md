# v0.1.2 P1 修复复测交接

在代码完成评审、分发且取得 Linux 测试窗口后使用本指南。
本次仅完成本地实现及离线验证；本文件不是生产部署或手机验证授权。
本地测试记录见 [P1 本地验证结果](V0.1.2_P1_LOCAL_RESULTS.md)。

## 前置核对

- 实现分支：`enterprise/v0.1.2-p1-workflow`。
- 起点：`4f7cf7f10b2633dd9e6ac2782d8c6b191d635c6c`。
- 新任务使用 pack `1.14.0`、profile `1.13.0`、intake skill `1.2.0`、writing skill `1.6.0`；摘要已同步。
- 独立工作树：`/tmp/agentseek-p1.hNI50N`。分发前需记录最终提交 SHA；当前不应按分支名假定远端已有代码。
- 不修改 M3、现有用户定制或 P0 证据；不移动 GA / hotfix1 标签。
- 保留已有 WORK schema，不自动重做迁移。测试前只读确认版本和表结构。
- 默认仍为 `AGENTSEEK_WORK_ENABLED=false`，新增业务适配器默认关闭。
- 真实 DeepSeek、生产 MCP、PostgreSQL 及手机链路均未在本次本地验证中执行。

## 复测步骤

### 1. 验证身份与日常问答

先在 WORK 关闭状态，分别询问“你是谁”“你能做什么”“怎么使用你”“我是谁”。
前三问应由岗位配置确定性回答；第四问只使用已解析员工姓名和组织，不返回 OA 账号。
正式工作流关闭时，不应宣称正式服务已启用，也不应创建任务或调用模型。
缺少员工身份时，“我是谁”应说明无法完整识别，不猜测身份。

开启 WORK 后重复上述问句，并核验普通问答不创建 WorkItem。
Direct Turn 的一般问答仍使用 `create_deep_agent` 构建的模型/工具循环；
身份、能力、部分状态与明确取消等确定性分支绕过该循环。

### 2. 验证路由与取消

在一个属于当前员工的测试任务中发送：

- “面向董事会，覆盖今年”“请把第二节缩短”“重点放在经纪业务”。
- 需求修改与解释组成的组合问句，以及原 D10 防泄漏探针。
- “我是谁”“查一下我的报销进度”等独立日常问题。

前两类应进入当前任务对话，不再被空白 NO_MATCH 列表吞掉；
日常身份/OA 问题应走 Direct Turn。路由选中不等于批准状态变更。
多个候选服务必须显示非空候选列表；不得用优先级替代用户选择。

发送“取消当前报告任务”：应由已认证委派人取消自己的当前任务，保留历史。
重复取消且没有新任务时，应返回无可取消任务，不追加取消事件。
他人、其他租户、否定句、引号转述和“取消当前任务？”均不得触发取消。
原 D+F 遗留 WorkItem 先核实归属及用户处置意图；本次没有删除或取消该生产记录。

### 3. 验证简化报告路径与 DeepSeek

使用新建测试任务，避免将旧任务冻结的 pack 快照视为已更新。
提交需求后，检查助手汇总询问缺失信息、复用当前对话中已明确的事实，
保存并展示真实 ReportBrief 版本，不虚构写入或授权。

对展示的当前版本发送“确认 ReportBrief vN 并自动研究生成初稿”。
已单独确认需求时，也可发送“按已确认需求自动研究并生成初稿”。

1. 需求版本检查先于检索。伪造 v999 必须零 MCP、零模型调用。
2. 内部检索有未解决缺口时暂停，并给出版本绑定的缺口处理选项。
3. 自动推进本身不调用 Tavily / Gildata。外部来源仍须单独明确授权。
4. 资料允许继续后，内部检索、来源绑定提纲和可审阅初稿可连续执行。
5. 自动接受新提纲时，检查 `report-draft-execution` 合同绑定 Brief / Outline 版本，
   外部搜索和审批/发布/交付授权标志均为 false。
6. DeepSeek 请求采用 `function_calling`，不发送 `response_format=json_schema`。
   离线 HTTP Mock 已覆盖实际 ChatOpenAI 请求结构和非法输出拒绝；真实端点仍需本步骤验收。
7. 初稿引用、Evidence / Claim 及输出 guard 仍需通过原 D5/D6 检查。
   模型失败或结构化结果不合法时不得保存 ReportDraft。
8. 重复自动初稿请求应返回同一当前初稿，不重复调用生成模型。

保留原逐版本手动路径。分别回归旧的 Outline 确认后停轮行为和新的显式自动路径。
“确认”“好的”不授予自动执行权。

用户体验按“确认需求 → 审阅初稿 → 审批交付”三个阶段说明，
但本次没有合并最终审批、DOCX 渲染、发布或交付授权。
原 D5 后半段应依次复测；初稿通过不代表整条交付链通过。

### 4. 验证生产 MCP 业务入口

仅在批准的测试配置中启用 `AGENTSEEK_PRODUCTION_MCP_ENABLED=true`。
复用 Linux 已有 MCP 连接和凭据，不复制同事工程的生产账号、配置或日志。

- OA 服务名：`OA流程助手`。工具：`describe_oa_query`、`query_my_oa`。
- 知识库服务名：`信息技术部知识库`。工具：`search_it_policy`。
- 制度与外规集合分别由 `AGENTSEEK_IT_POLICY_KB_CODE`、
  `AGENTSEEK_IT_REGULATION_KB_CODE` 配置；空值不发起对应查询。

先只读比对真实工具 schema，再进行本人最小范围查询。
OA 先验证私聊及员工状态账号与运行时脱敏 user_key 一致，
再按远端 schema 的 `oa_account` / `login_name` 字段注入账号。
账号不能由模型或用户参数改为他人；未知身份、群聊个人查询、身份键不一致必须在连接前拒绝。
远端缺少可绑定身份字段、未知参数、缺少必填字段或不支持的类型时，不执行查询。
当前适配器验证标量参数；复杂/联合 schema 需要额外适配，不允许临场绕过校验。

会议、最近报销、考勤与人员信息只做读取；会议室安排为单独查询。
报销流程明细仅凭 flow_id 不足以证明归属，因此保持关闭。
OA 审计不记录账号参数、个人结果或原始接口异常正文。
适配器仍服从原 MCP policy；不得为通过测试关闭策略。

知识检索应使用固定集合映射，并展示来源和覆盖限制。
普通知识问答可与活动任务并存；正式报告不暴露这些直接业务工具，继续通过工作流登记证据。
本次没有将同事生产知识库直接桥接为报告 SourceRecord，不能据此宣称已完成报告数据源替换。

## 停止条件与恢复

- 发现越权、账号可伪造、群聊个人信息泄漏、外部检索绕过授权：立即停止。
- 发现写入数异常、旧任务快照被改写、标签或非目标工作树变化：立即停止。
- 真实 MCP schema 与适配器契约不一致：保留失败证据，关闭新增适配器，不放宽校验。
- 测试结束按已批准的窗口恢复 WORK 和 MCP 功能开关；不通过删除数据库恢复。
- 遗留测试任务登记后按用户明确意图取消，历史记录保留；不运行 P0/D5 清理脚本。

## 回传要求

回传完整代码 SHA、配置开关（不含密钥）、逐项结果、模型/MCP 调用计数、
新增任务数量与状态、失败阶段、网关健康和错误增量。
真实环境未执行的项目标记 BLOCKED / NOT RUN，不填写 PASS。
复测完成后再决定 P1 发布与 production 双端同步；M3、D7/D8/E 仍按用户原决策执行。
