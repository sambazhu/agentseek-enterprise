# P1 外采 MCP 客户端兼容复测

## 前置范围

- 本轮只适配客户端，不修改外采服务端、报告生成、schema 12 或生产配置。
- 基线 ab97bbe；实际补丁提交 SHA 由交付时补充核对。本地文件不等于远端可获取。
- 保留原 MCP policy、确认链和员工身份绑定。OA 兼容别名为 OA流程助手、znsh；
  policy 仍按实际配置名判定，不自动扩权。业务 query_my_oa 工具仍用原服务名。
- 知识库兼容名为信息技术部知识库、战略发展部知识库、人力资源知识库及四个已登记库 ID。
  其他别名不自动按 URL 猜测，现场名称不一致时先回传映射。
- 本地测试 652 passed / 1 skipped，含 example/work/skill-mcp/模板渲染。
  未调用真实 MCP、模型、Linux 或 Langfuse；服务端可用性待现场验证。
- 锁文件检查如实：uv lock --check --offline 未通过，离线重算发现既有本地
  agentseek/agentseek-wecom 元数据与锁文件漂移。本轮撤回重算引入的无关差异，
  仅登记已有 jsonschema 为直接依赖。Linux 安装前须核对该漂移，不能宣称 frozen
  安装已通过；不要为本补丁擅自升级 DeepAgents 或其他模型 SDK。

## 复测步骤

1. 核对补丁版本和运行加载路径，在独立工作树验证依赖 jsonschema 可用。
   example 与模板已显式声明依赖；锁文件复用已有 jsonschema 版本，不升级供应商 SDK。
2. 只读获取实际 tools/list，核对服务名、工具名、properties、required 和 default。
   不把完整凭据、账号或原始内部响应入库。记录名称和 schema 摘要即可。
3. 检查 OA 最近费用报销工具：仅当 properties 有 oa_account 而无 login_name，
   客户端才把该工具的 required 中 login_name 替换为 oa_account；保留其他必填项。
   模型可见发现参数隐藏账户字段，实际调用由可信运行时注入本人账号。
   省略或 null 的 top_count 使用声明默认值；未声明默认值时沿用 3，上限仍为 20。
4. 在批准窗口测 OA 本人查询，确认出站参数不是空参；他人账号、未解析身份、群聊拒绝。
   服务端若继续按错误 required 校验，记录外部阻塞，不增发虚构 login_name 绕过。
   不调用审批或业务写操作；不打印账户值验证身份绑定。
5. 逐一测四个知识库工具。省略 kbCode 时，客户端取该工具 schema 的 default，
   并核对它属于已登记的该服务库集合；调用方不能改为别的库。
   其他顶层默认字段显式补齐（含对象型 default），保留已提供有效参数。
   required/type/范围按 JSON Schema 校验；缺省未声明的业务参数不猜测。
   不递归虚构未声明默认值的嵌套对象，未知参数拒绝。
6. 若正确参数仍返回 kbIndexCode不存在 或 MCP isError，记为后端失败，
   不当作无资料、不转查其他库。战略库索引缺失继续留档，不能宣称客户端已修复。
7. 核对 tavily 真实凭据位置及平台同步后的行为；按下一节选择是否使用本地覆盖。
   没有可信可用凭据或传递位置未核实时，标 BLOCKED，不从历史文件搜集密钥。
8. 结束核对同步、运行路径、原开关、单实例和健康。WORK 不需要为本轮开启。
   配置变更与部署窗口先报方案获确认；production/标签/测试资料不动。

## 可选本地凭据覆盖

1. 仅在平台无法持久保存正确配置、且真实认证位置已核验时启用。
2. 设置 AGENTSEEK_MCP_LOCAL_OVERRIDES 指向运维维护的受限 JSON 文件。
   顶层键必须与配置中的 server_name 完全一致；不创建新服务、不替换 URL。
3. 每个服务可声明 headers_from_env 或 env_from_env，值是“目标字段名→环境变量名”。
   headers_from_env 用于 HTTP 请求头；env_from_env 仅适用于本地 stdio 子进程。
   环境变量包含完整目标值，包括需要的认证前缀；文件只存变量名，不存密钥。
4. 该覆盖在 _read_mcp_servers 读取时应用，不回写平台同步文件。
   未配置时完全沿用平台；启用后若引用缺失或配置无效则报错，不静默用占位值。
5. 测“同步前调用→平台再次同步→同步后调用”，确认覆盖仍生效且平台原文件未被本层修改。
   本地自动化仅模拟配置被重写；真实平台同步和 tavily 调用仍需 Linux 实测。
6. 若 tavily key 位于远端服务内部、URL 查询参数或工具参数，本入口不覆盖该位置。
   回传实际合同再决定适配，不能把请求头覆盖成功等同于 tavily 已修复。
7. 恢复时撤销该环境变量及本轮专用环境配置，回到事前配置；不要删除公共凭据。
   此功能不修改 skill-mcp 同步器，也不解决其磁盘写入失败或 URL 持久化问题。

## 回传判定

| 项目 | 通过证据 | 未通过时 |
| --- | --- | --- |
| OA 兼容 | 本人查询真实成功，出站字段/默认值正确，原身份与审计边界保持 | 客户端与服务端拒绝分开记录 |
| 知识库默认值 | 四工具分别记录参数补齐与真实结果；无需四库都可用才确认补参机制 | 战略库正确传参后索引失败独立 BLOCKED |
| tavily | 认证位置核对，平台再次同步后真实调用成功 | 仅本地覆盖机制通过不记活体 PASS |
| kbCode 限制 | 工具按自身声明默认库调用，改库请求不发远程调用 | 不宣称服务端越权漏洞消除 |
| 恢复 | 原开关、同步和路径恢复，健康及错误增量可解释 | 不合并 production，回传异常 |

内容样例验收与本 MCP 复测分开记录；原业务审批能力不受影响。
