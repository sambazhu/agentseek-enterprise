# MCP 三层配置 Linux 受控验证工单

## 前置与范围

本工单只验证 P1 MCP 配置拆分。基线 `30eab69`，候选完整 SHA 以交付回传为准。
先核验两远端 P1 分支、候选祖先关系和精确差异；不移动 production 或标签。
沿用现有模型、SDK、数据库、mcp_compat 和本地业务定制；无依赖或锁文件变更。
CubeSandbox/M3 不属于本工单。

## 1. 备份并迁移配置

1. 在受控停机窗口私下备份旧运行配置、旧同步路径文件及 .env；目录 0700、文件 0600。
   登记恢复位置，不在终端、日志或提交中打印配置正文或 key。
2. 注意候选解除 `.agents/mcp.json` 的 Git 跟踪。更新前必须备份该文件；
   Git 更新可能删除旧跟踪文件，不能把“解除跟踪”当作跨主机自动保留保证。
3. 将旧混合配置中的平台服务保存为 `.agents/mcp.dmcp.json`，供首轮同步失败时保底。
   不将旧混合文件原封不动作为新的 local：否则旧平台条目会永久覆盖后续同步。
   平台条目与本地条目无法判定时停止迁移并回报，不猜测。
4. 首轮将 `.agents/mcp.local.json` 设置为 `{"mcpServers": {}}`。
   需要长期保留的本地条目另从备份选取，后续按验证步骤加入。
5. 设置 `AGENTSEEK_SKILL_MCP_MCP_JSON_PATH=.agents/mcp.dmcp.json`，
   `AGENTSEEK_MCP_CONFIG_PATH=.agents/mcp.json`。相对路径均按 example 项目根目录解析。
   local 固定为该项目的 `.agents/mcp.local.json`。三个路径必须不同。
6. 确保三个配置文件为 0600。`mcp.platform.json` 不参与读取或合并，不自动清理。

## 2. 核对加载合同

1. 核对首次 build_agent 的同步尝试发生在合并之前，合并发生在 MCP 工具读取之前。
   同步结果仍每进程缓存一次；每次 build_agent 可重新合并，不增加平台重试。
2. 核对同名 server 的 local **整条替换**平台条目，不做字段深合并。
   local 的 `null` 删除对应平台条目；它不是传给 FastMCP 的 server 配置。
3. 核对同步失败沿用缓存；缓存缺失时仅用 local 并警告；local 缺失或空文件仅用缓存。
   local 损坏或结构非法时整层忽略并警告，不导致网关启动异常。
4. 核对合并输出只有 `mcpServers`，不变换条目内部字段；mcp_compat 仍在加载后处理。
5. 核对日志只出现层状态和 dmcp/local/覆盖/实际屏蔽计数，无 server 正文、账号或 key。
   原子写失败保留旧产物并报错；这属于本轮验证失败，不能当作新配置已生效。
6. 旧环境若仍把同步路径指向 local/effective，程序跳过同步并提示路径碰撞；
   此保护不是自动迁移成功，必须修正路径再重启。

## 3. 离线复跑与受控验证

1. 使用独立 P1 工作树和已有环境离线复跑 examples 全套与 skill-mcp 全套。
   PYTHONPATH 的 examples 和全部 contrib/src 必须来自同一 P1 工作树；
   使用 Git 版本 profile，不以生产 itdept 定制作为样例测试基准。
   缺依赖先停止报告，不联网升级或改锁文件。
2. 部署候选代码并重启单实例，保持 WORK=false。确认源码路径包含新的合并模块、
   agent 接线和 skill-mcp 原子写实现；双健康正常。
3. local 为空时确认缓存生成、生效为平台 6 服务。数量变化先与平台下发核对，不能伪造六条。
4. 将备份中的 department-knowledge 整条配置加入 local，绑定已批准的测试 collection；
   重启后确认生效为 7 服务，平台同步保持开启；OA 本人、IT、HR、tavily 四项冒烟不回归。
5. 在批准窗口临时设置平台不可达并重启；确认旧 dmcp 缓存及 local 均保留，
   合并仍包含上述服务。恢复平台可达后再重启，确认一次同步与覆盖规则仍成立。
6. 仅在用户批准的 WORK 研究窗口短时启用 WORK，确认本地研究工具可用且无需关闭同步。
   外搜确认门不改变；本步骤需用户窗口，没有窗口记 NOT_RUN。
7. 可用独立测试配置验证同名整条覆盖、null 屏蔽和损坏 local 降级；不要篡改真实凭据制造异常。
8. 收尾恢复 WORK=false、平台可达、单实例和批准的 local 内容；登记配置权限、
   三文件 Git ignored 且未跟踪、错误增量及测试数据。默认不清理历史任务或知识库。

## 4. 回退与回传

1. 任一步异常先停止后续验证。保留诊断计数，不打印配置正文。
2. 停网关，切回已记录的原运行代码与定制文件，恢复旧 .env 与旧混合配置备份；
   不能只回退代码却保留新路径布局。恢复后按既有标准命令重启并核验单实例、双健康。
3. 不回退数据库（本次无迁移），不 force、不改标签、不清理 M3 工作区。
4. 回传候选/部署完整 SHA、源码加载路径、离线计数、平台成功及失败场景计数、
   文件权限与忽略状态、冒烟结论、WORK 窗口结果、恢复终态和 NOT_RUN。
