# MCP 同步失败冷却重试复验

## 范围

基线 b35d0c9；仅 P1 候选受控复验，不授权 production 合并、重启风暴或平台修复。
沿用三层配置、标准脚本、绝对 runtime 路径。WORK=false，无依赖/SDK/DB 改动。
此前每进程一次同步合同在本补丁中明确修订为以下规则。

## 1. 核对规则

1. 每进程最多三次同步尝试（首次加两次重试）；失败完成后以单调钟冷却 60 秒。
2. 冷却后仅由后续 build_agent 触发，不后台调度、不 sleep、不自动重启。
   已缓存 graph 的普通后续消息可能不调用 build_agent，不能据此宣称重试未生效。
3. 并发 builder 不等待正在进行的同步，使用现有缓存合并；仅一方发起平台调用。
4. 取得配置并成功写入 MCP 缓存后缓存成功结果；失败、配置为 None、
   MCP 转换/写入失败或路径碰撞不缓存成功。禁用/SDK 缺失也受相同次数上限约束。
5. 达上限后维持缓存降级，本进程不再尝试。不得为凑成功自动循环重启。
6. 同步重试会再次尝试 skills 导出；不是只重试 MySQL 或单个 MCP 请求。
   skills 导出原有优雅降级不变，MCP 成功不代表每个 skill 导出均成功。
7. dmcp/local 继续保底；缓存写失败现在返回失败标识，不再把转换结果当作写入成功。
   日志只含固定状态、次数和冷却值，不打印异常正文/凭据。

## 2. Linux 复验

1. 核验候选完整 SHA、双远端一致、差异和备份；独立候选环境复跑离线测试。
2. 按标准脚本受控启动一个实例，确认 agent 与 loader 同属候选树；
   不动现有 SDK、临时路径或三层配置合同。
3. 在批准的故障注入窗口使首轮平台加载失败，确认旧缓存与 local 完整、七服务仍生效。
   冷却内再次 build_agent 不新增同步尝试；必须记录实际 build_agent 触发证据。
4. 恢复平台，60 秒后在同进程触发新的 build_agent，确认尝试次数增加。
   若无法通过正常路径构造新的 build_agent，使用独立协议层驱动验证并标注方法，
   不把重启后的首次同步算为同进程重试，也不为测试添加运行时管理接口。
5. 取得成功后再次 build_agent 不再拉取；同一终态实例验证七服务、四项冒烟和双健康。
6. 三次均失败的上限及并发去重可沿用离线用例；活体未测标 NOT_RUN。
   平台始终失败时记 BLOCKED，不归因于多副本而无平台证据。

## 3. 回退与回传

1. 异常时停候选，恢复 b35d0c9 的生产脚本、模块路径、.env 和服务配置，
   去除候选 overlay；配置文件无格式迁移，不删除缓存或 local。
2. 回退恢复每进程一次语义，必须如实披露；不回退 DB、不清理语料或任务、不动标签。
3. 回传候选、实例标识、每次尝试时间/次数、build_agent 触发证据、缓存完整性、
   同实例冒烟、恢复状态与 NOT_RUN。正式发布另批。

新增用例覆盖失败冷却、成功缓存、三次上限和并发不重复；时钟和平台为替身。
