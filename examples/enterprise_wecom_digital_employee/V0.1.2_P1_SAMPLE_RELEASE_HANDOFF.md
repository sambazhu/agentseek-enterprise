# v0.1.2 P1 样例模板发布准备交接

## 适用范围

用本交接单准备样例模板发布，不执行发布。
先阅读同目录 `V0.1.2_P1_SAMPLE_ACCEPTANCE.md` 的用户裁定与限制。
人工业务审核已按用户决定跳过，不再索要评审人、逐句签字或新一轮业务测试。
不删除模板审批能力，不改变证据守卫、用途规则和既有账本状态。

## 当前可执行步骤：只读准备

1. 核对 GitHub/GitLab P1 分支完整 SHA、共同基线与待发布文件差异。
   本轮实测代码为 ab4698c，Linux 报告为 ab97bbe；后续文档提交单列。
   如发现未纳入验收的新代码或差异，列出并停止发布准备的完成判定。
2. 只读登记当前 production、GA/hotfix1 标签、运行代码路径及 schema 版本。
   分别记录 Git HEAD 和实际加载代码，不将 P1 分支存在等同于已部署。
3. 核对 WORK、平台 MCP 同步、健康与单实例状态，不改配置、不输出密钥。
   不为本次文档收口调用模型、MCP 业务工具或 Langfuse 读取 API。
4. 登记 P1ACC5 历史任务与 p1-acc4-a/acc4-a 保留情况。
   不恢复任务、不审批、不发布报告、不删除资料或备份。
5. 回传限定用途发布准备清单：候选 SHA、差异范围、配置兼容性、
   已验证与 NOT RUN 项、已知限制、发布和回退方案、待用户批准动作。

## 用户另行批准后才执行

1. 明确批准的提交、目标 production 分支、部署范围与测试窗口。
   默认建议仅做样例代码归并，WORK 保持关闭；启用能力单独授权。
2. 检查 schema 12 与运行依赖兼容，并保留本地定制。
   不把 schema 11 旧备份直接恢复到已有新写入的生产库。
   带背景绑定的新提纲不保证旧代码可读；回退优先关闭 WORK、保留账本。
3. 仅在批准范围执行普通合并/推送与受控部署；不强推、不移动旧标签。
   任何新发布标签须单独明确名称及授权。
4. 按批准窗口核对最终加载版本、关闭开关时的入口行为、单实例及健康。
   冒烟话术及是否调用模型提前列明，不擅自开启报告、外搜或交付。
5. 回传最终 SHA、部署前后状态、验证结果与恢复记录。
   使用“样例模板工程验收通过”的限定口径，不写“业务报告质量已验收”。

## 停止与回传

- 双端版本、实际加载或配置不一致时，回传差异，不用旧代码冒充候选版本。
- 需要新增迁移、平台 KB 适配或修复新代码时，另立范围，不混入 docs-only 收口。
- 清理测试集合、目录、历史任务或备份，须另获精确对象与范围授权。
- 人工业务审核跳过不改变既有 NOT RUN；不为了制造活体错误而追加生成调用。
- 当前完成标志是发布准备信息齐全；正式发布仍等待用户明确批准。
