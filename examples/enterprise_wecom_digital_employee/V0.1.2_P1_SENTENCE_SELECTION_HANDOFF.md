# P1 证据句 ID 选择式生成复测

## 前置核对

- 核对 P1 基线 `d9e99f7`，协议 `evidence-sentence-selection-v1`。
- 本轮只改确定性初稿生成、全批错误反馈及模板镜像，不改生产配置、MCP、
  schema 12、profile/pack、检索策略或用途规则。不重导、不清理、不部署生产。
- 手动 build_report_draft 工具仍接受原有 Claim 参数并严格校验，不自动调用模型。
  确定性 generate_draft_claims 改为 SentenceSelectionBatch，不再接受模型引文正文。
  原内部 DraftClaimBatch 已移除；外部如有自定义导入需同步，不回退接受旧输出。
- 沿用背景提纲兼容边界：新版可读旧提纲，旧代码不保证可读带背景绑定的新提纲。
  新候选表只在当前生成上下文存在，不新增数据库合同或持久化候选原文日志。

## 核对生成流程

1. 程序从已登记 Evidence 摘录中提取源句，运行完整句、敏感内容及用途检查。
   仅提供该 Evidence 与章节实际绑定问题的可用句，不从新来源补事实。
   截断摘录末尾仍受既有原句规则局限约束；不是完整文档语义核验。
2. 候选含 sentence_id、statement、evidence_id、section_uses。
   ID 绑定任务、Brief/Outline 版本、Evidence ID、摘录内容、原句及允许用途。
   同一上下文重复构造稳定，跨任务/版本/内容不可复用；ID 本身不是授权凭据。
3. 每个候选原句最多1600字符；候选上限120条，按 Evidence 轮流取句。
   不增加检索轮；超上限会截选，不能宣称全部正文都进入候选。
   原有 Evidence 上下文仍发送给模型，因此输入 token 不保证下降。
4. 模型仍通过 function_calling 返回结构化 selections，每项仅 sentence_id/section_id。
   不允许 statement、claim_type 或 evidence_ids。程序从候选原样组装 fact Claim。
   Pydantic 原有空白归一化仍在，不承诺字节级保留排版；数字、否定和限定词不改写。
5. 选择校验一次返回每条失败选择的原因：未知 ID、章节不允许、重复选择，
   修复阶段另检查总条数不得减少或增加。选择错章节可修正为候选允许章节。
   任一失败不返回通过项，不产生部分 Claim。
6. 整个确定性动作最多两次生成器调用，选择修复与账本修复共用此预算。
   首轮选择失败可用完整失败列表重试一次；二次仍错或删选择则干净退出。
   API/schema 解析失败不新增业务重试；底层 provider 网络重试设置不变。
7. 组装后照常执行账本全批校验。每个失败 Claim 收集首个原因与索引后统一拒绝，
   不再只反馈第一个失败 Claim；敏感内容、超量等批次前置仍立即拒绝。
   存在任一越界/缺证据等不可重试原因时，不因其他可修复错误而触发重试。
   两次校验都在 Claim 写入前；底层存储失败事务语义不在本轮扩展。
8. 生成前后复核任务与确认提纲快照；变化即停止。背景/公司案例标签与缺口保留，
   全批保存合同不变。已有初稿命中幂等路径时不再次生成或检索。

## 诊断与本地验证

- 新 reason_code：selection_repair_requested、selection_rejected。
  同一 report.draft_validation 事件含 selection_count 和失败索引/原因列表；
  此时 proposal_count=0 表示还未组装 Claim，不应解读为模型未返回选择。
- 模型运行 metadata 含 selection_version、candidate_count、repair_attempt。
  选择反馈仅在生成上下文；不把候选原文、完整工具参数或异常正文写入新增审计字段。
  现有 callbacks 的脱敏边界仍需核验；Langfuse 沿用 events-only，不调用读取 API。
- 本地 example + work + skill-mcp + 全量模板渲染：641 passed / 1 skipped；
  修改 Python 文件 Ruff 与 git diff --check 通过。
- 七句合成证据：一次选择保存7 fact、两错误一次修复成功、二次错误/删条零保存、
  成功重放零生成与零新增检索。另有跨版本ID、禁止模型正文、噪声候选过滤、
  上限与多 Evidence 分配、背景/公司用途、逐 Claim 错误汇总用例。
- 未调用真实模型、Linux MCP 或 Langfuse；合成七句成功不能等同真实材料成功率。

## Linux 复测步骤

1. 只读核对完整提交 SHA、基线祖先与独立工作树，普通镜像 P1 分支到 GitLab。
   production/标签不动，不覆盖本地定制。
2. 回报当前 acc4 测试集合/目录是否仍保留、本轮拟用任务与窗口。
   未经本轮确认不重导、不启 WORK、不清理；历史原件及任务继续保留。
3. 按用户选择使用本地研究资料，单独确认 department-knowledge 测试入口与平台
   同步恢复方案。不以外采平台 KB 替换研究接口，不混入 OA/IT 参数适配工作。
4. 先用固定 Evidence 离线构造候选表，记录各章节直接/背景/公司候选数及截选情况。
   候选为零需报告原因，不把零模型调用后的占位初稿判为业务成功。
5. 获准后用新隔离任务全链，确认模型输出只有 ID/章节，程序 Claim 原句可追溯。
   验证首次选择保存、错误选择有反馈且最多两次、二次失败零 Claim/Draft；
   未取得真实修复成功样本就标 NOT RUN，不用离线用例冒充活体覆盖。
6. 人工逐条确认事实及用途标签；背景不关闭问题缺口，原句引用正确不等于事实真实。
   分别记录候选数、选择数、事实/背景数量、六问缺口、调用数、首过与修复结果。
7. 结束恢复批准的运行路径、开关与平台同步，核对单实例、双健康、错误增量。
   清理和 production 发布另行决定；有新版背景提纲时回退优先关闭 WORK 并保留账本。
