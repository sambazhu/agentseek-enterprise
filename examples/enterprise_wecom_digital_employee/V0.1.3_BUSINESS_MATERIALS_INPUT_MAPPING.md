# 现场参数到禁用业务材料的映射

## 三层文件的区别

| 文件 | 来源/作用 |
| --- | --- |
| parameters.json | 安装方受控填写的14个必需字段，可另加布尔diagnostics_enabled；不含凭据正文，不手写10份documents |
| input.json | 本轮转换器生成的6字段编译输入：schema/sources/identity_files/directories/documents/output_directory |
| service.json | 最终16件之一，schema2精确12字段；不是前两层的输入 |

本轮补交选项C（转换脚本）及B（本映射）。不从service.json猜出缺失的W0、pins、创建批准或模板信息。
禁用输出不产生窗口、创建授权、服务启动或额度重置。

## 参数根字段（14个必需项，可选诊断开关）

| 字段 | 类型/来源 | 自动写入 |
| --- | --- | --- |
| schema | 整数1，参数格式版本 | 不等于service的schema2 |
| output_directory | .172已审的新材料目录，必须不存在 | 16件输出位置 |
| sources | 下表6项 `{path,sha256}`；对象不是数组 | 6件受控源资产物化及引用 |
| identity_files | 下表3项 `{path,sha256}` | 原监督身份文件引用，不复制 |
| directories | 下表8项已存在目录 | 各运行目录引用，不创建/清空 |
| create | 下表7项创建计划参数 | request/approval/precreate/installation/session |
| second_plan | 精确 `{create_token,request_sha256}`，安装方登记的第二结构计划 | batch_sequence第二项，无B批准或执行入口 |
| window | 精确12字段W0待审记录，accepted=false/revoked=false | window、exclusive_window、expires |
| supervisor_identity | 实际8字段pins记录 | precreate/session；先与identity_files逐项核对 |
| template_pins | 精确 `{template_id,node_ip,artifact_id,artifact_sha256}`，既有模板取证 | precreate.template_pins |
| request | 精确 `{request_id,owner_id,input_ref,instruction}`，.171可信上传与请求绑定 | permits及service plans |
| input_sha256 | .171实际上传CSV的完整摘要 | session/permit，不从input_ref截断值还原 |
| instruction_sha256 | 固定问题UTF-8原字节摘要 | 与instruction全文复算一致才继续 |
| listener | 精确 `{bind_host,bind_port}`，已审节点监听方案 | service.bind_host/approved_bind_host/bind_port |
| diagnostics_enabled | 可选严格布尔；省略等效false，拒绝字符串/整数/null | 仅session.diagnostics_enabled；失败结构取证，不改变任何批准位 |

`request_id`须为64位小写hex；不得两端分别铸造。owner/input_ref/instruction不从模型输出猜测。
instruction仅有摘要不足以构造permit，必须提供对应的固定问题全文；不strip或追加换行。
参数中不接受api_key正文、approved开关或proxy_port覆盖；额外字段拒绝。
这里的额外字段不包括上述显式可选项。未提供开关时，session仍为原12字段；
提供时为13字段，service仍为schema2精确12字段、输出仍16件。
开关开启只记录失败帧结构/输出字节数/结束状态/解析子阶段，不记录stdout或stderr内容，
包括十六进制前缀。参数、编译输入、session和引用它的service摘要均须重新核验钉住。

## sources：6项受控源

| 键 | path指向的现存文件 | sha256来源 |
| --- | --- | --- |
| api_key | Cube控制面纯key文件；不是.env，不含换行/变量名前缀 | 受控源交接清单 |
| ca | Cube控制面HTTPS的CA文件 | 对应控制面CA清单，不混用业务broker CA |
| receipt_key | 32字节receipt/vault密钥文件 | 受控源清单；不自动生成或轮换 |
| certificate | 业务broker服务器证书文件 | 已批准签发材料清单 |
| private_key | 上述服务器私钥文件 | 受控签发清单 |
| broker_token | .171/.172已经对齐的纯token文件 | 受控交接清单；principal由同源字节摘要派生 |

每项形状：`{"path":"规范绝对路径","sha256":"独立核准的完整64hex"}`。
文件必须已存在、0600、直接父0700。CA/证书如需私有暂存，应另按受控安装步骤完成，工具不改源权限。
输出中对应api_key.asset等文件会自动复制；无需Agent另写key物化脚本。
缺源、缺预期摘要或摘要不匹配，转换阶段即BLOCKED，不写input或材料。

## identity_files与supervisor_identity

| identity_files键 | 原始路径 | 对应pins键 |
| --- | --- | --- |
| executable | 监督进程实际规范解释器路径 | executable / executable_sha256 |
| script | 现役监督脚本原路径 | script / script_sha256 |
| unit_file | 监督unit的FragmentPath | unit_file / unit_sha256 |

supervisor_identity其余两键：`cmdline_sha256`、`unit`（完整.service名）。
8字段须来自只读身份核验记录；不是包含pid/boot/start_ticks的过程快照。
三组path/hash先与identity_files核对，不能通过模板替换掩盖原pins冲突。
脚本遵循launcher的0600/父0700合同；解释器/unit文件遵循受保护系统文件合同。

## directories：8项现存目录

| 键 | 含义 |
| --- | --- |
| supervisor | 已登记监督manifest/heartbeat目录；不是脚本目录 |
| vault | 当前计划的密封回执目录 |
| fence | 当前计划的创建栅栏目录 |
| quota | 当前计划的额度记录目录 |
| tracking | launcher跟踪记录目录 |
| lifecycle | lifecycle create/closeout记录目录 |
| store | BusinessStore持久化目录 |
| workspace | CsvWorkspace目录，不是.171用户文件区 |

全部规范绝对路径、当前UID所有、0700；彼此不重叠/嵌套，不与output_directory重叠。
工具只引用，不创建、不清空。目录可否使用仍须既有批准与状态核验，不能用新路径绕过旧状态。

## create与window

create精确7键：`run_id / create_token / template_id / boot_id / candidate_sha256 / domain / endpoint`。
candidate_sha256是运行候选安装信任链中的完整摘要（本链通常为wheel摘要），**不是短Git SHA**。
endpoint为Cube控制面HTTPS，domain为CubeProxy guest Host路由域。
`restricted=true`、request摘要、approval摘要、intent零占位由转换器/编译器构造。
数据面proxy_port固定80；不把控制面endpoint降为HTTP。

window精确12键：
`schema/window_id/run_id/boot_id/candidate_sha256/creator_id/inventory_sha256/accepted/revoked/starts_epoch/ends_epoch/writers`。
writers每项精确4键：`id/responsible/confirmed_epoch/abstain`。
creator按现有read_window合同不在writers中；不得为了凑字段伪造/移除主体，身份角色安排先审阅。
inventory为排序writer IDs的canonical JSON摘要，confirmed为真实实收，不是登记或推算时刻。
window的run/boot/candidate须等于create；accepted=false，revoked=false。

现有编译器即使生成禁用材料，也要求完整且一致的W0事实、确认不晚于start。
若窗口/确认尚未确定，必须报缺项；本工具不填样例日期、null确认或自动开新有效期。
禁用材料的未来/历史时间不构成“当前窗口有效”，激活另审。已有过期记录不得冒充新轮确认。

## 自动构造的documents（不再由现场手写）

| 文档 | 构造依据 |
| --- | --- |
| request | create的template/run/token，禁止公网 |
| window | 待审W0原事实，accepted保持false |
| approval | create plan、request内容摘要、max_creates=1、双false、window.ends |
| precreate | plan、template_pins、pins、源key/CA路径、W0路径/摘要 |
| installation | precreate/approval/request/key/CA/receipt摘要，目录，两个结构计划 |
| launcher | installation摘要、原监督脚本与摘要、tracking |
| lifecycle | slot=A、launcher摘要、lifecycle目录 |
| session | 完整expected_create、CSV/问题摘要、control/pins、双false |
| permits | 单一request、输入摘要、token源摘要、expiry、approved=false |
| service | schema2监听、证书/私钥、permit和单plan引用、approved=false |

所有模板引用由代码生成；禁用布尔固定false，转换器无开启开关。
批后不能原位翻转本轮文件，仍须另建审核过的最终输入与完整重验。

## 工具入口

`business_materials_input.py --parameters … --sha256 … --output-input … [--generate]`

- parameters：0600/父0700的现场参数文件规范绝对路径。
- sha256：安装方独立审阅钉住的parameters摘要，不是service摘要或编译器input摘要。
- output-input：新的0600 input文件路径，父目录0700；不在16件输出目录内部。
- 默认：核验源/身份/引用并输出input，状态DISABLED_INPUT_PREPARED。
- --generate：同一次调用编译并读回16件，状态DISABLED_MATERIALS_READBACK_VERIFIED。
- 输出含input_sha256及材料状态；不输出路径、绑定正文、凭据或原始异常。
- --verify-only仍使用business_materials.py，传output-input路径与返回的input_sha256。
- 已存在文件/目录不覆盖；失败保留，不自动改目录重试，不启动服务。

## 可填写样例与命令说明

`business_materials_example.py --directory … --parameters` 生成完整可读取的parameters.json假样例。
它仅用于展示结构/合成测试；现场必须替换每个来源值，不能复用假文件、假pins、假W0或样例token。
CLI采用明确导入交付目录中的business_materials，支持python -I，不依赖PYTHONPATH。

命令模板见本轮HANDOFF。Codex不持有真实绑定/凭据，不能给出含未知实值的“直接创建命令”。
