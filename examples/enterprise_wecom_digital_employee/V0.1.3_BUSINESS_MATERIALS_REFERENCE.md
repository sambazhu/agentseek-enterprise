# 业务材料生成与落盘自检合同

## 范围

| 项 | 合同 |
| --- | --- |
| 实现 | `scripts/business_materials.py`，标准库独立工具；不进入运行时 wheel |
| 输入 | 一份经安装方审阅、独立钉摘要的 JSON 模板图；无 Python/eval/命令模板 |
| 输出 | 6 个物化资产文件、10 个业务/创建链 JSON，共 16 件；新目录、不覆盖 |
| 支持 | schema-3 precreate、schema-2 installation、A lifecycle、schema-1 session、schema-2 service |
| 不支持 | B 执行、接续旧意图、生成批准决定、签发证书、修改 unit、创建或清理运行目录 |
| 凭据 | 输入仅源文件路径与源摘要；session 的内联 api_key 从已验证源字节派生，只写私有输出 |
| 成功状态 | `MATERIALS_READBACK_VERIFIED`；`execution_authorized=false`；不是 READY 或业务全链 PASS |
| 运行对象 | 现有 50adc3f 业务运行代码与 wheel 不变；历史 generators/、清单与披露原件不变 |

## CLI 与输入根字段

`--input` — 规范绝对路径，0600，直接父目录0700，当前 UID 所有。

`--sha256` — 安装方独立核准的输入文件完整 SHA256；不得将任意现存输入自算摘要充作批准。

`--verify-only` — 不写输出，不修权限，不补文件；从相同钉住输入和受控源重新推导预期字节。

| 输入字段 | 约束 |
| --- | --- |
| schema | 整数1 |
| output_directory | 规范绝对路径，直接父目录0700；生成模式要求目标不存在 |
| sources | 精确6项：api_key、ca、receipt_key、certificate、private_key、broker_token |
| identity_files | 精确3项：executable、script、unit_file；现役监督身份引用，仅读不复制 |
| directories | 精确8项：supervisor、vault、fence、quota、tracking、lifecycle、store、workspace |
| documents | 精确10项：request、window、approval、precreate、installation、launcher、lifecycle、session、permits、service |

`sources` 每项 — 精确 `{path, sha256}`。源文件须规范绝对路径、普通文件、单硬链接、当前 UID、0600/直接父0700。
源摘要来自受控源交接/审阅清单，随整个输入被安装方钉住。
输出禁止充当源。缺预期摘要为 `uncovered_digest`，不是跳过检查。

`identity_files` 每项 — 精确 `{path, sha256}`；独立可信身份 pins/安装清单提供预期摘要。
普通文件、单硬链接、当前 UID 或 root 所有，文件及直接父目录不可组/其他用户写。
监督解释器、脚本和 unit 保持原路径，不复制、不修改、不重启。
其中script遵循launcher的config_bytes合同：0600/父0700、当前UID、≤65536字节；
executable与unit_file才适用受保护系统文件权限规则。

`directories` — 已存在的0700目录，当前 UID 所有，彼此不重叠、不嵌套，不与输出目录重叠。
仅检查路径与权限，不登记监督、不初始化 SQLite、不检查或清空额度/manifest。
这些目录可否用于本轮，仍由现场批准与现有运行门禁裁定。

## 模板引用

| 形式 | 解析结果 |
| --- | --- |
| `{"$file":"api_key"}` | 当前输出目录的 api_key.asset；对其他 source/document 同理 |
| `{"$sha256":"precreate"}` | 由钉住输入编译出的 precreate **预期字节**摘要；非输出文件倒算 |
| `{"$ascii":"api_key"}` | 已核验受控源的 ASCII 原始字节；仅允许 api_key |
| `{"$directory":"vault"}` | 输入 directories 中已审路径 |
| `{"$identity_file":"unit_file"}` | 已核验的原监督 unit 路径 |
| `{"$identity_sha256":"script"}` | 已核验的监督脚本预期摘要 |

模板标记必须为单键对象。不支持插值、环境变量展开、任意代码或任意内联秘密。
`*_file`、`launcher`、`supervisor_script`、`exclusive_window.path` 不接受字面路径；未覆盖即失败。
未知引用、摘要依赖环、额外顶层字段、缺字段、摘要格式错误均拒绝。

## 摘要来源

| 对象 | 预期摘要来源 | 实际核验 |
| --- | --- | --- |
| 输入模板图 | 经安装方独立审阅/钉住的输入摘要 | 生成前与读回后重新读取输入 |
| 私有源资产 | 受控源交接清单中的预期摘要 | 先读取源并匹配，再物化；最终再次验证源 |
| 监督身份文件 | 独立 pins/安装清单的预期摘要 | 仅读现役文件、比较，不执行身份探测 |
| 生成 JSON | 钉住输入确定性编译出的内存字节 | 生成后独立读盘逐字节及摘要比较 |
| 已生成资产 | 已验证的受控源原字节 | 独立读盘比较，禁止从待验输出制造“预期” |

生成 JSON 的摘要由生成内容计算，是合法的引用构建，不是缺陷本身。
它不构成独立的人类批准。过去的问题是缺少源校验与实际读回，而非一律禁止内容寻址。

## 字节、权限与失败语义

- api_key：1–4096 字节，ASCII 33–126；broker token：32–256 字节、同字符范围。
- 不 strip、不追加换行、不生成/轮换秘密；带换行的源直接失败。
- receipt_key：精确32字节。
- 所有生成物≤65536字节，符合现有 config_bytes 大小上限。
- 输出0700，文件0600；O_EXCL/O_NOFOLLOW，文件 fsync，读回成功后目录 fsync。
- 输出清单必须恰为16件；缺件、多件、符号链接、FIFO、硬链接、权限或摘要错误均失败。
- 失败返回2；stdout仅固定错误类别，不打印异常正文、路径、凭据、业务内容。
- 失败后的已写文件保留；工具不删除、不回滚、不重试、不换目录重跑。
- `--verify-only` 不信任旧“PASS”或输出自带摘要，始终重新从同一钉住输入推导。
- root/同UID恶意修改、校验后修改、宿主崩溃的完全原子发布不在保证范围；执行前仍须重验及现有门禁。

## 静态引用核验

| 链 | 核验内容 |
| --- | --- |
| request→plan | 内容摘要、template/run/token、禁止公网 |
| W0→approval | run/boot/candidate、inventory、writer确认时间、起止、expires；不生成本人确认 |
| approval→precreate | 同 plan、候选、批准文件、W0路径/摘要、writer全集 |
| precreate→installation | precreate/approval/request/key/CA/receipt-key实际引用和预期摘要 |
| installation→launcher→lifecycle | 相邻路径/摘要、监督脚本引用、A槽、batch=2且token不同 |
| session | expected_create精确binding、vault/key、pins、control key/CA/endpoint/domain/HTTP80 |
| permits→service | 单请求owner/request/input/instruction/principal/expiry与session一致，plan文件摘要 |
| 身份/目录 | pins精确8字段、三身份文件源摘要、各路径对应已审目录 |

batch 第二计划仅结构登记，不生成B批准，不提供B执行入口，不增加创建授权。
审批布尔值原样来自已钉输入；七个相关批准字段须一致。工具不自动由false改true。
新批准输入必须另行审阅、另钉摘要；旧输出不原位翻转。

## 合成样例与验证边界

`scripts/business_materials_example.py` — `--directory` 指定新私有目录；生成 input.json、假受控源、空合成运行目录。
所有批准字段false；证书/身份文件为显式假字节，不能部署。源摘要由已知假字节构造。
样例不是现场凭据获取器，不从环境或机器猜测 owner/request/W0/pins。

39项工具测试：正常生成及只读复验、6源缺失、摘要缺失/错误、凭据换行、权限、符号链接/FIFO、
引用/环/错误摘要/端口/窗口/字段/批准/batch、输出篡改/漏写、源变化、3身份源变化、脱敏CLI等。
兼容测试调用真实 load_config、ApprovedCsvSessionFactory.validate_installation、
CreatePlan.binding、IdentityPins.validate、BatchQuota构造；不调用reserve或任何平台操作。
另调用真实read_window/read_create_approval；仅模拟root门，W0使用显式合成时钟，不冒充现场有效期核验。

不验证真实TLS证书链、有效期当前活体、systemd运行身份、guest模板、网络或实际业务结果。
不生成broker unit或网关grants。成功返回service_sha256供已批准的unit配置引用，禁止手抄后跳过比对。
现场批准、boot/身份、文件可用性与创建额度仍是独立前提。
