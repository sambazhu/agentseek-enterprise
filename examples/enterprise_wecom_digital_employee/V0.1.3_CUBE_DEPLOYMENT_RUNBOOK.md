# v0.1.3 CubeSandbox 私有化部署 Runbook（Linux）

本文是**操作体裁**的复刻手册：按部署步骤顺序组织，每步给出检查命令与
期望输出，用于在新的 Linux 环境复刻本项目已验证的 CubeSandbox v0.7.0
私有化部署（M0 形态，2026-09-08 用户确认 PASS，评审基线 `3d25447`）。

**事实依据与本文的关系**：全部细节源自验证手册 §10–§15（叙事实录）与
变更清单 v10（安装前方案）。本文只写**R1–R4 整改后的最终形态**（与
变更清单计划版的差异在 §5.9 列出）；与验证手册冲突时以验证手册为准。
叙事、评审过程与失败历史**不在本文重复**。

## 1. 前置要求（全部满足才继续）

```bash
# 1) 嵌套虚拟化（管理员在虚拟化平台开启后重启才生效）
grep -cE 'vmx|svm' /proc/cpuinfo          # 期望 >0
ls -l /dev/kvm                            # 期望存在，root:kvm 660
lsmod | grep kvm_intel                    # 期望已加载

# 2) XFS + reflink（CoW 依赖；ext4 不行）
findmnt -no FSTYPE,OPTIONS /data          # 期望 xfs 且含 reflink=1

# 3) cgroup v2 / eBPF
stat -fc %T /sys/fs/cgroup                # 期望 cgroup2fs
bpftool prog show >/dev/null && echo ok   # 期望 ok

# 4) 既有业务监听基线（冲突排查，存档备查）
ss -tlnp > /tmp/pre-install-ss.txt
ss -tln6 >> /tmp/pre-install-ss.txt       # 双栈都要记
```

**已知硬坑**：重启可能选到新装内核（本项目 5.15.0-119→191）；需固定内核
则先 GRUB pin。`/data` 不存在且 VG 满时需管理员加盘，不要动业务盘。

## 2. 版本锁定（禁止 latest / 浮动脚本 / 静默回退）

以变更清单 §2 为准（一键包/内核/guest 镜像/SDK wheel 四制品 sha256 +
8 依赖镜像完整 `registry/repo@sha256` 引用）。**安装时下载后重算四制品
sha256，不一致立即停止**。

基础镜像注意：ghcr `cubesandbox-base` 国内拉取慢且 HTTP/2 断流、未镜像
到腾讯源——本项目改用
`cube-sandbox-int.tencentcloudcr.com/cube-sandbox/sandbox-code@sha256:743d264f…`
（amd64 platform digest 单独登记）。

## 3. 端口规划矩阵（部署前定稿）

| 端口 | 归属 | 目标绑定 | 外部可达性 |
| --- | --- | --- | --- |
| 18089 | CubeMaster | 127.0.0.1（**默认 8089 必改**） | 不可达 |
| 3000 | CubeAPI | 127.0.0.1 | 仅经 nginx TLS :13000 |
| 3010 | CubeOps | 127.0.0.1 | 本机 + 172.29.0.1 过滤代理 |
| 13000 | nginx TLS 控制面 →127.0.0.1:3000 | 0.0.0.0 + 防火墙仅客户端 | TLS+X-API-Key |
| 13001 | nginx TLS WebUI →127.0.0.1:12088 | 同上 | TLS+WebUI 登录 |
| 13080 | nginx TLS 数据面 →127.0.0.1:80 | 同上 | TLS（token 透传） |
| 13010 | 过滤代理 →127.0.0.1:3010 | **仅 172.29.0.1**（专用网网关） | 仅 cube-webui 容器 |
| 80/443/9090 | cube-proxy（host 网） | **127.0.0.1**（模板级） | 不可达 |
| 9998/9966/8083 | cubelet/cubelet/LCM | **127.0.0.1**（模板级） | 不可达 |
| 9999/8082 | cubelet/proxy-nginx | 全地址 + **iptables 守卫链**（§5.3） | 仅本机+节点自 IP |
| 3306/6379/9000/9001 | mysql/redis/minio | 127.0.0.1 发布（compose 补丁/bind 变量） | 不可达 |
| 12088 | cube-webui | 全地址发布（脚本无 bind 变量）→防火墙限制 | 经 13001 |
| 9091/53 | egress admin/coredns | loopback/link-local | 不可达 |

**8089→18089 改写核验**（必须做，否则踩 §6 坑①）：改 env 后对渲染产物
全量 `grep -rn "8089"` 逐条分类——只有**活动值**（dynamicconf
`cubemaster_http_addr`、LCM `CUBE_LCM_CUBEMASTER_URL` 等）必须为
18089/127.0.0.1:18089；注释与历史文本可留。安装器 install.sh 本体 grep
应为 0 处。

## 4. 安装步骤

1. one-click 包解包审查（install.sh / env.example / 服务定义 / support
   compose），设 `CUBEMASTER_ADDR=CUBE_MASTER_ADDR=18089`，启用 WebUI
   （`WEB_UI_ENABLE=1`）并显式设 `CUBE_API_KEY`（**官方默认 unset=无鉴权**）；
2. 执行安装 → 8 容器 + 宿主组件（master/api/ops/cubelet/nginx）起来；
3. compose 渲染补丁规程（MySQL/Redis 等）：保留 `.orig` → 端口映射加
   `127.0.0.1:` 前缀 + §5.6 限额 → sha256 登记 → `docker compose config`
   校验 → 才 `up`；
4. 模板构建（登记 ID/digest）：
   ```bash
   cubemastercli tpl create-from-image \
     --alias agentseek-m0-poc \
     --image 'cube-sandbox-int.tencentcloudcr.com/...@sha256:743d264f…' \
     --cpu 1000 --memory 1024 --writable-layer-size 1024 \
     --expose-port 49983 --probe 49983:/health --backend xfs
   # 期望 status READY, distribution 1/1；登记 template_id/artifact/artifact_sha256
   ```
5. 立即冒烟一次创建/读写/销毁（沙箱创建 ≈0.2s=快照恢复路径正常）。

## 5. 与开源默认的关键差异（本文核心）

开源 one-click 默认形态**不能**直接用于本场景。以下 9 项为本项目改造，
全部经 M0 验证：

### 5.1 鉴权与入口（开源默认：CubeAPI 无鉴权明文）

- nginx TLS 三入口：13000（控制面，X-API-Key map **fail-closed**）/
  13001（WebUI）/ 13080（数据面，token 透传）；
- WebUI 隔离：专用 docker 网络 `cube-webui-net`（172.29.0.0/24）+
  过滤代理 13010（仅听 172.29.0.1，白名单 `^~ /api/v1/sdk/` 与
  `= /health`，`/internal/` 与归一化变体全 403，`/sandbox/` 入口 403）；
- 客户端侧 TLS 隧道（.171 asyncio 转发器 127.0.0.1:13080 → .172:13080），
  CA 信任 + IP SAN。

### 5.2 loopback 绑定收敛（模板级，非产物级）

80/443/9090/9998/9966/8083 收 127.0.0.1——**必须改 nginx.conf.template
地址前缀 / env，不能只改渲染产物**（重渲染会冲掉，见 §6 坑⑤）。

### 5.3 防火墙最小集（9999/8082）

`CUBE_POC_GUARD` 专用链，**v4+v6 双栈**，INPUT **首条无条件跳转**：

```
v4（每端口三条）：-s 127.0.0.1/32 ACCEPT；-s <节点IP>/32 ACCEPT；
                  其余 REJECT --reject-with tcp-reset
v6（每端口两条）：-s ::1/128 ACCEPT；其余 REJECT tcp-reset
```

用仓内 `sandbox_poc/portguard.sh`（R4 版：无窗口换链、阶段化失败合同、
flock 互斥）。**v6 不可省略**：9999=cubelet `[::]` 双栈通配监听，同链路
客户端可经 link-local 绕过 v4 规则（本项目实测复现，见 §6 坑⑥）。

### 5.4 systemd 拓扑（重启韧性，实测 boot 时序守卫→docker→容器）

| 单元 / drop-in | 作用 |
| --- | --- |
| cube-poc-portguard.service（enabled） | boot 重建守卫链（幂等） |
| docker.service.d/93-poc-portguard | **Requires+After** 守卫（守卫缺失 docker 拒启，两种失败形态均实测） |
| 4 个监听单元 .d/93-poc-portguard | Requires+After 守卫 |
| nginx .d/94-poc-order | After=docker + Restart=on-failure（boot 时网桥未起 bind 失败自愈） |
| cube-poc-limits.service（enabled）+ egress/coredns ExecStartPost | 限额对齐（docker update 不跨容器重建持久） |
| cubelet .d/91-poc-arp | ExecStartPre ping 网关（ARP 过期崩溃根治） |

⚠️ **安装器默认 `cube-sandbox-compute.target=disabled`**：整机重启后计算
栈不自启，需手动 `systemctl start cube-sandbox-compute.target`。生产部署
建议 enable 并做一次重启演练。

### 5.5 PoC 侧三组件（.172/.171 各自部署）

- **.172** `/root/cube-poc-supervisor/`：node_supervisor（120s 墙钟硬截止、
  metadata marker 归属、HttpCubeClient 总截止+看门狗）+ preflight（创建前
  门禁 exit 0/3）+ manifest；systemd cube-poc-supervisor.service；
- **.172** `/usr/local/sbin/cube-poc-portguard.sh`（§5.3）；
- **.171** `/root/cube-poc-client/`：venv（py3.13）+ tunnel_forwarder +
  pki/（CA/证书/x_api_key）+ Oracle 脚本。

### 5.6 资源限额（冻结值，容器/宿主分别落点）

容器（compose 模板 mem_limit / docker update）：mysql 512 / redis 128 /
minio 768 / coredns 64 / webui 64 / proxy 512 / lcm 256 / egress 256 MiB；
宿主（systemd MemoryMax）：master/api/ops 各 512M，**cubelet 1536M（含
VM 1024，不重复计）**，nginx 64M。汇总：服务 4.625GiB≤5GiB，含 VM
5.625GiB≤6GiB。VM 档位 1C/1G/120s/并发 1。

### 5.7 preflight 创建门禁（6 项，全部失败关闭）

master 活动引用值级校验（防空值回落 8089）/ 8 容器限额 / 端口收敛+
`iptables -S` 完整形态 token 全等 / **firewall_v6**（ip6tables 同构）/
egress 9091 存活 / 监督心跳。exit 0 放行、3 阻断；**每次建沙箱前调用**。

### 5.8 与变更清单计划版的差异（R1–R4 演进结果）

- UFW 三向策略 → **用户拍板禁用**（内网 PoC），以绑定收敛+守卫链补偿；
- 限额主落点 docker update → **compose 模板 mem_limit + ExecStartPost
  双路径**（R2 渲染回归教训）；
- portguard 单簇版 → R4 阶段化版（含 v6 双栈）。

### 5.9 测试资产

`sandbox_poc/` + `tests/`（含状态化 iptables 模拟器）随仓分发；**部署机
Python 版本必须进测试矩阵**（py3.10 与 py3.13 标准库行为有分叉，本项目
纳秒时间戳解析缺陷因此逃过九轮评审）。

## 6. 部署检查清单（六大坑，逐项核过才算部署完成）

| # | 坑 | 检查命令 | 期望 |
| --- | --- | --- | --- |
| ① | cubemaster_http_addr 空值→编译默认 127.0.0.1:8089（模板构建 sha 恒错） | 构建 1 次后取 artifact sha；或 strace cubelet `connect()` | sha=登记值；connect 目标=18089 |
| ② | 创建链不校验 egress（宕机仍可建沙箱） | 停 egress → 建沙箱 | 应被 preflight 阻断（exit 3）；egress 配 unless-stopped |
| ③ | 重渲染冲掉产物级改动 | restart cube-proxy 单元 → 复核 §5.2/§5.6 | 收敛与限额不变（模板级） |
| ④ | cubelet ARP 崩溃循环 | journalctl -u cubelet | 无 `gateway mac … not found` |
| ⑤ | startedAt 纳秒 × 部署机 py 版本 | 部署机跑 supervisor 单测 | 全过（解释器矩阵） |
| ⑥ | IPv6 双栈绕过 | `ss -tln6`；客户端 `curl -6 'http://[fe80::…%iface]:9999/'` | 全地址监听端口必须 v6 守卫；探测 refused |

## 7. 验证与验收

1. preflight 6/6 PASS exit 0；
2. 客户端侧双栈探测：除设计入口（13000/13001/13080/管理 SSH）外全部
   REFUSED；
3. O0–O11 Oracle（表见验证手册 §5，实测结果 §10.3）至少覆盖 O1/O4a/O5/
   O6/O7 冒烟级重跑；
4. **整机重启演练**：核 boot 时序（journalctl 时间戳：守卫→docker→容器）、
   preflight 复跑 6/6、compute.target 状态；
5. 建议各一次失败注入：守卫单元缺失时 docker start 拒启、portguard 晚期
   失败保留保护（外部链引用法，见验证手册 §14.3）。

## 8. PoC→生产差异清单（复刻到生产前必须处理）

1. **防火墙**：正式防火墙（ufw/firewalld/云 SG）+ DOCKER-USER 双栈；
   有全局 v6 的环境守卫链必须全量 v6；
2. **镜像扫描**：PoC 已豁免（≠已评估）——生产必扫底座镜像；
3. **存储**：同机 MinIO=单故障域 → 独立 S3/存储集群，Volume 与内容分桶；
4. **多身份**：单可信 PoC 身份 → 生产必须做跨身份资源归属授权
   （O4b 类，验收清单见验证手册 §11.7）；
5. **证书**：正式 CA 替代自签；
6. **上游反馈五项**（部署时同样会遇到）：cubemaster_http_addr 渲染默认值、
   cubelet ARP 依赖、startedAt 纳秒精度、cubelet/LCM 全接口绑定、创建链
   egress 校验缺失。

## 9. 升级注意事项

- 升级/重装前先取 §5 全部改造点清单对照——**上游升级脚本会重渲染配置**，
  模板级补丁需按补丁规程重放（`.orig` 比对一致才重放，防覆盖新版本修复）；
- drop-in 与自建 service 不在升级路径内，升级后逐个复存；
- 升级后完整重跑 §6 检查清单 + §7 验收。

## 10. 回滚（默认=停用保留，删除类操作另需授权）

顺序：停客户端转发器 → 停 supervisor → 停自建单元（cube-poc-*）→ 删
nginx 站点与 apikey map/DOCKER 网络 → 撤 iptables 守卫（`portguard.sh
remove`，v4+v6 都撤）→ 撤 drop-in → 恢复 `.poc-orig/.orig` 配置 →
数据卷保留归档。既有业务（SSH/8089 归属/其他监听）全程不动。
