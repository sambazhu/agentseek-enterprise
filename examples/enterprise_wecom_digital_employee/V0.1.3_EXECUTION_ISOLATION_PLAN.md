# v0.1.3 CubeSandbox 执行隔离与工作数据架构评审

状态：**2026-09-06 用户已确认方案审阅通过；M0 准备进行中，尚未实现或部署。**
阶段记录见 [M0 准入与验证清单](V0.1.3_M0_SANDBOX_ADMISSION.md)。
最新预检结论为 PARTIAL：Linux CC 已完成只读检查，但 `.172` 未暴露 KVM。
锁版决策、安全清单和操作 Oracle 见
[M0 Linux 验证手册](V0.1.3_M0_CUBESANDBOX_VERIFICATION.md)。
本稿取代此前多 Provider 并行建设草案。调研日期为 2026-09-06；
官方资料反映各页面当前状态，不代表本项目已锁定或验证了对应发行版。

## 1. 评审结论

建议 v0.1.3 **只实现 CubeSandbox**，通过私有化微虚机服务执行脚本。
AgentSeek 保留薄适配接口用于测试和未来替换，不开发 Podman、Docker、
Bubblewrap、E2B 四套并行适配，也不在故障时静默降级为宿主 Shell。

架构准入是“有条件通过”：CubeSandbox 适合 Linux、企业内网、不同研发团队
扩展 Skill 的目标；生产可用性需要真实部署证明。M0 必须锁定 Cube 服务端、
原生 SDK、模板和 Volume 插件版本，完成 KVM、鉴权、网络、存储和故障恢复验证。
无法满足时保持 BLOCKED，调整部署条件后再继续。

采用以下四个核心决定：

1. Agent 和企业授权留在 Gateway；脚本进入独立微虚机。
2. 一个 execution attempt 独占一个沙箱，可在其中执行多个连续命令。
3. VM 生命周期与资料、workspace、输出物生命周期分离。
4. 以版本化 manifest 和外部内容存储恢复任务，VM 快照只作为可选加速。

## 2. 现有方案中需要修正的问题

| 问题 | 证据或影响 | 本次修正 |
| --- | --- | --- |
| 多后端同时建设 | 测试、故障分类、挂载语义会成倍增加 | 只交付 CubeSandbox |
| “一次 Tool 调用一个容器”过细 | DeepAgents 写脚本、执行、读输出常需多次调用 | 一个执行单元内复用 VM，跨 attempt 新建 |
| 每个 WorkItem 一张长期 VM 又过粗 | 等审批时占资源，容易遗留进程与权限 | Work 保存文件版本，计算阶段短期租用 VM |
| 文件挂载缺少版本与提交合同 | 只读不保证内容不被其他写入者改变 | immutable input manifest + 单写 attempt |
| 将任意输出登记成 Work Artifact | 当前 ArtifactRecord 要求 WorkItem、来源合同和审批版本 | 草稿用 ExecutionOutput，正式产物继续走 Work 审批发布 |
| 以快照代替持久化 | 内存、文件和外部副作用不能一起回滚 | 独立 ledger 与内容提交，快照不作业务真相源 |
| 主 Agent Backend 与沙箱混用 | 文件权限不会自动约束所有 Python Tool | 专用执行 Tool/子 Agent 获得受限 backend |

这不是对 v0.1.2 已通过的渠道合同返工，而是新执行能力上线前需要补齐的边界。

## 3. 从成熟实现中借鉴什么

| 参考实现 | 可借鉴机制 | 在本项目的选择 |
| --- | --- | --- |
| DeepAgents | Agent 在沙箱外运行，Backend 提供文件与 execute，宿主负责导入导出 | 保留企业主 Agent；只给执行子 Agent 沙箱能力 [S1] |
| E2B | 控制面与微虚机执行面分离 | AgentSeek 管业务，Cube 管 VM；不自研虚拟机运行时 [S2] |
| Daytona | 进程内存、沙箱磁盘和独立 Volume 有不同生命周期 | 分开定义工作版本、临时文件和 VM 恢复点 [S3] |
| Firecracker | 微虚机还需宿主权限约束、补丁和资源隔离 | 将宿主加固列入准入；不假定 Cube 等同 Firecracker 实现 [S4] |
| Bubblewrap / gVisor | namespace 或用户态内核提供不同隔离与兼容性取舍 | 仅保留比较依据，不增加 v0.1.3 实现 [S5] |
| CubeSandbox | 微虚机、独立 Volume、网络代理和模板生命周期 | 选定单一执行基础设施，以原生 SDK 适配 [S6–S11] |

这些是架构借鉴，不是性能或安全认证。本轮没有测得启动延迟、并发容量或故障恢复
成功率，不引用供应商宣传数字作为容量规划。

## 4. 推荐部署架构

```text
每名数字员工的逻辑部署单元
  Gateway / Main Agent
    身份、会话、记忆、Capability、WorkItem、企微交付
       |
       | 已授权 ExecutionRequest（文件引用，不含主机路径）
       v
  Execution Broker（独立进程、独立凭据）
    准入、租约、attempt、资料选择、输出提交、对账
       |                              |
       | Cube 原生 SDK                +--> Execution Ledger（本地可靠盘）
       |                              +--> Content Store（私有 S3 兼容存储）
       v
  独立 CubeSandbox 服务
    CubeAPI / 调度 / 节点 / 代理 / Volume 插件
       |
       v
  microVM：某个 execution / attempt
    /skills       版本化执行资产，只读
    /inputs       本次授权输入，只读
    /context      最小背景资料，只读
    /workspace    本 attempt 工作副本，可写
    /outputs      待校验候选输出，可写
    /tmp          临时盘，限额
```

优先使用独立 Cube 测试/执行节点，保持现有企微 Gateway 主机运行方式。
使用方已指定 Gateway 为 `192.10.50.171`、Cube 测试节点为 `192.10.50.172`；
主机规格、虚拟化能力、实际服务端口与存储位置在 M0 核验后固定。
如果数字员工部署在没有 KVM 的普通 VM，Gateway 可通过内网访问远端 Cube，
无需在每个部门实例里运行嵌套微虚机或改宿主内核。

Cube 可以由平台统一运维；每名数字员工仍有独立 Broker 和服务身份。共享集群
不等于共享 VM、Volume 或企业凭据。若选定版本无法按资源所有权校验跨 Broker
请求，首版按团队分区部署 Cube，不能仅凭 Volume 名称前缀声称多租户隔离。

## 5. CubeSandbox 的准入条件

### 5.1 版本与接口

使用 Cube 原生 Python SDK，锁定精确版本及模板不可变 ID/digest。
Volume 文档所述只读挂载需要原生扩展；该文档还明确指出相关官方 E2B Python
SDK 路径存在硬编码后端限制，不能把“E2B 兼容”理解成所有 SDK 原样可用。[S7]

项目当前锁定 `deepagents==0.6.12`。先实现其
`SandboxBackendProtocol` 适配，不顺带升级整个框架。
较新 DeepAgents 的 Provider 或多模态文件 API 必须另做兼容验证。

### 5.2 鉴权和网络

Cube 文档说明 API 默认不鉴权，出网默认允许。[S8][S9]
上线合同必须显式配置：

- CubeAPI 的身份认证、资源所有权校验和认证服务故障时拒绝；
- 控制面和数据面均使用私网、TLS、访问控制，不能只保护 API；
- 默认拒绝出网，业务网络只经服务端固定代理规则；
- 检验 IPv4/IPv6、DNS、直连 IP、非标准端口、元数据地址和内网绕过；
- 模型、企微、PG、Cube 和对象存储主凭据不进入 VM；
- 代理代签仅开放具体业务目标和操作，避免“看不到密钥却可以滥用权限”。

沙箱的 RO 标志、环境变量清理、非特权执行身份和挂载不可重配均需实测。
Guest 内可执行任意脚本时，不能以 prompt 或 `chmod` 作为唯一限制。

### 5.3 计算节点与容量

裸机 KVM 是优先路径。Cube 另有 PVM 和开发嵌套虚拟化路径，需按版本和部署
文档核验，不能直接用于现有生产主机内核替换。[S12]

M0 建立 CPU、内存、任务数、磁盘、文件数、日志量、网络和运行时间的实测档位。
每个 VM 上限之外，还要有节点预留、数字员工总配额、请求人并发和队列上限；
否则很多小 VM 仍可耗尽共享节点。节点失联只阻断执行任务，普通问答应继续服务。

### 5.4 本轮安装安全合同（M0 固定项）

- 控制面启用 X-API-Key 校验和资源所有权检查；数据面要求 TrafficAccessToken，
  分别测试缺失/错误凭据被拒。字段和 SDK 行为以 v0.7.0 实测为准。
- `.171` 到 `.172` 的控制面、文件代理均使用可信 TLS/反代；内部明文端点仅限
  loopback 或明确防火墙隔离，不能通过另一个监听端口绕过认证。
- 沙箱显式默认拒绝出站，需要访问业务目标时使用 CubeEgress 精确白名单；
  凭据注入另列安全评审，首轮 PoC 关闭，不注入真实业务凭据。
- cgroup v2 配额同时覆盖微虚机与 Cube/MinIO 服务总消耗；共存服务资源余量
  经实测后冻结，不能按节点总容量全部分配给沙箱。
- Host Mount 默认不使用；若做边界 Oracle，仅允许 `.172` 的
  `/data/shared/agentseek-m0/` 专用测试子目录。`/data/shared/` 是候选允许根，
  不是自动授予整棵目录读写权限；拒绝路径穿越、符号链接逃逸和父目录挂载。
- `.172` 既有 `:8089`、`:22589` 和 `/opt` 业务保留。v0.7.0 的默认
  CubeMaster 配置含 8089，必须修改 Cube 监听及所有引用并完成渲染核验；
  不得停止原 uvicorn 腾端口，不直接执行默认一键安装。
- 管理员完成嵌套虚拟化变更后，重验 KVM 和既有服务；安装前还须验证
  `/data/cubelet` 的 XFS、eBPF/bpffs、网络 CIDR 和目录冲突。磁盘有余量不等于
  文件系统条件已满足；禁止自动格式化现有磁盘。

## 6. 数据应按什么粒度挂载和持久化

**授权以文件清单为单位，计算以 attempt 为单位，工作进度以任务版本为单位，
正式产物以不可变版本为单位。** 不按“整个部门一块可写盘”或“一个员工一张常驻 VM”
实现。

| 数据类别 | 作用域与版本 | 沙箱内呈现 | 持久化位置与时机 |
| --- | --- | --- | --- |
| Python/系统依赖 | runtime template digest | 模板提供，执行用户不可改发布基线 | 受控模板仓库；发布时固定 |
| Skill 脚本、品牌模板 | digital employee + Pack/Skill version | /skills，只读 | 发布资产库；升级产生新版本 |
| 部门背景资料 | tenant + digital employee + ACL + document version | /context，仅选择本次有权使用的文件/片段 | 外部知识源保持真相，执行留来源和所用版本 |
| 员工附件 | tenant + digital employee + conversation + grant + file version | /inputs，只读清单 | 复用 FileStore，通过授权导入 |
| Playbook 历史稿件 | tenant + digital employee + work_id + revision | 导入 /workspace 的私有副本 | 上一已提交 workspace revision |
| 普通 Turn 工作进度 | tenant + digital employee + conversation + task_id + revision | 同上，不要求创建 WorkItem | 通用 workspace manifest；显式 task_id，不取整个 session 为可写范围 |
| 中间文件与调试缓存 | execution_id + attempt | /workspace、/tmp | 默认临时；仅显式 checkpoint 进入持久化 |
| 候选输出 | execution_id + attempt + relative path | /outputs，可写 | 导出后隔离待检区；验证后成为 ExecutionOutput |
| 正式报告与交付件 | work_id + contract/approval version + artifact_id | 下一阶段只读导入 | 既有 Artifact/Publication/Delivery 流程 |
| 记忆与业务数据库 | 当前企业/会话/Work 作用域 | 不挂数据库目录；只投影必要事实 | Gateway 的现有存储与授权工具 |
| VM 内存快照 | execution_id + attempt + policy/template version | 私有恢复优化 | 默认关闭；启用时加密、短 TTL、访问控制 |

同一群的不同员工不必自动拥有彼此私聊文件。群聊 session 是对话范围，
文件是否可用于群任务还需显式 grant；“知道 file_id”不是授权。
跨阶段或跨会话继续任务时，Broker 重新校验当前权限，权限撤销后停止再次导入。

## 7. 首版数据路径：显式导入导出，Volume 只读加速

推荐首版只维护一条写入真相路径：**Broker + 私有 S3 兼容 Content Store**。
普通资料经 SDK 导入；脚本在 VM 临时盘运算；输出经 Broker 校验后用对象 API 提交。
VM 不持有对象存储主凭据。现有本地 FileStore 可作为输入来源，无需一次迁移。

Cube 的 S3 Volume 可独立于 VM 保存数据，支持只读 attachment。[S6]
它适合大模型权重、只读资料包等需要减少重复传输的资产。
首版普通文件默认复制；大资料采用“一个已封存资料包版本一个只读卷”，
并由 Broker 验证内容摘要。不是每个小文件建一卷，也不把整个员工目录挂入 VM。

需要特别遵守：

- Cube 文档说明只读是 attachment 属性，其他 writer 更新同一卷时读方会看到变化；
  因而发布卷必须封存，更新创建新版本，不能只加 read_only 就当快照。[S7]
- Cube 的 S3 Volume 经 s3fs 暴露文件。[S6] 不把它假定为本地 POSIX 事务盘；
  SQLite、SeekDB、WAL 和锁文件留在适合的本地盘或数据库服务。
- 首版不将 writable Volume 作为 workspace 真相源。未来如需要，再单独验证
  flush、原子性、并发和节点故障时的数据语义。
- Host Mount 指向的是 Cube 计算节点上的路径，不是远端 Gateway 的同名路径；
  它增加节点亲和和主机暴露面，首版不用于业务文件。[S10]
- 不向 sandbox 提供 Content Store 根桶凭据、列举其他 scope 的权限或永久下载 URL。

因此“不直接挂载宿主文件夹”仍然可以提供 /inputs 和 /outputs：
这些目录是 Guest 内的视图，由 Broker 负责填充与回收。

## 8. 工作进度如何跨步骤、跨 Turn、跨重启延续

### 8.0 沙箱何时启动（已确认）

DirectTurn 与 Playbook 使用相同的按需启动机制。进入对话或 Playbook 不创建 VM；
首次调用声明需要沙箱的业务能力时，服务端完成授权、输入清单和配额检查，
持久化 execution/attempt，再创建 VM、导入资料并开始执行。

是否需要沙箱由服务端 Capability 执行声明决定，不由模型指定。普通聊天、远程
知识查询和远程 MCP 不因此创建 VM；本地解析、脚本和文件生成能力按声明进入沙箱。
同一执行单元的连续工具调用可复用 VM；无关工具调用不能仅因属于同一 Turn 而共享。

DirectTurn 关联 task_id/execution_id/attempt；Playbook 额外关联 work_id/phase。
单元完成或需要等待用户时，先提交工作版本和输出再释放 VM；后续从已提交版本
新建执行环境。提交失败时保留有界恢复窗口并进入失败/对账状态，不能宣称成功。

### 8.1 执行粒度

定义稳定 `task_id`、`execution_id` 和递增 `attempt`。
一次执行单元可以包括“写脚本 → 运行 → 读取报错 → 修改 → 导出”多个命令，
同一 attempt 共用一张 VM。只读/普通问答无需建 VM。

Playbook 在执行阶段租用 VM，进入审批等待时提交文件 revision 并释放计算资源；
下一阶段或重试创建新 VM，导入上一已提交 revision。
普通 Turn 后续需要继续文件任务时，通过 task_id 找到 revision，而不是依赖 VM 仍活着。

同一 task 的可写 revision 首版单写，使用 ledger 中 lease + fencing token。
多个并行研究分支各自使用 branch/attempt 目录，由协调步骤显式合并。
旧 worker 失去 lease 后不能再提交；后端网络状态不确定时，不启动竞争 writer。

VM 创建也有不确定结果：请求超时不证明创建失败。Broker 在调用前持久化
execution/attempt 与创建 token，使用服务端标签或可核验关联记录查找孤儿 VM；
若选定 Cube 版本不能确认创建结果，进入 reconciliation，不立即再建另一张 VM。
取消以进程树停止和 VM 状态确认收敛，客户端超时本身不能作为“已取消”证据。

### 8.2 两阶段内容提交

```text
running
  -> exporting（停止/隔离写入者）
  -> validating（路径、类型、大小、摘要、输出合同）
  -> committing（对象已持久保存，再提交 manifest 和 ledger）
  -> succeeded
  -> 业务发布/企微投递（使用已有独立账本）
```

这里是应用层提交协议，不声称对象存储与 SQLite/PG 具有分布式 ACID 事务。

1. 分配 attempt 私有 staging key，脚本结果不能直接覆盖已提交对象。
2. 收集结束前停止后台写入；拒绝逃逸路径、软/硬链接、设备文件和特殊文件，
   避免校验与下载之间内容被替换。必要时通过隔离收集器读取稳定副本。
3. Broker 对最终下载字节重算 digest，校验配额、实际类型和 manifest；
   扫描/解析不可信格式也不得重新进入 Gateway 执行。
4. 写不可变对象并核验持久化，再以事务和 fencing token 发布 revision。
5. Work 正式产物仍检查来源合同、审批版本和 stale 状态；ExecutionOutput
   通过不意味着已批准、已发布或已送达。
6. 内容写入后 ledger 提交前崩溃，只留下待回收对象；同一提交 token 重试认领。
   ledger 提交后通知前崩溃，通过交付账本补偿，不重新运行脚本。

`exit_code=0` 只表示进程结束；成功还需可读、校验通过、已登记的输出。
任意脚本或外部 API 无法普遍保证 exactly-once；外部副作用未知时进入对账，
不能靠恢复 VM 或重跑命令保证不重复。

### 8.3 崩溃和快照

已提交 revision 是恢复点：节点硬崩后可换 VM 导入，未提交临时写入可能丢失。
长任务应在显式检查点导出增量 manifest，恢复保证为“最后一次成功提交”，不是零丢失。

Cube 的 pause/snapshot 涉及 rootfs、内存和元数据；外部 Volume、企业账本和外部 API
不应被假定为同一原子恢复点。[S11] 首版关闭自动快照恢复，先验证 manifest 重放。
将来启用也仅允许同一 scope/attempt 重连；恢复前重新检查权限与网络策略，
禁止把含员工数据的 VM 快照发布为公共模板。

## 9. 与本项目代码的接缝

- `agent.py:build_agent` 保留只读 Skill/Asset 和当前记忆 namespace。
  新增受治理执行 Tool；专用子 Agent 需要脚本推理时才注入 Cube backend。
  自定义 Python Tool 不会因切换 backend 自动迁出进程，需逐项改接。
- `LocalFileStore.store_bytes` 当前按 tenant、employee、session 等建目录，
  file_id 源于内容摘要；Broker 必须读取完整 FileRecord 并校验所有权和 grant。
  不能把摘要 ID 当授权，也不能把现有目录直接开放给 Cube。
- 当前 FileScope 未显式承载 digital_employee_id，依赖独立部署根隔离。
  新执行索引从第一天纳入该维度；历史根保留兼容映射，不直接重命名。
- `ArtifactRecord` 和 `put_artifact_record` 面向正式 Work 合同；
  通用 ExecutionOutput/WorkspaceRevision 独立建模，再适配已批准产物，
  不伪造 WorkItem 或审批记录承接普通 Turn 文件。
- 企微 response_url、长连接身份、应用 Secret 和 delivery 幂等继续由 Gateway 管理。
- 有状态 SeekDB/身份 sidecar 不作为首个每任务 VM 迁移对象。若需进程故障隔离，
  单独评估服务化，不把其数据库塞进 S3 FUSE 卷。

建议模块：

```text
contrib/agentseek-execution/       请求/结果、lease、提交、workspace、审计
  cube_backend                   唯一生产适配；测试使用 Fake
  broker                         受控创建/执行/取消/导入/导出
  manifests                      输入、输出、workspace revision
  reconciliation                 孤儿 VM / staging / 不确定动作对账

enterprise example + template    Capability 绑定、默认策略、部署预检
```

先做薄接口，不建设通用 provider 市场或另一套调度平台。Cube 已有 VM 调度，
AgentSeek 只补业务准入、任务公平性与持久化。

## 10. 数据保留、回收和运维

建议默认策略（须在 M0 与业务保留要求确认）：

| 对象 | 建议生命周期 |
| --- | --- |
| 临时 VM、/tmp | execution 结束回收；失败时有界隔离窗口 |
| 未提交 staging | 建议 24 小时后按无引用且无活跃 lease 条件清理 |
| 普通文件任务 revision | 建议 7 天，可显式延长，遵守来源附件保留期限 |
| Work workspace | 活跃任务及修订期间；归档后按企业策略 |
| 正式 Artifact、审计 | 延续既有业务保留与审批要求 |
| 发布资料包/模板 | 有任务引用时不得删除，升级新增版本 |
| VM 快照 | 首版不启用；以后单独设加密与 TTL |

TTL 不是无条件删除授权。回收先检查引用、lease 和实际挂载，再进入隔离/软删除
窗口；不能只相信节点崩溃后的 refcount。运维以加密存储、受控备份和恢复演练保证
持久性，0600 文件权限本身不代表加密。内容与 manifest/ledger 应一致备份。

单部署首版 ledger 用 Broker 独占的本地 SQLite（可靠本地盘），敏感字段加密，
不存脚本正文或凭据。Content Store 用私有 S3 兼容服务，单独桶/身份/策略；
产品和部署选型在 M0 冻结，不自动启用 Cube 一键安装所带的开发存储。
不迁移共享 ai_memory；未来 HA 再评估 ledger 的 PostgreSQL 适配。

## 11. 调整后的 M0–M6

| 阶段 | 本阶段交付 | 退出条件 |
| --- | --- | --- |
| M0 选型准入 | Cube/SDK/template/plugin 锁版；执行节点与 Content Store 方案；小型隔离与导入导出 PoC | 明确通过/缺口，用户确认；PoC 使用独立测试环境 |
| M1 数据和执行合同 | task/execution/attempt、InputManifest、OutputManifest、WorkspaceRevision、lease/fencing；Fake tests | 多用户权限、幂等、提交状态机可验证 |
| M2 Cube 接入 | 独立 Broker、create/execute/cancel/delete、配额、默认网络策略 | 真 VM 隔离、资源、失联、鉴权失败测试通过 |
| M3 文件生命周期 | 输入导入、RO 资料卷、候选输出校验、内容提交、回收 | 跨 VM 恢复文件，旧 attempt 不可覆盖新 revision |
| M4 DeepAgents/业务接入 | 固定入口文件 Tool，再接专用脚本子 Agent；Turn 与 Work 分别集成 | 普通输出不伪造审批，模型不能改 scope/模板/网络 |
| M5 恢复和多人并发 | Broker/VM/存储故障，取消、孤儿资源和人工对账 | 断点提交矩阵通过，无盲目重执行，无跨会话读写 |
| M6 Linux canary/发布 | 模板、runbook、观测、容量、回滚与 v0.1.2 全回归 | 活体 PASS 后进入合并评估 |

每阶段先交付可审阅结果，经用户确认再推进下一阶段。本次仅修改评审和路线文档。
首个真实能力建议选“结构化输入生成 DOCX/CSV 的固定入口”，计算在 VM，
Work 发布和企微交付在 Gateway。后续才开放限定模板中的 Python/Shell 自由脚本；
依赖安装通过镜像发布完成，默认不允许运行时联网安装。

## 12. 必须命中的验收场景

- 员工 A/B 同时执行，A 无法访问 B 的输入、workspace、输出和 Volume；
  群之间、数字员工部署之间同样验证，包括猜测资源 ID 和旧授权。
- RO 输入写入失败，资料源更新不改变已固定的输入 manifest。
- 同一 attempt 多次 execute 可衔接；新 attempt 无旧进程状态，能载入已提交 revision。
- 两个研究分支同名输出不互相覆盖；过期 fencing token 的提交被拒。
- 生成完成、导出中、对象上传后、ledger 提交后分别杀进程，结果可重放或可对账。
- 后台进程改写输出、符号链接、zip bomb、超大日志、磁盘满不会逃逸或拖死 Gateway。
- VM 销毁后已提交产物可下载；运行结束但未成功提交不得标 succeeded。
- Cube/鉴权/存储不可用时执行 fail-closed，已运行任务进入有界取消/对账，
  普通问答及既有渠道健康。
- 代理、DNS、IPv6、非标准端口和控制面地址绕过失败；Secret 不进入 prompt、VM、
  公共日志或产物，业务原文仅存在有授权的数据存储。
- 同一输入输出、模板与政策版本可追溯；内容变化产生新 revision，
  模型生成内容本身不承诺字节级可重现。
- 首次部署用 Linux 独立 canary；生产实例、历史数据和密钥按既有运维流程保留。
