## 2. 前置门：管理员完成后补验

1. 管理员在 vSphere 暴露嵌套虚拟化并安排 `.172` 重启。由于原 uvicorn 非
   systemd，业务恢复由其负责人安排；先确认原业务恢复再做 Cube 工作。
2. Linux CC 检查 vmx、/dev/kvm、实际设备权限及 KVM ioctl 可用性；仅加载模块
   或看到设备不足以判完整虚拟机创建通过。失败保持 PARTIAL。
3. 记录 `/data/cubelet` 的文件系统类型及 v0.7.0 本地 CoW 所需配置；安装器
   要求 XFS。核验 eBPF、bpffs 挂载和网络条件。任何格式化或系统调整交管理员，
   不执行 skip-precheck 绕过。
4. 记录 `.172` 既有业务的监听、健康和资源基线，保留 8089、22589 及 /opt
   所有既有业务目录。只记录允许的健康响应，不收集业务正文或凭据。
5. `.171` 双网关保持原样；在独立 PoC 目录/虚拟环境运行客户端，不更新现网 venv。

全部前置符合才标 READY-FOR-POC；这不是 M0 PASS。

## 3. 安装前生成配置与变更清单

1. 仅获取上述固定版本制品，校验摘要，在独立目录审查 bundle 的 install.sh、
   env.example、服务定义和 support Compose；不直接运行在线一键脚本。
2. 生成所有监听端口、绑定地址、配置引用、容器映射和目录的矩阵。
   CubeMaster 默认 8089 与现网冲突；可提议 18089，但先确认空闲，修改所有
   服务端与客户端引用后再核验。22589 同样保留，无论当前是否监听。
3. 检查配置中 8089 是否仍作为活动端点出现，包括 CUBEMASTER_ADDR、
   CUBE_MASTER_ADDR、节点注册与健康检查；注释与历史文本可保留。
   未找到可配置项时暂停，不用停止现有进程解决冲突。
4. 为 Cube/MinIO 预留独立目录、容器名和数据卷，检查是否与现有资源同名。
   不对已有 Docker/containerd 升级、重启、prune 或执行宽范围 compose down。
5. 冻结资源预算：首轮最多 1 个运行 VM，从 1 vCPU/1GiB 及 120s deadline
   的试验档开始；可否满足所选模板需实测。总服务预算先扣除既有业务峰值
   与节点余量。不能仅凭“节点 15Gi”判容量足够。
6. 生成控制面 X-API-Key 与数据面 TrafficAccessToken 的独立认证配置、TLS
   证书/反代配置，密钥只在本机受限文件保存。授权回调失败必须拒绝。
7. 配置默认拒绝出站；首轮不配置真实业务白名单/凭据注入。管理网络仅授权
   `.171` 的客户端与必要管理地址，防止绕过 TLS 直接访问后端监听。
8. Host Mount 默认关闭。若验证白名单，只允许预先确认的
   `/data/shared/agentseek-m0/` 测试子目录，不开放整个 /data/shared 或 /opt。
9. MinIO 数据用专用持久卷，PoC 内容存储与 Cube Volume 使用不同桶/前缀和
   权限；记录镜像版本/digest、数据目录和停服务不删数据的恢复办法。

先提交变更清单及端口/资源矩阵供维护者确认；确认后才执行审查过的部署步骤。
没有可验证的鉴权/TLS/端口避让配置时不能先开放服务“再补安全”。

## 4. 执行安装和最小 SDK PoC

1. 在 `.172` 应用确认后的配置，逐个启动本轮 Cube 与 MinIO 组件。
   每次启动后复核旧业务端口与健康；出现回归立即停止本轮变更。
2. 在 `.171` 独立 PoC 环境固定 cubesandbox==0.7.0，不接入现网 Agent。
   验证控制面 TLS 与数据代理 TLS，禁止关闭证书校验。
3. 建立带唯一测试前缀的 Volume，显式 driver=s3；记录 ID 的受限映射。
   先用可写测试实例写固定 canary 字节并完成存储确认，停止 writer；再以
   VolumeMount(read_only=True) 创建 reader 验证原生 SDK 挂载。
4. 使用已固定模板，默认拒绝网络，运行确定性脚本；分别执行写文件、读文件、
   返回摘要，证明同一实例的连续命令衔接。实际 SDK 参数按 0.7.0 签名核验，
   不从当前主干示例直接照抄。
5. 下载测试输出，对最终字节重算 SHA-256，保存到独立测试内容桶并回读比对。
   销毁 VM 后仍从外部存储读取输出；重建 VM 从同一只读 Volume 读取 canary。
6. 依次执行下表 Oracle，记录逐项结果、耗时、版本、资源基线及清理结果。
   测试只能使用本轮资源和虚构 canary，不加载真实员工数据或模型 Key。

## 5. 确定性 Oracle

| 编号 | 操作与判定 | 失败动作 |
| --- | --- | --- |
| O0 共存 | 安装前后 .172 8089/22589 归属与业务健康不变，/opt 未改；.171 双网关未重启；资源在预算内 | 停止本轮组件，保留现场 |
| O1 VM | 创建 A/B 各有独立实例；A 的临时文件在 B 不存在；删除后资源释放 | 不判隔离通过 |
| O2 原生 Volume | writer 写固定字节；reader 只读读取摘要一致，创建/覆盖/改名/删除均失败 | SDK 或挂载合同 BLOCKED |
| O3 持久化 | 删除 VM 后 Volume 重挂可读，下载输出外部保存可读；无隐式删除卷 | 保留卷，核查提交语义 |
| O4a 控制面（入口认证） | 缺失/错误 X-API-Key 被拒（13000 执行点）；后端 3000 直连不可达；WebUI/SDK 入口凭据不互通 | 不开放 PoC 业务调用 |
| O4b 跨身份授权（**已批准移至 Broker 阶段，本轮未验证、不计通过**） | A/B 有效身份跨资源负向、资源归属映射 | Broker 阶段验收时执行 |
| O5 数据面 | 对同一受保护端点，缺失/错误 token 被拒，合法 TrafficAccessToken 可执行所需文件操作 | 检查代理直连绕过 |
| O6 网络 | 默认出站关闭，测试已授权的探测目标不可达；元数据/控制面/IPv6等绕过失败 | 隔离网络；不扩大允许列表 |
| O7 配额/超时 | 有界测试触发 deadline；进程树可确认终止，资源回收；单 VM 限额实效可读 | 不以 SDK 超时代替取消 |
| O8 Host Mount | 禁止路径和逃逸路径拒绝；若未开启 host-mount，明确记录禁用及拒绝证据 | 不临时开放父目录 |
| O9 未知结果 | 有界模拟客户端断连，查回原资源或进入待对账；不盲目再建竞争实例 | 收集关联记录 |
| O10 计算故障 | 仅停止本轮 Cube 执行服务，MinIO 保持运行，已提交输出仍可读，恢复不重复创建 | 不关闭整机或旧业务 |
| O11 脱敏/收尾 | 凭据不入日志/报告，旧业务回归正常，测试资源逐个登记处理 | 保留受限记录修复 |

资源耗尽测试必须有硬上限和节点预留；本阶段不在共存节点运行无界 fork/OOM。
全机故障不在本轮执行。Cube 与 MinIO 同在 `.172`，O10 不证明存储高可用。
M0 只验证基础设施和 SDK；Broker fencing、Work 提交与消息幂等在后续切片验收，
不能将 PoC 成功计为那些尚未实现的合同通过。

## 6. 故障处理与回滚

| 现象 | 处理 |
| --- | --- |
| 无 KVM / vmx=0 | 管理员处理 vSphere；不安装 PVM 绕过本轮决策 |
| XFS/bpffs 未满足 | 补充系统变更方案，不格式化现有业务盘、不跳过检查 |
| 8089/22589 冲突 | 改 Cube 端点及全部引用并重做矩阵；原进程保留 |
| 内核/Guest 元数据不匹配 | 停止模板构建，报告差异，不自动使用另一个 release |
| SDK 无所需只读/认证行为 | BLOCKED，保留锁版事实，不改为无鉴权或读写卷 |
| Volume 删除 409 / 节点 refcount 可疑 | 核实真实 attachment，不能强删 |
| 安装影响既有业务 | 停本轮新增服务，按记录恢复本轮配置；通知原业务负责人 |
| Cube 创建结果不明 | 查证关联资源；不重复创建；进入受限对账 |

回滚只停止本轮新增的明确服务/容器，恢复经备份的本轮配置。MinIO 数据卷和
测试证据保留为受限归档，不删除共享目录、不清空 Docker、不重写生产仓库。
测试 VM 可按 ID 清理；Volume/桶删除前确认无引用并获准，报告可恢复性。

### 10.4 执行中暴露并修复的缺陷（真实平台首测）

1. **监督无法锚定 deadline（O7 首测失败→修复→复验）**：平台 startedAt
   为纳秒精度（9 位小数）；Python 3.10 的 fromisoformat 仅支持 3/6 位
   →解析 None→只告警不终止（沙箱滞留 9 分钟，超出 120s 合同）。
   修复：_parse_epoch 归一化小数到 6 位；新增 2 回归测试（合计 **49
   passed**、ruff 全绿）；重部署后监督当场击杀滞留沙箱，后续两例均
   T+120~122s 精确终止。教训：**测试环境 py3.13 与部署环境 py3.10 的
   标准库行为差异**逃过九轮评审——部署目标版本必须进测试矩阵。
2. **模板分发下载撞 8089（构建 #1–#9 反复 sha mismatch）**：cubelet
