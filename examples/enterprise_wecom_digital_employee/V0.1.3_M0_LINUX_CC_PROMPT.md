# v0.1.3 M0 Linux CC 双机准入预检任务

以下内容可直接交给 Linux CC。先执行只读预检，形成部署依据；本任务不包含安装。
本轮只读任务已由 Linux CC 于 2026-09-06 完成，结论 PARTIAL；以下保留原任务。
后续以 [M0 验证手册](V0.1.3_M0_CUBESANDBOX_VERIFICATION.md) 为准。
没有指定环境的登录能力时，报告该检查未执行，不要求使用方发送密码或密钥。
提示词可独立使用；配套文档尚未同步到 Linux 时，以此任务范围为准。

## 提示词

你负责 AgentSeek enterprise-wecom v0.1.3 M0 的 Linux 环境准入预检。
用户已审阅通过 CubeSandbox 单后端架构和以下两机拓扑：

- 192.10.50.171：现有数字员工 Gateway，未来部署独立 Execution Broker。
- 192.10.50.172：独立 CubeSandbox 测试节点。

本轮目标是提交可复核的环境报告和锁版候选，不安装、不重启、不改配置，
也不进行压力测试。现有企微实例保持运行。Broker 尚未开发，不尝试启动它。

一、核验实际访问位置与仓库

记录本机主机/IP/时间，能访问哪些节点、使用的普通账号及权限等级；不输出凭据。
如果仓库已存在，记录 branch、HEAD、tracked 是否干净，不切换现网工作树。
可阅读 V0.1.3_EXECUTION_ISOLATION_PLAN.md 和 V0.1.3_M0_SANDBOX_ADMISSION.md；
若尚未同步，注明缺失并按本提示词继续预检，不据此改变生产分支。

二、只读核验 .172

1. OS、内核、CPU 架构、裸机/虚拟机类型、CPU/可用内存/可用磁盘。
2. /dev/kvm 是否存在、设备权限及当前账号是否可访问；记录虚拟化支持信息。
   设备存在仅表示前置条件，不能判定微虚机已可运行；禁止加载模块或更换内核。
3. cgroup 版本与可用控制器、当前资源占用、是否已有业务进程。
4. 已安装 Cube/容器运行时/对象存储及版本，仅报告相关服务与监听地址端口。
5. DNS、时间同步、代理使用情况及获取官方制品的网络条件；代理只报配置有无，
   不打印环境变量、认证 URL 或配置全文。
6. 普通账号、sudo 是否可用，以及后续安装应由谁执行；不修改用户、组或权限。

三、只读核验 .171

1. 当前 Gateway 的代码版本、监听端口和已知 health 端点状态，记录 PID；
   不读取或输出进程环境、.env、完整命令行与业务日志正文。
2. 剩余 CPU/内存/磁盘，未来 Broker 的独立账号/目录是否已有规划。
3. 到 .172 的路由/DNS 条件；只测试已确认正在监听的必要端点，禁止端口扫描。
   未安装服务的端口未监听属于“部署后验证”，不判网络缺陷；ping 也不作为
   应用接口可达性证据。
4. 后续需同时验证 CubeAPI 与文件数据代理，不能只测控制面成功就判文件链路通过。

四、存储与版本候选

1. 确认是否已有可用的私有 S3 兼容测试存储，记录产品/版本/部署位置与测试桶
   的准备状态，不列业务对象、不创建桶、不索取主凭据。
2. 若暂无存储，提出在 .172 测试部署与使用独立既有存储的取舍，不自行安装。
   若同在 .172，明确整机掉线同时影响计算与存储，不宣称独立存储高可用。
3. 查询 Cube 官方 release、原生 Python SDK、Volume 插件兼容要求，给出一组
   明确的版本候选及官方来源；不使用 latest 作为锁版结果，不执行远程安装脚本。
4. DeepAgents 保持项目当前 0.6.12；Cube 只读 Volume 使用原生 SDK 的实际支持
   版本核验，不假定任意 E2B SDK 可兼容。
5. 列出候选部署必须启用的 API/数据面鉴权、TLS、默认拒绝出网、资源限制；
   此处只设计，不改防火墙。需额外安装或系统变更的条件单独列出。

五、反馈格式

- 预检结论：READY-FOR-POC / BLOCKED / PARTIAL，并列判断依据。
- 两节点逐项环境表：实测事实、缺失项、未执行项分别列出。
- Cube/SDK/template/plugin/存储版本候选，注明尚未锁版及未验证内容。
- 后续安装步骤的范围：目标节点、预期变更、必要端点、回滚和清理方式。
- 需要管理员处理的具体事项；不要仅写“环境正常”。
- 边界确认：未安装、未改内核/防火墙/.env/数据库、未重启现有网关、未上传凭据。

报告只包含脱敏摘要。若有独立验证分支可按既有流程追加记录；否则直接反馈文本，
不为保存报告修改 production/tag，不提交日志、数据库或 runtime。
READY-FOR-POC 只代表前置条件满足，不代表 M0 PASS。
收到评审后的部署指令，再在 .172 执行锁版安装和最小 PoC；不进入 M1。
