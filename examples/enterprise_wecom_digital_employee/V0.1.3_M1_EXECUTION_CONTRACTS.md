## 2. 数据对象

| 对象 | 字段及语义 |
| --- | --- |
| Scope | tenant / digital_employee / conversation / requester；可信身份上下文 |
| Task | task_id / scope / 可选 work_id+phase；DirectTurn 不创建 WorkItem |
| Execution | execution_id / task / inputs / template_version / policy_version；重试不能更改合同 |
| Lease | execution_id / attempt / owner / fencing / expires_at / base_revision / create_token |
| InputManifest | schema_version=1；FileEntry + grant_id；tuple 固定，输入路径不得重复或父子冲突 |
| FileEntry | file_id / version / path / sha256 / size / media_type；ID 和摘要均不授予权限 |
| OutputManifest | schema_version=1；候选文件 tuple；摘要以下载后的实际 bytes 重算 |
| WorkspaceRevision | task_id / revision / parent / execution_id / attempt / manifest / commit_token |
| ExecutionOutput | WorkspaceRevision 内已登记文件；不是 Artifact、审批、发布或送达凭证 |

稳定 task 跨执行续接；execution 的 attempt 从 1 递增。task 的 fencing 单调递增。
任务 ID 在账本内唯一；同 ID 不同 scope/Work 合同拒绝。ID 应由服务端分配。
重试保留前一 attempt 快照；成功执行不原地重试，下一执行使用新 execution_id。
工作区 revision 首版为完整 manifest，不是增量 patch；连续执行继承上次已提交父版本。

## 3. 授权端口

| 检查 | 执行点 |
| --- | --- |
| actor 与 task.scope 完全相符 | start / submit / cancel |
| task_allowed | Authority 服务端任务注册与准入校验 |
| work_allowed | 有 work_id 时同时校验 scope、phase 与 Work 权限；真实状态适配未接入 |
| file_allowed | 完整文件版本和 grant 校验；过期、撤销、错所有权均拒绝 |
| verify_execution | submit / cancel 请求必须与持久化 execution 指纹一致 |

FakeAuthority 仅为测试夹具，不能注册为生产权限源。
单可信调用方下仍包含其他员工、群、数字员工和租户的伪造请求负向测试。
真实跨身份 Cube 资源授权 O4b 留在 M2/Broker，不据此计通过。

## 4. 状态与写入约束

```text
未登记 → preparing → running → exporting → validating → committing → succeeded
活动态 → cancel_requested → cancelled（停止已确认）
结果不确定 → reconciling → failed/cancelled（可信停止对账后）
已知失败 → failed（仍占写入资格，直到确认停止）
```

- 准入前无账本 pending 行；持久化 preparing 与 create_token 后才调用 Provider。
- lease 过期禁止提交，不自动释放 active 或启动第二 writer。
- `reconcile_stopped` 可在 lease 过期后完成对账，但必须提供可信停止证据。
- token 不是鉴权凭据；所有调用先经过可信服务层授权。
- 事务提交同时核对 owner、attempt、fencing、create_token、lease、父 revision。
- 同一提交 token 与相同 manifest 返回原 revision；不同内容或其他 attempt 拒绝。
- succeeded 重放仍重新授权，可在原 lease 过期后返回已提交结果，不执行脚本。
- 对象成功写入后才能提交账本；对象与 SQLite 不声称具有分布式事务。
- 对象写后事务失败保留未发布对象；重试以幂等内容写入继续。
- 导出期间写入者必须停止；Fake 用 stopped 状态模拟，真实进程树证据留 M2/M3。

## 5. 错误分类

| Code | 含义 | 重试政策 |
| --- | --- | --- |
| authorization_denied | 身份、任务、Work 或文件授权拒绝 | 不自动重试 |
| invalid_contract | 非法路径/manifest/摘要/配额 | 修正输入后重新请求 |
| write_conflict | 单写竞争、过期 lease、旧 fencing、提交冲突 | 不抢占、不覆盖 |
| outcome_unknown | Provider 创建/取消或持久化确认未知 | 保留状态，受控对账 |
| execution_failed | 已知执行失败预留类别 | 当前 Fake 不执行脚本；真实分类留 M2 |

异常正文只返回分类码，不回显输入或底层凭据。底层异常链属于内部诊断，
M2 暴露服务时必须统一脱敏；不能直接输出 traceback 给用户。
SQLite 和 Content Store 的底层异常允许传播给可信调用方，不能转成 succeeded。
本轮不实现网络重试器；“已知暂时失败”映射留 Provider 适配阶段明确，禁止将未知统一重试。
