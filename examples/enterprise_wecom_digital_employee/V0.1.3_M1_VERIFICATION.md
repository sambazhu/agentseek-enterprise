# v0.1.3 M1 离线合同复验

## 前置

- 使用独立检出的 M1 功能分支，不切换生产网关工作目录。
- 从仓库根运行；仅使用合成数据，不加载 .env。
- 准备 uv 和 Python 3.10/3.13。解释器及工具首次下载需要网络；测试自身无需网络。
- 不安装 Cube SDK，不操作 .172，不改 M0 运维件，不访问共享数据库。

## 执行

1. 执行两套解释器测试。pytest 临时目录承载 SQLite，现网文件不在范围。

   ```bash
   uv run --no-project --python 3.10 --with pytest==8.4.2 pytest -q contrib/agentseek-execution/tests
   ```

   ```bash
   uv run --no-project --python 3.13 --with pytest==8.4.2 pytest -q contrib/agentseek-execution/tests
   ```

2. 检查静态门禁。Ruff 必须显式 no-fix，避免修改工作区。

   ```bash
   uv tool run ruff check --no-fix --target-version py310 contrib/agentseek-execution
   ```

   ```bash
   uv tool run ruff format --check contrib/agentseek-execution
   ```

   ```bash
   uv tool run ty check contrib/agentseek-execution/src --python-version 3.10
   ```

3. 核验补丁空白与工作区。不要将临时测试文件加入版本控制。

   ```bash
   git diff --check
   ```

### L4. 五专题定向复核（实现落点 + 突变抽查）

实现落点核对（源码通读）：

1. **授权负向**：`Service.start/submit/cancel` 首行 `authorize()`
   先于任何 Provider/账本副作用；四维 scope 伪造在 provider.create 之前
   以 DENIED 拒绝（`provider.create_calls == 0` 断言）；
2. **单写**：`Ledger.begin` 在 `BEGIN IMMEDIATE` 事务内检查
   `tasks.active IS NULL`；lease 过期不放行写入、不自动释放 active、
   不启动第二 writer（`single_writer_expiry...` 断言 create_calls 恒 1）；
3. **旧 fencing 拒绝**：`_current()` 校验租约五元组
   （attempt/owner/fence/base/create_token）全等 + `tasks.current_fence`
   与 `tasks.revision`（commit 侧 base 校验）三道防线；
4. **未知结果对账**：Provider 创建/取消异常 → 状态落 `reconciling`、
   active 保留（writer 资格不释放）；`reconcile_stopped` 强制
   `confirmed=True`（可信停止证据）才置 failed/cancelled 并释放 active；
5. **事务回滚与幂等重放**：`transaction()` BEGIN IMMEDIATE + 异常
   ROLLBACK（测试以 SQLite 触发器注入 mid-commit 失败，断言 revisions
   0 行、对象保留、重试收敛）；重放防护分两层——**Service** 侧
   `verify_execution` 校验请求 execution 指纹与持久化指纹一致；
   **Ledger.commit** 对已存在 token 校验租约五元组及
   （execution_id, attempt, manifest）全等才返回原 revision，内容
   不同即拒。【勘误（收官轮，按 Codex 复核意见修正）：原文把指纹
   校验并入 commit() 的 token 重放路径表述，两层职责归属不清；
   历史原文见 d52dd5f。】
