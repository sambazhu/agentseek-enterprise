# v0.1.3 M2 Broker 切片与验收合同

## 1. 状态

| 项 | 内容 |
| --- | --- |
| 基线 | M1 收官 4a7e76f；分支 enterprise/v0.1.3-execution-broker |

## 2. 已批准切片

| 切片 | 交付 | 判定条件 |

## 3. M2.1 已实现接口

| 接口 | 约束 |
| --- | --- |
| Principal | 服务端 principal_id 与精确 Scope 集合；调用方不能注册自身授权 |
| CredentialRegistry | 服务端预配高熵 API key；仅保存摘要；禁止覆盖已有凭据；支持撤销 |
| creation_scope | 凭据认证后验证 tenant/DE/conversation/requester；返回服务端 Scope |
| Resource | Broker 公开 ID、principal、Scope、内部 backend_handle；句柄不进入 repr |
| OwnershipStore | get/owned 端口；SecureOwnership 提供加密持久化；访问门禁另有内存夹具 |
| resource | connect/execute/read/write/cancel/delete 均检查 principal 与 Scope；未知/越权统一 DENIED |
| list_ids | 仅返回己方公开 ID；对仓储返回内容再次过滤，不泄露平台 ID |
| volume | 初版接口关闭，认证后仍拒绝；不计为卷授权操作已验证 |

Resource 返回值只用于 Broker 内部，不能直接序列化给请求方。
凭据注册/资源登记接口只能由可信启动与创建流程调用，不是远程端点。
库方法返回后与实际 Provider 调用之间的授权绑定、撤销竞争、创建幂等及资源登记事务，
仍需完整 Broker 入口实现验证；不能以此库独立宣称端到端安全。

### 4.1 加密资源归属库增量

| 项 | 当前实现 |
| --- | --- |
| 可选依赖 | broker extra：cryptography==49.0.0；M1 模块仍只依赖标准库 |
| 数据 | Resource 的身份、作用域、平台句柄整体 AES-GCM 加密；随机 96-bit nonce |
| 完整性 | AAD 绑定记录索引、owner 索引和格式版本；记录互换/修改拒绝 |
| 查询索引 | 独立用途 HMAC 索引，不存原始 ID；不是授权凭据 |
| 初始化 | 专用 0700 目录、0600 单链接普通文件；拒绝符号链接、不自动放宽已有权限 |
| 密钥 | 独立预配 32 字节二进制文件；缺失/错误/长度不符拒绝；不写入数据库 |
| 注册 | BEGIN IMMEDIATE，相同映射幂等；同 ID 不同映射拒绝覆盖 |
| 重启 | 加密格式校验后恢复；错误密钥无明文回退 |
| 限制 | 不防 root/同 UID 内存访问及完整数据库回滚；未实现轮换、备份恢复或执行账本加密 |

## 5. 后续准入与风险边界

### 5.1 执行账本加密增量

| 项 | 当前实现 |
| --- | --- |
| Codec | M1 Ledger 增加存储编解码接缝；默认仍为原明文离线参考实现 |
| SecureLedger | HKDF 域隔离子密钥；AES-GCM 加密 owner/create_token/manifest/history |
| 绑定 | 加密字段绑定 execution_id、attempt、字段名，跨记录替换拒绝 |
| 幂等 token | AES-SIV 确定性认证加密，支持唯一索引；同值关系可见，不暴露原 token |
| 数据库 | SQLite 事务不变，DELETE journal + FULL synchronous；0700 目录、0600 文件 |
| 兼容 | 明文旧库非空时拒绝接管；不自动迁移 M1 或任何线上数据 |
| 索引 | task/execution 必须为服务端生成的 UUID hex；状态、时间、fencing、revision 和摘要明文可查询 |
| 限制 | 非 SQLCipher；不认证全部数值/状态列，不抵御整库回滚或同 UID/root 改写；需专用可信目录 |

新增 5 项加密账本测试，包括重启后幂等重放、错误密钥、明文旧库拒绝、
跨执行密文替换、旧 lease 拒绝、历史加密及事务中途回滚。
M2 当前全量为 86 项，Python 3.10/3.13 本地均通过；不计实机验收。

### 5.2 后续门禁

本地 SDK worker 增量：

- run_worker 仅执行可信 Broker 预置命令，不接受模型或外部请求提供 argv。
  无 shell；请求经 stdin 传递，环境由服务端显式提供，不继承整个网关环境。
- 非阻塞管道 + 单调总截止覆盖输入发送、输出读取和退出等待；输入 64KiB、输出 1MiB。
  stderr 不回传，退出非零/超时/超限均按 outcome_unknown；本层不重试远端操作。
- finally 清理本地进程组并有界等待。此层不是恶意宿主代码沙箱；
  不保证捕获主动脱离进程组的恶意程序，也不证明远端 VM 停止。
- OS 进程创建本身不能由此函数强制中断，清理最多另加 1 秒等待；
  不把结果宣传为任意故障下精确硬实时截止。
- 新增 13 项测试：环境隔离、双向管道、挂起/滴流/关闭 stdout 后挂起、
  输入阻塞、输出超限、非零退出脱敏、子进程持管道、非法预算。
  当前全量 110 项；仍未接入真实 Cube。

锁定 SDK 本地源码核对（cubesandbox==0.7.0，未连接现场）：

- Sandbox.create 默认为 allow_internet_access=True；适配必须显式关闭并指定 restricted。
- 控制面请求未传 request timeout，必须由外层 worker 总截止约束。
- Sandbox.traffic_access_token 属性说明：token 仅在原 create 响应提供，
  connect/resume 返回实例不保证带 token。创建回执需加密持久化；
  响应丢失后的 token 恢复能力仍待适配和实测，不得假设 connect 自动补齐。
- timeout 是空闲 TTL，不替代执行期限。真实 worker 入口/回执/对账尚未实现。

时钟与入口增量（本地 97 项、无跳过）：

- BrokerClock 使用服务器 wall/monotonic 与加密高水位；运行中回拨不延长租期，
  重启时 wall 落后于持久化水位则失败关闭。不是 NTP 证明，不防整库回滚。
- serve_unix 为受控本地监听函数；要求预配 0700 目录，Socket 0600；
  不自动删除已存在路径，退出仅清理本次 inode。尚无部署 CLI/systemd 单元。
- 每连接一个 JSON 行，请求和响应各限 64KiB；Socket I/O 使用单一总预算。
  重复键、额外身份/时间/模板字段、批量追加报文、非法输入统一拒绝。
- Dispatcher 目前只开放认证后的 list/inspect，响应仅公开资源 ID。
  create/execute/cancel/delete/volume 尚不开放；不能记为生命周期接入完成。
- handler 同步执行；I/O 预算不约束任意 handler 计算或 SDK 阻塞。
  真实 Cube 调用必须另走受监督 worker，不能直接接入本 inline handler。
- 新增测试包含真实本机 UDS 收发与清理、慢输入截止、超长请求/响应、
  异常脱敏、身份字段注入拒绝、时钟回拨/前跳/重启/篡改。

- O4b 分别记录 Broker A/B 授权与 Cube 原生授权，不互相替代。
- 平台主凭据仅供 Broker；客户端不得获得绕过 Broker 的控制/数据面能力。
- 无法证明共享平台隔离时采用分区或阻断，不以名称/metadata 标签替代权限。
- M0 的 TLS、restricted、资源及 preflight 保持原状；Broker 通过受控门禁接缝检查。
- Broker 与 M0 监督器的资源管理集合必须显式登记，避免双重管理和孤儿资源。
- M2 只运行合成文件及固定命令；真实文件提交/扫描归 M3，真实 Agent/企微归 M4。
- 持续保存 M0 镜像扫描豁免、egress 根因未定和存储故障域限制。
