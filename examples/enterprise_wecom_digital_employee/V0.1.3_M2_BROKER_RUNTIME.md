# M2 Broker 部署候选接口与运行合同

## 1. 状态与范围

| 项 | 合同 |
| --- | --- |
| 发布对象 | `enterprise/v0.1.3-execution-broker`；基线 M1 收官 `4a7e76f` |
| 状态 | 本地候选，交 Linux 安装评审及真实 VM 验证；不是 M2 PASS |
| 入口 | .171 独立单进程 Broker，UDS，0700 运行目录、0600 Socket；不新开 TCP |
| 后端 | cubesandbox==0.7.0，Cube 服务端/模板沿用 M0 锁定实测基线；不升级平台 |
| 身份 | 两个服务端预置 API Principal，各一个精确 tenant/DE/conversation/requester Scope |
| 负载 | 仅合成 DirectTurn/Work 请求和固定命令；不触发真实 Agent、企微、Work 数据库 |
| 容量 | 全局最多一个未确认停止的执行，含 creating/reconciling；忙时拒绝，不排队 |
| VM | 每 execution 独占 VM，固定模板 1 vCPU/1GiB；120s 服务端期限，不允许请求修改 |
| 资料 | `/tmp/agentseek-m2.txt` 固定合成文件；没有任意路径/上传/下载/Volume/发布接口 |
| 后续 | 通用文件与版本提交 M3；真实 DirectTurn/Playbook Tool 接入 M4 |

M0/M1 PASS 不替代本轮。O4b 仅对本轮开放的 Broker 资源操作验收；
Volume 接口关闭，只能记“越权/未实现能力拒绝”，不能记授权挂载成功。
底座扫描豁免≠已评估；egress 根因和同机存储故障域沿用 M0 遗留。

## 2. 配置字段

配置文件必须为当前服务 UID 所有的 0600 单链接普通文件；不加载 `.env`。
完整样例见 [部署配置](m2_broker/broker.example.json)，所有路径/身份均为占位示例。

| 字段 | 约束 |
| --- | --- |
| runtime | 绝对规范路径；专用 0700 目录；UDS 完整路径建议少于 100 字节 |
| encryption_key_file | 独立 32 字节二进制密钥，0600；不是 hex 文本 |
| cube_key_file | M0 控制面 X-API-Key 文件，ASCII 32–256 字符，可有一个末尾换行；0600 |
| api_url | M0 控制面 HTTPS 地址；禁止 HTTP、URL 凭据、query、fragment、业务路径 |
| ca_file | 可信 CA 文件绝对路径；worker 设置 REQUESTS_CA_BUNDLE/SSL_CERT_FILE，不支持跳过校验 |
| template_id | M0 已验 READY 模板精确 ID；安装前复核 artifact digest、CPU/内存与 writable layer |
| proxy_port | .171 数据面 TLS 转发器 loopback 端口；整数 1024–65535；不改变 M0 转发器 |
| sandbox_domain | M0 锁定 SDK/Host 路由域名，不能据示例臆填 |
| run_id | 本轮部署固定标记；须与 .172 独立 M2 监督 manifest 完全相同；重启不换值 |
| principals | 恰两个 `{id,key_file,scope}`；key 独立生成，与 Cube/加密材料不同；不提供公开注册 API |
| preflight_command | 可信宿主绝对可执行文件及固定参数数组；非 shell 字符串；最长 10s；成功只输出 READY |

`--check-config` 只检查配置结构，不证明密钥有效、平台可达、模板正确或监督存活。
底层 Cube 凭据、TrafficAccessToken、实际 sandboxID 不下发给 Broker 客户端。
CLI 只从私有文件读取客户端 key，不接受命令行明文 key。

## 3. 请求与返回

协议：每连接一个 JSON 行，单请求/响应各 64KiB；所有额外字段拒绝。
未知、越权、参数错误和内部错误在线路上统一 `request_rejected`。
无端点接受调用者提供的 now、owner、lease、template、scope 或任意 shell。

| method | 除 key/method 外的字段 | 成功结果 |
| --- | --- | --- |
| list | 无 | 仅当前 Principal 且当前 Scope 匹配的资源摘要 |
| create | request_id=UUID hex，kind=direct/work | resource_id、task_id、kind、state、execution_state、deadline |
| inspect | resource_id | 本地账本摘要；不等同平台健康探针 |
| connect | resource_id | 平台 get_info 验证归属且 running；不调用可能恢复暂停 VM 的 SDK connect |
| execute | resource_id | direct 固定 printf M2_DIRECT_OK；work 固定 printf M2_WORK_OK |
| write/read | resource_id | 仅固定合成 `/tmp/agentseek-m2.txt` 写读，不支持客户端路径 |
| slow | resource_id | 固定 sleep 130；用于超时/失联验证，预期不会正常完成 |
| cancel/delete | resource_id | 平台查无此资源后 stopped；重放停止幂等 |
| volume/其他 | 任意 | 拒绝；未实现，不构成平台 API 透传 |

create 的 request_id 应在请求前保存；回执丢失重发同一值，不能生成新值。
同 Principal/request_id 返回同一执行，不重新建 VM；kind 冲突拒绝。
普通 direct 不产生 work_id；work 仅记录服务端生成的 `m2-synthetic-*` 引用与 probe phase。
固定命令完成不是工作成果发布；本轮通过停止对账回收，ledger 终态为 cancelled，
不是 M3 manifest 提交或真实 Work 完成。

## 4. 状态、回执与失败

| 状态/事件 | 处理 |
| --- | --- |
| reserved | 先持久化意图；尚未调用 SDK create；重启可安全关闭该意图 |
| creating | M1 租约落盘后先标记，再调用一次 SDK；占用容量 |
| created 响应 | worker 先加密保存 `_data` 必需回执，再向 Broker 确认；Token 缺失拒绝成功 |
| running | 当前 lease/fencing/期限通过后才允许固定命令 |
| worker 非零/超时/回执异常 | outcome_unknown→reconciling，保留 writer/容量，不重试命令或再次创建 |
| 已知回执恢复 | Sandbox(receipt,config) 本地重建；get_info 校验 run/create-token/template；不恢复旧命令 |
| 创建回执丢失 | list 后逐条 get_info；仅 run_id + 唯一 create_token 全等资源可认领停止 |
| 零匹配/多匹配/平台不可达 | 不能证明停止，继续 reconciling，阻止新建；不得手改为已停 |
| delete | 删除后 get_info=404 才记停止；已有句柄 get_info=404 也可确认；未知结果不释放容量 |
| 重启/优雅退出 | 清理而非重跑所有旧活动执行；SDK 不可达则保留对账状态 |

CubeJournal 敏感记录整体 AES-GCM；SecureLedger 敏感字段加密。
两 SQLite 库不是分布式事务；reserved/creating 分界及原租约恢复用于断点对账。
公开 UUID、状态、时间、revision 等仍可查询；不防同 UID/root 篡改或整库回滚。
平台元数据是可信 Broker 的资源认领证据，不是面对平台管理员的授权凭据。

## 5. 时间与进程边界

| 层 | 机制及限制 |
| --- | --- |
| SDK worker | 独立 Python 子进程、固定 argv、显式环境；10s 总预算，超时 kill 进程组；清理可另加 1s |
| 数据请求 | SDK command timeout=5 作为内层提示，不替代外层总截止 |
| UDS | 请求 I/O 预算 25s；响应后 SHUT_WR，再最多64KiB/50ms drain，且不超过原剩余预算；慢输入会延迟巡检 |
| 本机巡检 | 空闲约 1s 周期；期限到达尝试停止；受在途请求/SDK 调用影响，不保证恰在120s删除 |
| 节点监督 | .172 必须启动独立 M2 run 的既有监督代码，120s 期限与已验轮询预算；Broker 消失仍生效 |
| 同故障域 | .172 控制面不可达时监督也不能保证销毁；保持告警、拒建，按 M0 停止条件处理 |
| Socket 恢复 | flock 单实例；仅回收加密登记 dev/ino 完全相同的旧 Socket；其他文件/未知 Socket 拒绝 |

进程锁与 0600 UDS 是可信宿主约束，不是两个恶意 Linux 用户的隔离演示。
A/B 是 Broker API 身份，由可信测试驱动发起；root/服务同 UID 不在威胁模型内。
响应后 drain 只丢弃输入，不解析、不再次调度；写半关闭避免等待EOF的客户端与服务端互等。
超出清理字节/时间上限的持续恶意输入仍可能导致连接重置，不保证任意流量下错误响应可达。
原超限请求 Oracle 保持必须收到 request_rejected，不以接受 RST 改判。
O4b 不得写成“Cube 原生多租户授权 PASS”。不可信客户端不能获得宿主同 UID 执行能力、
Cube API key、数据 Token 或可绕过 Broker 的代理权限。

## 6. 本地证据与现场待验

本地测试：授权矩阵、事务/加密/时钟、生命周期 Fake、真实本机进程/UDS、
锁定真实 SDK + 模拟 Cube HTTP、受监督 worker 挂起/滴流/清理。
SDK commands.run 的测试替身只验证固定命令与 Token 构造，不证明真实数据面发送。

现场必须验证：真实模板/SDK 字段、restricted 三态、TLS 两跳、A/B 真实资源、
实际文件隔离、API失联/回执丢失/进程崩溃后的唯一资源收敛、期限和宿主 shim/TAP 回收。
入口、清单和逐项 Oracle 见 [Linux 部署复验手册](V0.1.3_M2_BROKER_VERIFICATION.md)。
