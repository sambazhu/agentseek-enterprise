# M2 Broker Linux 安装与真实沙箱复验

接口及边界见 [运行合同](V0.1.3_M2_BROKER_RUNTIME.md)。
本地已验证 CLI、双解释器离线测试和模拟平台；本文现场命令未在 .171/.172 执行。

## 1. 先核对基线，提交安装变更清单

1. 在 .171 建独立 worktree，拉 `enterprise/v0.1.3-execution-broker`；
   记录完整 HEAD、双端 ls-remote、`4a7e76f` ancestry、diff --check。
   不切生产网关主仓、不动 production/tag、不改 `.env`。
2. 保留 .171 的 :12000/:12001 网关与 M0 数据转发器，核验 PID/health。
   核对 .172 M0 preflight 6/6、模板 READY/artifact digest、8 容器、双栈管理面拒绝、业务 :8089。
3. 逐项登记下表的真实路径、UID、端口、资源额、服务及回滚命令；
   用户确认本轮新增项后才能安装。既有安装授权不自动扩大到 M2 服务。

| 节点 | 仅允许新增/使用的对象 | 约束 |
| --- | --- | --- |
| .171 | 独立 worktree、M2 venv、Broker 私有配置和运行目录、UDS、一个 systemd 单元 | 不复用网关 venv/SQLite/密钥；服务预算 512MiB/1 CPU/64 tasks |
| .171 | 既有 TLS 控制入口和数据面 loopback 转发器 | 不新开 TCP，不停/改 M0 转发器；不可用先报 BLOCKED |
| .171→.172 | 新专用受限 SSH gate 身份、固定远端 preflight | host key 预核对；无口令 argv；不得绕开原网络限制 |
| .172 | M0 监督/preflight 原代码的独立副本、M2 manifest/alarm/heartbeat、新监督进程 | run_id 独立；不修改 M0 运维代码/现有实例，监督预算建议128MiB/25% CPU |
| .172 | M0 已验固定模板、每轮一个 M2 VM | 1 CPU/1GiB/120s，不能升级平台、模板、内核或改网络策略 |

SDK 0.7.0、cryptography 49.0.0 固定；安装后 `pip freeze`/解释器版本登记。

## 4. 执行逐项 Oracle

使用安装好的 `broker_probe` 或可信测试驱动 `exchange()`；密钥从私有文件读取。
create 前先生成、保存一个 UUID hex request_id；响应丢失仅重放该 ID。
下例 ID 是明确合成示例，正式每个用例另生成并保留，不跨轮复用：

```bash title="not executed in this run"
/ABS/M2_VENV/bin/python -I -m agentseek_execution.broker_probe --socket /var/lib/agentseek-m2-broker/broker.sock --key-file /etc/agentseek-m2-broker/client-a.key create --request-id 11111111111141118111111111111111 --kind direct
```

```bash title="not executed in this run"
/ABS/M2_VENV/bin/python -I -m agentseek_execution.broker_probe --socket /var/lib/agentseek-m2-broker/broker.sock --key-file /etc/agentseek-m2-broker/client-a.key execute --resource-id REPLACE_BROKER_RESOURCE_ID
```

修改 method 可依次 connect/write/read/delete；全部使用 Broker resource_id，不用 CubeID。
probe rc=0 为成功；拒绝 rc=3；连接/客户端错误 rc=2。单条终态以 `ok` 和平台证据共同判断。
长任务超时的 rc=2/3 不能记执行成功；需继续确认 VM、ledger 和容量收敛。

| Oracle | 操作与 PASS 条件 |
| --- | --- |
| B0 环境/安装 | 本轮独立目录、UID、venv、监督 run、配置、基线与6/6门禁齐备；原服务无变化 |
| B1 创建策略 | A direct 真 VM；模板/CPU/内存/120s策略/restricted/拒出网与 M0 一致；元数据 run/token 已留痕；不新增 WorkItem |
| B2 固定执行/文件 | A connect、execute=M2_DIRECT_OK、write/read=M2_FILE_OK；实际 Token 经 TLS 数据面；无明文跨机能力传输 |
| B3 O4b A/B | B 对 A inspect/connect/execute/read/write/cancel/delete 全拒绝，A VM/文件不变；B list 不含 A；A→B 对称重复；未认证/原始CubeID/额外scope/template/volume全拒；服务主凭据不能充当客户端key |
| B4 幂等/容量 | 同 key/request_id create 回放 resource 相同，平台create恰一次；第二请求不新建；删除确认后 B work 才创建并返回M2_WORK_OK；B新VM初始无A合成文件（只读探针失败后需对账回收） |
| B5 恢复 | 创建/执行成功后 SIGTERM 或进程组 SIGKILL；保留库/密钥/run；重启对账原VM停止、不重跑命令、不新建、旧request_id稳定；误删旧Socket以外文件必须拒绝 |
| B6 硬截止 | slow 后停止整个 .171 Broker 单元（含worker），保持 .172 M2监督；平台 startedAt 对齐120s，按 M0 有界偏差击杀；404/终态 + 对应shim/TAP归零；Broker重启后 writer释放且可新建 |
| B7 未知结果 | 限定本轮worker的测试接缝抑制create响应，不改共享代理；平台原资源标记存在，恢复按唯一run/token认领删除、不再次create；若无/多匹配必须保持reconciling，不能假记stopped |
| B8 门禁/网络/权限 | M2 gate告警/心跳过期/SSH不可达拒新建；错误控制key、错误CA不成功且不泄密；restricted正确/缺失/错误token三态；外部管理端口v4/v6仍拒；Cube不可达不释放容量 |
| B9 收尾 | M2无活动/未知VM、shim/TAP；journal/ledger对账终态；Broker日志/公开输出的凭据与真实句柄0命中，journal敏感字段无明文；原网关PID/health与M0限额/服务不回退 |

对 B7 的故障注入必须先写限定目标、方式与回滚点，禁止改全局反代、关共享网络或清库。
可用独立 worker 测试包装器，在真实 SDK create 回执落库后丢弃 stdout，验证已知回执分支；
无回执分支需额外构造本轮唯一真实资源 + 匹配标记的受控测试夹具，不能删除真实账本字段冒充现场故障。
未做的分支标 NOT RUN/BLOCKED，不用本地模拟代替真实证据。夹具不得进入常驻服务或扩大接口。
如需 SDK/平台未提供的恢复能力，回传缺口，不手改终态、扩大匹配范围或提高上限。

B6 需要临时停用**仅 M2 Broker** 的自动重启，再向该单元整个进程组发送 SIGKILL；
仅执行正常 systemctl stop 会触发 Broker 主动清理，不能证明 .172 的120s独立监督。
在节点监督完成、证据留存后恢复 M2 Restart 策略并启动 Broker对账；
临时覆盖与精确回滚必须纳入安装清单，不改网关或 Cube 单元。

B8 的错误 Cube key/CA 用已获得回执的本轮 VM 做 connect 负向；
恢复正确配置后对账已知 VM。避免在主验证 run 用错误配置 create 制造无法证明未创建的孤立意图。
SDK 失败保守按 UNKNOWN，不把401/SSL异常自动等同“远端没有执行”。
零/多匹配拒绝由定向测试锁定；若现场出现则真实 BLOCKED，不以清空库继续判 PASS。

O4b 的 API 授权验证与宿主操作系统权限分开记录。可信验证账户可以驱动 A/B；
不能声称同 UID/root 不能读取服务文件。不得把“没有下发token”写成 Cube 原生多身份隔离。
Volume 仅未开放拒绝项；真实挂载授权待 M3，不能计入本轮正向已通过。
节点监督/平台受限运维证据可能含资源ID，沿用M0本机受限存储口径；
跨机回传只给哈希/计数，不把这类私有证据复制进Broker公开输出或提交入仓。
