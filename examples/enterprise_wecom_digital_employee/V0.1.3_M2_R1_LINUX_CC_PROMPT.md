## 1. 前置与权限

1. 保留 `4b47755` 所有实测和NOT RUN历史。B9的原PASS须追加勘误：
   平台为零，但一个未知意图仍占容量，账本尚未全终态，不是完整收尾。
2. 固定本轮代码SHA，独立venv升级组件；沿用原M2配置、运行库与密钥，不重建、不迁移。
3. 停止**仅M2 Broker**整个单元，确认SDK worker全零且不会自动拉起。
   保留 .172 M2监督、M0服务与网关。运维CLI的flock只排除另一个Broker，不能证明遗留worker已停止。
4. root核验m2gate精确sudo命令、无通配/SETENV；脚本、导入模块和全部父目录不可由m2gate写入。
   修复不得扩大sudo授权，不改M0代码。

## 2. 恢复配置目录只读

新版将 `read_config`、`load_key`、`load_service_key` 改为O_RDONLY；
仍保留O_NOFOLLOW、属主、0600、普通文件与单链接检查。数据库/锁保持O_RDWR。

1. 撤销M2单元的 `/etc/agentseek-m2-broker` ReadWritePaths例外，保留原runtime写权限。
2. 核验ProtectSystem=strict、ProtectHome、PrivateTmp、NoNewPrivileges等仍在位。
3. 启动M2验证配置/各密钥读取、list、单实例锁。当前未知意图未结案前，新建被拒是预期。
4. 继续离线对账前再次停止M2单元。对账完成后补一次create/execute/delete，证明worker也适配只读目录。
5. 如失败，只回退本轮M2变更；不得永久扩大`/etc`写权限或全局关闭硬化。

## 3. 零匹配意图：先审批证据，再对账

本工具是**单可信PoC下的离线运维裁定**，不是自动平台证明器。
审批文件由具备本机运维权限的可信操作方提供，不是Broker客户端能力。
没有双人签名/审批平台集成。文件摘要只证明内容绑定，不证明证据真实或结论正确。
用户授权开发工具不等于已批准清除当前意图。

允许两类结论：

- `never_admitted`：权威证据证明该次请求没有被平台接纳，且不会在之后完成创建。
- `terminated`：权威证据将该次请求绑定到具体资源并证明已终止，且无待完成创建。

必须同时证明发起方worker已停止、没有仍可发起/完成该创建的请求。
“列表零匹配”“TTL已过”“一次连接异常”“平台count=0”单独均不够。
仅有这些证据时继续BLOCKED；不要填写一个批准JSON绕过缺失证据。
不得为取证停共享Cube或改变全局网络；需要扩大操作范围时另请用户批准。

### 3.1 获取当前绑定

以Broker服务UID执行，不使用root绕过现有文件属主检查；先保全受限证据。
命令不带approval时不释放任何writer：

```bash title="not executed in this run"
/ABS/M2_VENV/bin/python -I -m agentseek_execution.broker_reconcile --config /etc/agentseek-m2-broker/broker.json --resource-id REPLACE_FULL_BROKER_RESOURCE_ID
```

记录返回的resource_id/state/binding。binding绑定原执行、身份Scope、部署、原租约及回执，
不输出create_token或平台句柄；不能拿其他意图的审批复用。

### 3.2 提交证据供用户/维护者审批

准备两份受限证据文件：平台不接纳/终止证明、发起方已静止且无待完成请求证明。
文件必须非空、各不超过1MiB、0600、当前UID所有、绝对规范路径、无符号链接/硬链接。
跨机原始证据只留受限现场，回传内容使用摘要和脱敏事实。

以下审批文件样例**不是有效审批**；示例时间0会被拒绝，不能机械填值后执行：

```json
{
  "schema": 1,
  "resource_id": "REPLACE_FULL_BROKER_RESOURCE_ID",
  "binding": "REPLACE_INSPECTED_BINDING",
  "verdict": "never_admitted",
  "reviewer": "REPLACE_AUTHORIZED_REVIEWER",
  "approval_reference": "REPLACE_EXPLICIT_APPROVAL_TICKET",
  "observed_at": 0,
  "provider_evidence": "/ABS/PRIVATE/provider-evidence.json",
  "provider_sha256": "REPLACE_ACTUAL_SHA256",
  "worker_evidence": "/ABS/PRIVATE/worker-evidence.json",
  "worker_sha256": "REPLACE_ACTUAL_SHA256"
}
```

observed_at为可信运维本次核验证据的UTC epoch秒，首次应用不得在未来或超过1小时。
证据中事件原始时间另外保留；不得改旧事件时间伪造新证明。
审批文件0600、绝对规范路径、≤64KiB，重复键/额外字段拒绝。
当前现场意图是否满足上述证明由用户/维护者裁决；无法证明就继续保留，不自动转交M3。

### 3.3 获明确批准后应用

```bash title="not executed in this run"
/ABS/M2_VENV/bin/python -I -m agentseek_execution.broker_reconcile --config /etc/agentseek-m2-broker/broker.json --resource-id REPLACE_FULL_BROKER_RESOURCE_ID --approval /ABS/PRIVATE/approved.json
```

工具取得daemon同一flock后，验证绑定/摘要，再先记加密审计pending，后释放ledger writer，
最终标记stopped及审计applied。此终态须注明“运维依据证据裁定”，不冒充自动API查证。
中途失败保留pending；保持Broker停止，用**完全相同**审批重试，不手改库。
已完成的相同审批重放幂等；不同审批、旧租约、其他执行、摘要不符均拒绝。
失败输出仅RECONCILIATION_REFUSED，不打印证据内容；无force/批量清除/重建接口。
成功后恢复Broker，原request_id仍返回原终态；新request_id只创建一份资源，随后正常回收。

## 4. B7 无回执真实恢复夹具

文件：`contrib/agentseek-execution/tests/live_cube_recovery.py`。
它不在常驻服务中安装入口，不接受外部worker命令配置。
只在测试子进程内，真实SDK create返回后、加密回执写入前抛出异常。
随后调用正常生产恢复worker，按唯一run/token查找并删除，确认404后释放测试writer。

1. 先登记夹具绝对路径/hash、新专用fixture目录、证据位置和回滚；取得本轮故障注入授权。
2. 停M2整个单元，确认worker零、平台无活动/待创建VM，且其他PoC驱动不会并发创建。
   保持M2节点监督运行；夹具使用相同受监督run_id，但独立UUID/create_token和独立运行库。
3. fixture目录必须全新且与真实runtime不同；不清空旧目录，不修改真实未知意图。
4. 用安装了新版组件cube extra的解释器，以服务UID执行：

```bash title="not executed in this run"
/ABS/M2_VENV/bin/python -I /ABS/M2_WORKTREE/contrib/agentseek-execution/tests/live_cube_recovery.py --config /etc/agentseek-m2-broker/broker.json --fixture-dir /ABS/NEW_PRIVATE_B7_FIXTURE
```

5. 预期B7_NO_RECEIPT_RECOVERY_PASS且rc0；同时保全平台create恰1、receipt缺失断点、
   元数据唯一匹配、delete/404、ledger终态、对应shim/TAP零及原服务不变的证据。
   SDK+mock通过不能替代该实机证据；只看到CLI标记也不替代宿主资源核验。
6. 失败时保留目录和监督，不重新执行创建命令。对账原夹具使用：

```bash title="not executed in this run"
/ABS/M2_VENV/bin/python -I /ABS/M2_WORKTREE/contrib/agentseek-execution/tests/live_cube_recovery.py --config /etc/agentseek-m2-broker/broker.json --fixture-dir /ABS/EXISTING_PRIVATE_B7_FIXTURE --recover-only
```

未知/零/多匹配继续BLOCKED；该命令不扩大匹配、不会再次创建。
确认全部资源消失后才能归档夹具目录，不能直接删除SQLite“清理故障”。

## 5. B8/B9 补证及收官

1. 在本轮新VM上补restricted合法/缺失/错误Token三态；使用可信数据面测试夹具，
   不让Broker接收原始Token。可复用M0只读请求方法，但绑定本次M2 VM，密值不输出。
2. 完整敏感扫描包含Cube key、加密材料、A/B key、SSH凭据、envd/traffic token和真实平台句柄；
   Broker日志/公开输出及数据库敏感明文仅报计数。受限平台证据按M0边界单独记录。
3. B9要求主runtime无未决意图、所有本轮VM/shim/TAP回收、writer释放后可重新执行。
   人工裁定必须附证据和批准引用，不能只写“平台0”。
4. 监督manifest为空不必然异常：自动deadline跟踪在内存；显式register_sandbox才登记，
   不应写成“击杀/确认自动登记”。
5. 追加M2验证手册§7，不删原PASS/部分/NOT RUN/勘误历史。
   回传代码HEAD、双解释器门禁、只读硬化、B7、人工对账审批、B8三态、B9及原服务零变化。
   任一证据不足继续BLOCKED；最终由用户验收，不进M3、不动production/tag。

## 6. 回滚

仅停止/回退M2单元和本轮代码；保持节点监督与所有受限运行库。
不要覆盖已写入的审计，已应用裁定不能靠恢复旧SQLite撤销。
若对审批真实性有疑问，立即停新建并按事故对账，不自动复活旧任务。
只读启动失败时回传错误类型，必要的临时豁免须重新登记，不永久扩大系统权限。
