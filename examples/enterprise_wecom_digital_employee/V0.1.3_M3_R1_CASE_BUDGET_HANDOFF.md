# M3 R1 单行预算补丁 Linux 隔离复验

## 1. 核对授权与固定候选

本轮仅备料、受控传输、独立安装、离线测试、只读代码审阅与归档。
不接真实平台，不创建 guest，不执行真实探针，不切换现用安装或监督。
测试内临时 loopback 服务和监督子进程仅按既有隔离套件启动并收尾。

- 执行分支：`enterprise/v0.1.3-execution-broker`。
- 固定代码：`a12bf86b5f10b73db7b67d4eaeed125f688c61dc`。
- 基线报告：`2a7d8e502e253ac3f667f7bbb4717fe8437d4554`，应为候选祖先。
- wheel：`agentseek_execution_r1-0.1.3a0-py3-none-any.whl`。
- 预期 wheel SHA256：`bc7cce1eac25da76d25af6eabeaabfebda902cc81eb1acf580da60af7f0ee44e`。
- 本文为后续文档提交，不改变固定代码 SHA；不要从浮动分支 HEAD 构建。

沿用 OFFLINE_HANDOFF、LAUNCHER_HANDOFF 中已执行的清单、构建与隔离检查方法，
仅替换为本候选和新的独立目录。旧 aa9e1e5 安装、资料及禁用草稿原样保留。

## 2. .171 备料与交接

1. 核对双远端、祖先链及候选与基线差异；仅预算代码、测试与参考说明三文件变化。
2. 使用固定候选的独立干净工作树；不要修改候选或带入主树未提交文件。
3. 用候选 inventory 工具生成静态源码/测试闭包和 runtime-only 包项目，离线构建 wheel。
   核对 5 入口、32 运行模块与完整逐文件摘要；wheel 摘要不符即停止报告，不临时改构建参数凑摘要。
4. 准备固定运行依赖、隔离测试依赖及构建/安装检查工具；沿用已批准的离线依赖来源。
   仅已批准的 cffi 2.1.0 wheel 目录可经 find-links 使用；缺包记 BLOCKED_DEPENDENCY，不联网补包。
5. 新建本轮备料目录，生成 SHA256 清单；不放凭据、生产配置、vault 或现场回执原文。
6. 按用户已批准通道和投递位置交接材料。只传材料，不写 .172 的安装、配置或运行目录，
   不重启服务；若无可用批准投递方式，先报用户，不自行扩大权限。
7. 回传用户到货位置、候选 SHA、wheel 摘要和清单核验信息，等待用户通知 .172 执行。

## 3. .172 独立复验

1. 核对到货清单、文件权限及候选身份；不使用 Git、不改代码。
2. 复用已批准的独立 Python 3.13.14 解释器，创建新的 scratch 与 venv；
   不覆盖现用 /opt 安装，不修改系统 Python、服务 unit、启动路径或任何 .pth。
3. 全程 offline 安装固定 wheel 与运行依赖。使用独立测试环境运行测试；
   运行 venv 不要求装 pytest，明确测试环境和 installed-wheel 检查环境的区别。
4. 用新 venv 的 python -I 运行 install_check：预期 32 个安装模块来源/摘要一致、
   5 个无效配置拒绝，isolated=true。禁止用真实配置补测成功路径。
5. 从独立源码闭包复跑完整测试：预期 747 passed；清单工具预期 5 passed。
   明确设置闭包 src 与 examples 的导入路径，不从现用安装或其他工作树补齐模块。
6. 核验新增边界测试：剩余不足 16 秒零启动、同一截止跨行不刷新、
   子进程拒绝旧 30 秒载荷、UNKNOWN 不重试；测试后确认临时子进程无残留。
7. 只读核对预算参考中的整行预算和嵌套关系；发现差异则报告，不现场修改代码。

## 4. 单独报告阶段二编排缺口

本轮离线通过不代表跨行驱动器已交付。只读盘点实际调用方是否具备以下能力：

- 从可信 guest/批准事实建立同机单调钟截止，不使用每行 now+120。
- 首行前核验全槽 80 秒（A）/96 秒（B）加额外余量；额外余量仍待审定。
- 每行检查剩余预算；阳性对照失败、UNKNOWN 或身份/审批异常后停止后续行与 B 槽。
- 保存 A 真实回执、准备 B 动态字段期间仍正确核算寿命，不假定准备耗时为零。

给出文件/入口依据；无调用方则记 BLOCKED_IMPLEMENTATION，交回 Codex，
不要临时拼脚本或把操作员目测耗时当成已实现约束。此项与预算补丁离线 PASS 分开判定。
不得为本次盘点读取现场 key、物化 api_key、重写批准文件或变更现有草稿。

## 5. 回传与停止

.172 将脱敏报告和摘要清单写入新的本轮专用回传目录，不混入或覆盖历史材料。
建议报告名 `V0.1.3_M3_R1_CASE_BUDGET_LINUX_RESULTS.md`；清单使用本轮唯一文件名。
清单仅列本轮可回传文件，禁止包含凭据或要求 .171 拉取私有配置。

报告列明候选/实际分支资料版本、wheel 摘要、解释器、安装检查、测试数、
失败及修正过程、临时进程收尾、编排缺口、现场零变更边界。
通过时仅记 `R1_CASE_BUDGET_OFFLINE_PASS`；阶段二仍为待批准，
`BUDGET_ADJUDICATION_PENDING` 不自动解除，非 M3_READY。

用户通知后，.171 只读拉取回传目录、校验摘要并脱敏扫描，普通提交执行分支、
推送双远端并核验。提交前核对远端最新状态，不强推、不覆盖 Codex 或既有报告提交。

任一候选/摘要不符、离线依赖缺失、测试失败或真实环境操作需求超范围均停止报告。
不合并 production、不移动标签、不动 M0/M2/M3 服务、网关、MCP、DB、WORK 或既有语料。
本轮新增 scratch/venv 保留供审计；失败不自动删除目录或停止既有监督。
