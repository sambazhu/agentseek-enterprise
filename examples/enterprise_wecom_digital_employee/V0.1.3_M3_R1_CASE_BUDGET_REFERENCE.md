# M3 R1 单行预算参考

## 范围与判定

开发侧预算补丁与离线验证；不是阶段二创建、探针或 M3_READY 批准。
现场准备基线为 `2a7d8e502e253ac3f667f7bbb4717fe8437d4554`。
旧候选 `aa9e1e5` 的现场准备结论保留，新代码需要独立复验；不得覆盖旧安装。

## 已实现约束

| 项目 | 合同 |
| --- | --- |
| 整行外层预算 | 15 秒，包含审批读取、实时证据采集、数据面请求；另预留 1 秒清理 |
| 启动前检查 | 调用方传入同机单调钟的可信截止；剩余不足 16 秒时 DENIED，不启动 worker |
| 子进程校验 | 接收时剩余必须在 11–15 秒之间；拒绝旧 30 秒载荷 |
| 内层约束 | 原有采集、审批、请求前剩余时间校验不放宽 |
| 超时 | UNKNOWN 原样传播，单次调用无重试；不删除行记录、fence 或重置 quota |
| guest 寿命 | 监督仍按平台 startedAt + 120 秒换算固定单调截止，不从 attach 或每行启动重新计时 |
| 实时性边界 | OS 进程创建、调度和私有文件 I/O 不具备硬实时保证；15+1 不是整个系统的绝对耗时证明 |

## 预算核算与报告勘误

| 项目 | 软件预算 |
| --- | --- |
| A 五行 | 5 × (15 + 1) = 80 秒 |
| B 六行（含 X1） | 6 × (15 + 1) = 96 秒 |
| 创建 worker | 10 秒执行，清理另计；guest 实际消耗从平台 startedAt 计算 |
| attach worker | 10 秒执行，清理另计；登记 3 秒、等心跳 3 秒包含其中，不重复相加 |
| closeout | 独立结束事实检查，不要求在 guest 存活时执行，不代表再次创建授权 |

原报告实际提出 ≤15 秒/行；转发摘要的“压缩至 30 秒”无效，因为旧代码已是 30+1。
不能用 80/96 秒直接声称完整矩阵可在 120 秒内完成；还存在启动消耗、文件准备与收尾余量。

## 阶段二仍待落实的执行条件

- 调用方应提供 guest 截止与批准截止的较早值，不能每行构造 now+120。
- 首行之前应核验实际剩余寿命至少覆盖本槽全部行预算及经批准的额外余量；
  额外余量的数值与测量依据待现场执行方案审阅，不按剩余理论差值自动获批。
- 每行重新检查剩余预算；不足即不启动，后续未执行行记 NOT RUN。
- UNKNOWN、阳性对照失败或审批/身份异常立即停止后续行及后继槽，不以重试补齐矩阵。
- 本补丁只收紧单行入口，没有新增矩阵驱动器、自动批次停止编排或自动创建权限；
  跨行停止规则仍需在阶段二受信调用方中落实并验证。
- W0 责任人、全部 writer 禁创确认、执行窗口、两槽审批与 API key 物化仍待授权；
  B 的 previous_create 仍只能来自 A 真实成功回执。
- 预算子项维持待审，不能仅凭离线 PASS 自动解除 BUDGET_ADJUDICATION_PENDING。
