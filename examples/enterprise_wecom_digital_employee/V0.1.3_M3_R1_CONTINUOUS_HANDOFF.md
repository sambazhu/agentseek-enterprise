# M3 R1 A 槽连续驱动入口隔离复验

## 前置与范围

使用本工单复验新增连续调用入口，不执行真实 A/B。
现场 A_EXECUTION_PARTIAL 归档基线为 `2eb7a47d068ca0ae805f7efc200de2f89a4b1e35`。
代码候选为 `89be61f`，接收时解析完整提交并双远端核对。
本工单为离线验证授权，不是 /opt 安装切换、创建或探针授权。
旧 A 已消耗额度、fence、slot-intent、回执、审批材料全部原样保留。
旧窗口不续用。未来真实执行需另审计划、材料、身份和窗口。

## 1. .171 备料

1. 在执行分支接收候选及本工单，核验归档基线为祖先。
2. 使用现有 inventory 工具从固定候选生成全新隔离源码闭包和 wheel 工程。
3. 保持固定依赖和离线模式。沿用已批准 cffi 本地供应方式；缺包即停，不联网补装。
4. 核验 wheel `agentseek_execution_r1-0.1.3a0-py3-none-any.whl` 的 SHA256：
   `79531abc26d03c46ef5d95aa3ae8dacea657168e46fb893704ff13bb1a7c2b17`。
5. 将闭包、wheel、固定依赖、检查工具与逐文件清单按既有受控交接方式提供给 .172。
   不携带真实凭据、旧审批正文或真实回执。

## 2. .172 独立安装核验

1. 核验全部传输摘要，使用全新 scratch/venv；不覆盖旧候选安装。
2. 使用独立解释器离线安装，禁止借生产 venv，禁止修改常驻监督。
3. 使用新 venv 的 python -I 执行现有 install_check 工具。
   预期36模块来源/摘要匹配、9入口无效输入拒绝、isolated=true。
4. 仅检查 m3_continuous 的 help 或无效输入拒绝；不得提供任何真实有效配置。
5. 复跑 inventory 闭包内 execution 测试及 node_supervisor 测试，另跑清单工具测试。
   源码测试的 import 路径必须来自此次闭包，记录真实解析来源。

## 3. 核验连续驱动合同

1. 核验 schema=1 精确六字段：lifecycle/lifecycle_sha256、
   preapproval/preapproval_sha256、directory，以及 schema。
2. 核验只接受 A：B 或未批准预批在创建前拒绝。
3. 核验创建前 binding、plan、监督身份、W0、模板、request、vault/key 路径匹配。
   这些静态比较不替代原有实时门禁，也不声称完整配置 dry-run 已实现。
4. 核验 continuous/lifecycle/output/dispatch 为四个空私有目录，互不相同、不嵌套。
5. 核验独占 continuous-intent 在创建前持久化；同配置重复调用不再次创建。
6. 核验同一次调用内直接执行 lifecycle create → materialize → slot，
   中间没有人工批准、Agent 往返、sleep、重试或自动 B。
7. 核验跨阶段配置重新钉摘要，生成结果必须与磁盘 manifest 一致，
   slot 路径/完整摘要及5行数量必须正确；缺失或篡改不得派发探针。
8. 核验异常不继续；intent 留存，失败后不删除、不换目录绕过，不手工抽取部分行。
9. 核验原 slot 的85s预算及逐行门禁没有改变，监督120s硬截止没有改变。
10. 核验成功输出仅为连续链结果与各段耗时，不输出 token 或配置正文。
    closeout_required=true，next_create_authorized=false。

## 4. 收尾与回传

连续入口不等待 guest 结束、不 kill、不自动 closeout。
未来真实执行仍需保持独立监督有效，并按原 lifecycle 合同单独核验结束与 closeout。
失败也不得关闭监督。本轮离线测试仅允许已有 synthetic 测试的临时子进程。

产出新脱敏报告与清单，记录安装、测试、入口合同结果及实际测试方法。
.172 零 Git；用户通知后 .171 只读拉取报告与清单、核验后普通提交双远端。
不回传私有配置、凭据、真实 create-token 或密封回执正文。
本轮最高判定为 `R1_CONTINUOUS_OFFLINE_PASS`，非现场全链 PASS、非 M3_READY。
