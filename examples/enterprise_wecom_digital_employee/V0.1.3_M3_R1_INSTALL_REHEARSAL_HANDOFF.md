## 3. .172 安装新版本并明确调用路径

1. 先只读记录旧安装、解释器、监督 unit 的实际引用关系；无需控制面请求或凭据读取。
2. 在新版本专用目录创建 venv，例如 /opt/agentseek-m3-releases/be59e54/venv。
   路径已存在但来源不明或非空时停止，不覆盖。使用已批准解释器，离线安装固定 wheel 与依赖。
3. 不替换 /opt/agentseek-m3-supervisor 下旧 venv、解释器、脚本或服务引用。
   不升级依赖、不改 .pth、全局 PATH/PYTHONPATH、unit、systemd 或监督 pins。
4. 用新版本 venv 的 python -I 重跑安装检查：34 模块摘要一致、7 无效入口拒绝。
   执行新入口 help；不提供有效配置。报告明确实际解释器、模块来源和 wheel 摘要。
5. 将“后续受信调用路径”登记为新版本解释器的规范绝对路径，生成私有安装记录，
   记录候选、wheel、解释器、检查结果、旧路径与回退路径。
   这里的切换只指后续显式调用的入口选择，不是切换常驻进程或启动任务。
   不创建 current 符号链接替代规范路径，不假定导入成功意味着现有进程已换版本。
6. 确认既有监督/服务未变。新安装失败则不登记新入口，保留旧路径及现场。
   已登记后需回退时，只恢复后续入口选择；不删除新目录、不停止监督。

## 4. .172 合成资料准备演练

1. 新建独立私有目录，使用明确标注的 synthetic run/ID/key，不复制真实凭据、vault、
   fence、quota、回执或现场批准。不得复用真实 run_id 的任何可执行文件。
2. 仅模拟“已收到创建回执之后”的资料准备：保存合成回执、填充动态字段、生成规范 JSON、
   写盘、计算摘要、核对配置引用顺序；A/B 分别计时。
   所有审批保持 approved=false、w0_accepted=false；禁止调用 lifecycle create/closeout、
   slot.run 或任何真实平台入口。离线测试中的批准 fixture 不得提升成现场配置。
3. 可以编写只处理合成 JSON 的一次性计时辅助程序；不得实现替代执行器、自动批准或网络调用。
   辅助程序随脱敏演练材料留存，明确它不是交付候选的一部分。
4. 至少做三轮独立目录演练，记录每轮开始/结束单调时间、各步骤耗时、冷/暖缓存及失败情况。
   计时覆盖本轮实际发生的人工/Agent 等待，不只计最后一次 JSON 写盘。
   尚未模拟的用户批准或消息往返必须单列“未计入”，不得假设为零。
5. 不把人工确认缩成测量脚本中的固定 sleep；不得通过删掉校验步骤获得更短结果。
6. 若资料准备本身已超过可用预算，报告不可行；不缩减矩阵、不扩 120 秒、不自动重试真实任务。

## 5. 提交预算建议，不自行批准

分别列 A/B 的资料准备测量值、未测项和 reserve_seconds 建议值及依据。
采用“观测最大值 + 明确说明的额外裕量”只能作为建议，不是统计上界或硬实时证明。
合成准备演练不能测得真实平台创建、attach、实时证据查询或网络抖动；这些保持未测。

首行实际检查为剩余可信寿命至少 A 80+reserve、B 96+reserve。
创建、attach、回执保存、动态准备及首轮证据采集已经耗用的时间不另计成可用余量，
不得重复扣算或重新起算 120 秒。也不得把合成资料准备最大耗时直接称为 reserve。
应列预算账：已消耗时间 + 全槽预算 + 建议余量，并注明未测耗时无法由本轮补证。

资料准备演练可支持操作可行性评估，但不能单独证明完整矩阵能在 120 秒内完成。
实际证据门不足时必须停止；真实窗口仍待用户对余量、W0、writer 禁创、两槽审批等逐项裁定。
