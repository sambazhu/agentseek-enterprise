## 2. 审阅配置契约，不在现场生成

launcher JSON schema 1 的精确字段如下，所有路径必须是规范绝对路径。
配置及所读取私有文件为本机 root 所有、0600，父目录 0700。
监督脚本必须是受信安装方复制的私有、摘要固定副本，不能任意传命令。

| 字段 | 含义 |
| --- | --- |
| schema | 整数 1 |
| create_file / create_sha256 | 当前槽创建安装文件及 SHA256；A 使用已有 schema 2，B 使用 schema 3 |
| candidate_sha256 | 带外固定的候选摘要，不是 Git 短 SHA，也不是自测量承诺 |
| supervisor_script / supervisor_sha256 | 既有 node_supervisor.py 的私有副本及摘要；本程序不安装/启动服务 |
| tracking_directory | 本槽独立空目录，0700；不得复用前槽目录或 vault/fence/quota/supervisor 目录 |

创建配置继续引用既有 precreate、独立 approval、CA、密钥、vault、fence、quota 与固定 sequence。
本补丁不生成批准文件、不更改模板/网络，不给创建批准附加探针权限。
案例探针仍经 `m3_case_process` 独立批准；本 launcher 不发送案例，不代表矩阵已经自动编排。

## 3. 审阅 A/B 顺序，不执行

1. 可信安装方准备 A 的不可变文件和带外摘要；在独立已安装解释器下以 `-I` 启动模块。
2. A 创建子进程外层预算 10 秒；成功后附着子进程另 10 秒，登记命令最多 3 秒，等待真实心跳最多 3 秒。
   这些预算不延长 guest 的 120 秒硬截止；OS 启动/清理开销沿用原合同。
3. 输出包含 CreateBinding，不包含 traffic token；由可信调用方在私有目录保存、核验完整 JSON 并计算摘要。
   stdout 保存失败/截断/丢失属于不确定结果，不能重跑创建来恢复输出。回执与 fence 留存，转人工核对。
4. A 的探针与终止由另批工单和独立 supervisor 负责；launcher 不执行 kill，也没有自动轮询/续时。
5. 需要结束检查时调用公开 `--closeout` 模式：stdin 精确字段为 path、sha256、binding。
   它只做一次有界检查；成功返回 `known_target_absent=true`、`next_create_authorized=false`。
6. B 配置由可信安装方在 A 回执已知后准备并另行固定摘要，保留 A 的原配置不变。
   B 的 previous_create 必须等于 A 的完整 binding，previous_tracking_directory 必须指向 A；
   vault/fence/quota/sequence 与 A 相同。不能以保存的 ID 替代回执，不覆盖 A 的 approval/precreate 文件。
7. 显式 B 调用提供 `--config`、`--sha256` 加四个参数：`--previous-config`、`--previous-sha256`、
   `--binding-file`、`--binding-sha256`。binding-file 是 A 完整 launcher 成功输出，私有文件独立钉住摘要。
8. B 调用先查 A 当前结束，再调用既有 schema-3 创建入口；后者重新采集实时结束状态并执行 check_successor。
   旧 closeout 结果不能跳过新检查。B 不自动启动，失败不重试、不删除 fence、不退款或重置 quota。

注册失败或注册后心跳/身份/观测失败时，目标可能已存在；保留所有记录并停止后续槽，
原独立监督仍按其授权运行。不要停止监督以“回退”客户端错误。
`--attach` 是内部子进程入口，不作为人工恢复或绕过创建流程的运维接口。
