# M3 R1 Linux 隔离安装核验工单

## 1. 核对范围与版本

- 分支：`enterprise/v0.1.3-execution-broker`，不是 P1 分支。
- 固定代码候选：`07e098e67678ca60f8434cc276fe9c731464b6bd`。
- 基线：`8bec3313bbd7f9144855384481cceb4d0c0a38a3`。
- 本轮只验证源码隔离复跑、wheel 构建、独立 venv 安装、隔离解释器加载与无效配置拒绝。
- 不调用真实 CubeSandbox；不创建/终止 guest；不安装或重启节点 supervisor。
- 不改 production、标签、网关、P1、数据库、MCP 配置或现有虚拟环境。
- 不启 WORK；不使用生产凭据；不生成有效创建配置或批准材料。

先核验双远端候选可达且完整 SHA 一致，再建立该 SHA 的独立干净工作树。
从包含本工单的分支读取文档；实际构建工作树固定到上述代码 SHA。
不要直接使用混有其他 M3 工作的开发目录。

## 2. 核对依赖

需要 Linux Python 3.13、uv，以及兼容该主机的离线依赖缓存。
构建后端固定 `pdm-backend==2.4.9`。
运行依赖版本见 `scripts/m3_r1_runtime_requirements.txt`。
测试使用 `pytest==9.1.0`、`cryptography==49.0.0`、`cubesandbox==0.7.0`。

版本约束不是带平台 wheel SHA256 的完整锁文件；本次未交付 Linux wheelhouse。
缺少解释器、缓存或对应架构包时，标记 `BLOCKED_DEPENDENCY`，列包名/版本/架构后停止。
不得去掉 `--offline`、降级版本、借用生产 venv 或升级生产依赖。
后续补包单独协调。

## 3. 在候选工作树执行

以下是 Linux 执行块，本地以 Mac Python 3.13.3、独立临时目录执行同等构建与安装步骤；
Linux 本身尚未执行。TODO：Linux CC 记录 Python/uv/OS/架构与结果。

```bash title="not executed in this run — Linux"
set -euo pipefail
umask 077
m3_source=$(pwd -P)
test "$(git rev-parse HEAD)" = "07e098e67678ca60f8434cc276fe9c731464b6bd"
test -z "$(git status --porcelain)"
python3.13 --version
uv --version
m3_scratch=$(mktemp -d /tmp/agentseek-r1-linux.XXXXXX)
python3.13 scripts/m3_r1_inventory.py \
  --stage "$m3_scratch/tests" \
  --package-stage "$m3_scratch/package" > "$m3_scratch/inventory.json"
uv build --offline --wheel "$m3_scratch/package" \
  --out-dir "$m3_scratch/dist" --no-build-logs
uv venv --offline --python python3.13 "$m3_scratch/venv"
uv pip install --offline --python "$m3_scratch/venv/bin/python" \
  -r "$m3_source/scripts/m3_r1_runtime_requirements.txt" \
  "$m3_scratch/dist/agentseek_execution_r1-0.1.3a0-py3-none-any.whl"
cd "$m3_scratch"
"$m3_scratch/venv/bin/python" -I "$m3_source/scripts/m3_r1_install_check.py" \
  "$m3_scratch/package/R1_INVENTORY.json"
sha256sum "$m3_scratch/dist/agentseek_execution_r1-0.1.3a0-py3-none-any.whl"
```

预期：31 个模块来自新 venv，源码逐文件摘要匹配；4 个固定入口的空配置全部拒绝。
程序输出只包含检查结果与依赖版本。
不要向入口提供真实配置以“进一步验证”。

包名 `agentseek-execution-r1` 与完整包共用 `agentseek_execution` namespace，
不得与完整包混装；必须使用上面新建的 venv。
不同构建时间可能导致 wheel 容器摘要不同；记录 Linux 自身 SHA256，
源码完整性以固定 Git SHA 和安装检查逐文件摘要为准，不能只比较 wheel 文件名。

## 4. 在隔离源码目录复跑

延续上一执行块的变量。测试只使用模拟平台或 loopback HTTP；
独立 supervisor 测试会启动临时子进程及本机临时 HTTP 端口，并在 finally 收尾。

```bash title="not executed in this run — Linux"
cd "$m3_scratch/tests"
env PYTHONPATH="$m3_scratch/tests/contrib/agentseek-execution/src:$m3_scratch/tests/examples/enterprise_wecom_digital_employee" \
  uv run --offline --no-project --python python3.13 \
  --with pytest==9.1.0 --with cryptography==49.0.0 --with cubesandbox==0.7.0 \
  python -m pytest contrib/agentseek-execution/tests \
  examples/enterprise_wecom_digital_employee/tests/test_node_supervisor.py -q --tb=short
cd "$m3_source"

```

Linux 有差异则保留原始失败，停止验收，不修改门禁或本地用例使其变绿。
