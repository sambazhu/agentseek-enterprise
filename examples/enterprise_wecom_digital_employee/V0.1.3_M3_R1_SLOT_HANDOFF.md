## 4. 审阅显式调用合同，不执行现场配置

按以下顺序审阅，不将其理解为自动流水线或阶段二批准：

1. m3_lifecycle 的 create 动作调用既有 launcher，把完整成功输出写入私有目录
   create-result.json；写前 create-intent.json 独占保留。创建或保存 UNKNOWN 均不得重跑。
2. 受信安装方根据真实回执准备、独立批准并钉住逐行配置及 slot 配置。
   当前没有自动配置/审批生成器；准备时间消耗 guest 寿命，不能暂停或重算计时。
3. m3_slot 从首行实时证据构造可信截止，检查 A 五行 80 秒/B 六行 96 秒加显式余量，
   每行重新检查剩余总预算并调用已有 15 秒单行入口。余量无默认值，具体值仍待批准。
4. 整组 intent 独占持久保存；预算不足、异常、UNKNOWN 或响应不符停止后续行。
   阳性要求 200 及对应协议信号；负向要求 403、http_denial_signal 且无 activity。
   此判定不扩展为服务端无副作用证明。成功保存 slot-result，next_create_authorized=false。
5. lifecycle closeout 显式调用现有结束检查并保存结果，不轮询、不 kill、不启动 B。
6. B create 显式绑定 A create-result 与 slot-result 的路径/摘要；只有 A 五行成功才调用
   launch_successor，后者再查 A 当前结束事实及 B 独立创建批准。A schema 2、B schema 3 强制区分。
7. B slot 再绑定 A 成功记录；X1 只在 B 最后一行，E1/e2b 别名，凭据来自本轮 A 密封回执。
   验证同 run/boot/template/candidate、不同 ID/token、A→B 序列、归档 fence 及当前 B fence。
   实时 schema-4 collector 要求完整平台列表恰为 B，作为当时 A 缺席事实；非原子快照。
   旧 standalone receipt worker 和旧平台 collect 接口继续拒绝 X1，不得绕过完整 case gate。

配置字段按候选源代码精确集合审阅：

- lifecycle：schema/slot/launcher/launcher_sha256/directory；B 另有 previous，
  内含 launcher/launcher_sha256/create_result/create_result_sha256/slot_result/slot_result_sha256。
- slot：schema/slot/reserve_seconds/directory/rows；B 另有 previous_slot（path/sha256）。
  每行 installation/sha256/approval_sha256；A 顺序 E1正确、E2正确、E2错值、E3正确、E3缺失，B 加 X1。
- X1 ReceiptProbeSource 另有 donor（create/successor_file/successor_sha256）。
  probe schema 4、state=cross_guest、donor_ref=donor 描述的 canonical JSON SHA256；
  原非 X1 probe schema 3 不变。所有路径规范绝对、私有文件 0600、父目录 0700。

## 5. 如实记录验证边界

本地完整闭包 784 passed、清单 5 passed、wheel 34/7 安装检查通过；Python 3.12/macOS，非 Linux 结论。
新增 X1 测试使用真实私有回执与归档文件；slot/lifecycle 测试替换平台采集和部分下游调用。

Linux 本轮也只可记离线/合同结果，不补跑真实探针凑完整结论。

动态配置准备耗时、端到端现场时序、额外余量值及新的现场批准材料仍待审。
OS 调度/文件 I/O 非硬实时；监督 120 秒不变。任何不足继续记 BLOCKED，不承诺矩阵必定完成。
如发现无法按上述显式阶段形成闭环，逐项回报 BLOCKED_IMPLEMENTATION，不现场拼脚本。
