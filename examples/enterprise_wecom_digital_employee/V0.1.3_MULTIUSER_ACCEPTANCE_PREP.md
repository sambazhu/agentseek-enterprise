# v0.1.3 最小双用户验收准备合同

## 范围与批准状态

| 项 | 合同 |
| --- | --- |
| 目标 | 同企业两位真实用户，各自在企微单聊完成执行、工作区回写、明确索取及实收摘要核验 |
| 用户准备 | 用户已确认第二位测试用户就绪；账号、凭据不进入本文件 |
| 执行方式 | A 完整收口后再 B；每位用户独立新 request、材料、窗口和一次创建授权 |
| 最小材料路径 | 沿用单用户生成链，两轮分别闭合；不新增多计划装配器 |
| 原因 | 业务服务可表示多计划，但现有生成器要求一个 permit 和一个 plan；服务表达能力不等于材料链已支持合并 |
| 本文件效力 | 开发端准备合同；不批准部署、重启、账本重建、创建、发送或清理 |
| 范围外 | 并行 guest、自动排队、群发、多企业、自动投递、HTTPS 启用、上游/Bub 升级 |

## .171 / .172 准备交付

| 责任方 | 必须回传 |
| --- | --- |
| .171 | 执行日只读版本、配置、可信身份链和两用户应用可见范围；不读出凭据。候选采用/恢复操作单，完整摘要、实际路径、env 差分、导入与工具装配门禁 |
| .172 | broker 实际状态、unit 指向、既有 venv/wheel、监督 pins、实时 guest、在途进程、双用户相关 store 状态；附 UTC 采集时刻 |
| 两端 | 两套材料缺项表、每轮预检输入及摘要、owner/request binding 对算；采用链全文对算另列，不能只凭 binding 判通过 |
| 测试输入 | 两份内容不同的合成 CSV、相同输出名 summary.csv；上传前离线核定输入和预期输出完整摘要，两用户分别确认 |
| 权限信息 | 用户 A/B 标签与密封可信身份对应，scope 与收件人来源可审计；模型无指定 owner 或收件人的权限 |
| 待批准动作 | 网关候选采用；每轮业务配置/重启与 broker 采用启停；新授权；必要 manifest 重建；两次各自明确投递，逐项列明 |

现场基线 — 最近回报为 .171 534bfa4/NFD-only、.172 broker inactive。PID、配置摘要、权限和库存均属历史快照，必须重新采集。

manifest 门禁 — A 收口后可能保留合法历史登记。B 如需替换现役 manifest，须完整字节归档并另列明确批准；不得因串行验收自动清账。

恢复门禁 — 每次恢复前重查 NFD inflight/uncertain 和 outbox 可恢复态；有未决即停，保留新守卫、账本及工作区关联文件，不删除以求通过。

## 现场时序门禁

| 顺序 | 门禁 / 证据 |
| --- | --- |
| 1 | 两端只读准备与离线备料；用户审阅具体采用操作单和 A 轮批准项 |
| 2 | A 用户确认可立即配合后，收新四方确认、定不超过 2h 的真实窗口；生成、读回、独立对算、最终预检 |
| 3 | 按批准顺序节点 ready → 网关采用 → 双端运行态复核；网关重启在上传前完成 |
| 4 | A 原私聊上传 A CSV；完整绑定核对后只发一次固定问题；实际创建最多一次，失败不重创 |
| 5 | A 成功后明确索取精确本轮文件；用户实收、打开、本地摘要核验；完成节点与网关收口 |
| 6 | 两端保留 A 账本/文件；B 使用独立批准材料与窗口重复同链，不继承 A 授权。重复采用动作及停点须写明 |
| 7 | 对账 A/B 两个 request、attempt、artifact、工作区关联和投递账本；核定收件人分别为本人 |

固定问题 — 沿用已批准的原始文本与字节摘要；不同 CSV 输入各自重钉。上传后如重启，必须重新上传并完整重核。

跨用户检查 — A/B 在自己的单聊只可列出、查询和投递本 scope 文件。负向检查先列具体只读测试步骤、由用户批准；不转发另一用户正文、句柄或凭据，不用 shell 直驱替代真实通道。

## 通过、停止与口径

| 项 | 判据 |
| --- | --- |
| 各轮业务通过 | 当前 request 对应实际 attempt；一次创建；CSV 正确；双侧持久化、主动销毁及 closeout；工作区不可变关联；确定性终稿属于本轮 |
| 各轮投递通过 | 用户明确索取；精确 file_ref 与 attempt 关联核对；投递账本/outbox 恰一次；api_accepted 与本人实收分列；打开后完整摘要一致 |
| 隔离通过 | 两用户身份/scope/owner 分立；A 产物不出现在 B 的查询/投递权限中；B 结果及收件人属于 B；同名不替代、内容摘要不充当任务身份 |
| 日志实证 | 自然业务调用的 sandbox_tool 行到达日志通道，状态和 request 摘要与账本对应；若缺失如实列缺口，不据此否定或伪造执行证据 |
| 停止条件 | 任一可信身份或绑定不符、未决全库门禁、材料/进程漂移、UNKNOWN、不确定发送、授权过期、恢复硬门未过 |
| 停止行为 | 不补跑、不自动重发、不清未决、不延窗；保留现场证据，报告具体阻断点 |
| 最终判定上限 | 单企业、双单聊、串行执行与显式投递的端到端隔离验收；不宣称并行容量或完整多企业能力 |
