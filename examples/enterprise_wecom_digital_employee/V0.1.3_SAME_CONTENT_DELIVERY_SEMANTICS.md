# 同日同内容产物与投递语义

## 范围与判定

| 项 | 说明 |
| --- | --- |
| 基线 | a5dea87；I05 现状定性与合同提案，不是功能修复 |
| 本轮内容 | 5 项合成反证测试与本文；零运行源码、schema、依赖变更 |
| 判定上限 | SAME_CONTENT_SEMANTICS_CHARACTERIZED；不是 I05 归属关联修复 PASS |
| 边界 | 临时目录、合成 request 与模拟上传/发送；无真实任务、用户消息或现场配置 |

## 三种身份（不能互相代替）

| 对象 | 当前标识 | 可以证明 | 不能单独证明 |
| --- | --- | --- | --- |
| 任务 | owner + request_id 派生 attempt | 某主体某次请求的账本记录 | 文件已送达 |
| 执行产物 | attempt + 内容摘要派生 artifact_ref | 与该 attempt 关联的持久化字节 | 唯一工作区路径或新发送 |
| 工作区文件 | tenant/user/date/session/direction/content file_id 路径；workspace file_ref 对路径+完整摘要取哈希 | 指定 scope 的指定文件副本 | 独立 attempt 身份；同日多次执行可能共用一个路径/ref |
| 原生投递 | scope + recipient_key + workspace file_ref + initial/明确重发 message_id | 该文件副本的投递尝试与回执 | 新任务执行、用户实收/打开；api_accepted 仍非用户确认 |

## 当前行为（源码与测试分列）

| 场景 | 行为 | 证据 |
| --- | --- | --- |
| 同 scope、同 UTC 日、同内容再次保存 | 同路径、同 workspace file_ref；metadata 的 created_at/expires_at 被重新写入 | 测试直接调用实际 LocalFileStore |
| 两次独立成功任务产出同字节 | 两个 attempt、两个 artifact_ref，可以共享同一工作区 ref | 实际 BusinessStore 与 LocalFileStore 组合测试；非真实 provider 执行 |
| 第二次保存后用户再次说“发给我” | 初次 key 不变，返回已有 api_accepted 回执；模拟 upload/send 次数不增加 | 实际 FileDeliveryBinding + DeliveryLedger |
| 用户明确说“再发” | 新入站 message_id 参与 key，可再次发送；同 message_id 重复调用仍判重 | 实际投递代码、模拟 HTTP 上游回调 |
| 不同内容或不同 UTC 日 | 不同工作区 ref；同名多件时拒绝按文件名猜测，需要精确 ref | 两个参数化用例 |
| 当前成功任务结果查询 | workspace_result 调用 store_bytes，可能刷新 metadata/期限或跨日新建副本 | 本轮静态源码核对；未把查询的这一组合路径计入 5 项测试实证 |

## 合同建议（待用户确认，不在本候选改变行为）

| 项 | 推荐方案 |
| --- | --- |
| 初次/重发 | 保持文件副本级去重；新任务不自动使相同副本再次可投递；再次发送仍须用户明确要求 |
| 用户呈现 | 已有回执须表述为“该文件已有投递记录，本次未再次发送”，不得将旧 api_accepted 说成刚刚发送；当前返回结果尚无独立 reused 标志，后续需设计兼容字段与文案 |
| 执行归属 | 另建不可变、可复核的 request/attempt/artifact→workspace 关联；不能仅记录“最新 attempt”覆盖之前关联；不把 created_at 当独立执行证据 |
| 保留期 | 任务结果只读查询不应隐式延长已物化副本期限；需在业务物化层设计幂等性，不贸然更改所有上传调用的通用 store_bytes 语义 |
| 相同路径多任务 | 可以多对一关联；每个关联需核 scope、完整摘要及任务产物，不能凭同 SHA 宣称某次任务已执行 |
| 替代方案 | attempt 级工作区文件与投递 key 会改变列表、路径、保留期及重发语义；本轮不默认采用 |
