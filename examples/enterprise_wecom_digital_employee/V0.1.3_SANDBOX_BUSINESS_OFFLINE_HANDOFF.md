# CSV 沙箱业务节点隔离复验工单

## 范围与通过条件

本轮只复验独立业务 wheel，不是 R1 升级或真实执行放行。目标交付路径是
“guest 生成 summary.csv → 节点持久工作区 → 网关用户文件区 → 文件引用”，
不测试企微附件上传/发送。架构与状态定义见 [业务参考](V0.1.3_SANDBOX_BUSINESS_REFERENCE.md)。

通过条件：固定候选来源、44 运行模块/2 入口核验通过、节点闭包 835 项与业务清单工具
1 项复跑通过，报告实际结果。通用 R1 清单工具的 5 项完整仓库测试只在备料端运行，
不得要求业务子闭包复跑。macOS 开发端结果不是 Linux 结论；平台差异必须如实披露。
网关定向回归 38 项仅为开发端记录，本轮节点安装不包含网关依赖。

## 1. .171 备料

从本工单所在执行分支提交建立独立干净工作树，记录完整 SHA；不得混入未提交代码。
使用该候选的 `scripts/business_inventory.py`，分别生成源码测试闭包与独立包工程。
固定两入口为 business_service/business_cube_session；清单兼容文件名仍是
`R1_INVENTORY.json`，但 scope 必须为 CSV business node，不能沿用 R1 清单。

开发端已执行下列等价命令；变量须由备料端填写为本轮新建绝对路径，Linux 执行结果待回传：

```sh
python scripts/business_inventory.py --root "$candidate_root" --stage "$source_stage" --package-stage "$package_stage"
uv build --offline --wheel --out-dir "$wheel_directory" "$package_stage"
PYTHONPATH=scripts uv run --offline --no-sync pytest -q scripts/test_m3_r1_inventory.py scripts/test_business_inventory.py
```

开发端 wheel：`agentseek_execution_business-0.1.3a0-py3-none-any.whl`。
SHA256：`bceeb6e372b7dfa8c0d4c2c3a588c5430e94f7b3dbca5b08086ee41087fb8f2a`。
若重建摘要不同，先核对源码/构建环境并报告，不自行替换预期值。

打包源码闭包、wheel、该候选检查工具、工单与参考、离线依赖及逐文件 SHA256 清单。
运行依赖为 cryptography==49.0.0、httpx==0.28.1 及其解析依赖；构建为
pdm-backend==2.4.9；测试需 pytest。Linux cffi wheel 必须匹配现场 Python/架构，
不得拷 macOS wheel 充数。不得联网补包、升级 SDK、借生产 venv；缺项报告后另批。
不放入任何生产配置、预批正文、API key、broker token 或证书私钥。

沿既有批准传输路径交付 .172 的新目录，0700；不得覆盖历史材料或写其服务配置。
若现有分工不允许 .171 直接落盘，由 .172 接收到货；不扩大 SSH 写权限。

## 2. .172 离线安装与核验

先复核全部到货摘要；新建 scratch 与独立 venv，保留 R1 所有安装、额度、栅栏、回执。
本包与 R1 有同名 Python namespace，禁止装进同一 venv。不得改 /opt 入口、常驻服务或软链。

```sh
uv venv --offline --python "$isolated_python" "$business_venv"
uv pip install --offline --python "$business_venv/bin/python" --find-links "$approved_wheels" "$business_wheel" pytest
"$business_venv/bin/python" -I "$tools_directory/m3_r1_install_check.py" "$package_stage/R1_INVENTORY.json" --profile business
```

进入本轮源码测试闭包根目录，再执行：

```sh
"$business_venv/bin/python" -I -m pytest -q -o pythonpath=examples/enterprise_wecom_digital_employee contrib/agentseek-execution/tests examples/enterprise_wecom_digital_employee/tests
```

开发端该命令为 835 passed；最初遗漏 sandbox_poc 的测试路径曾导致收集失败，
上列已更正。运行包必须解析到新 venv，不得用源码 PYTHONPATH 覆盖安装检查。
TLS 测试仅开本机临时 loopback listener，使用合成凭据与假 provider；
允许测试子进程并须收尾，禁止连接真实 Cube/平台或以真实配置启动 business_service。

随后只运行随业务子闭包交付的业务清单测试：

```sh
AGENTSEEK_BUSINESS_INVENTORY_ROOT="$source_stage" \
AGENTSEEK_BUSINESS_PACKAGE_TEMPLATE="$tools_directory/business_package.toml" \
PYTHONPATH="$tools_directory" \
"$business_venv/bin/python" -I -m pytest -q "$tools_directory/test_business_inventory.py"
```

预期 1 passed。`test_m3_r1_inventory.py` 的 5 项测试依赖完整候选树，由 .171 备料端
与 Codex 开发端验证；不得在 .172 业务子闭包中运行，也不得为此补交或拼接完整仓库。

## 3. 只读检查下一轮前置

只报告以下事实/缺项，不生成批准文件、不启服务、不执行 guest：

- .171 网关和 .172 节点间拟用 HTTPS 地址、端口与证书签发方案；不改防火墙。
- 新业务 store/workspace 的拟议位置，不复用旧 A 的 quota/fence/run。
- 网关上传文件的 tenant/user/session 是否与可信运行上下文一致；特别核对 userid 与 OA 账号映射，不猜测或放宽归属校验。
- 节点支持 guest 固定 Python CSV 程序的待测项；不得凭模板 READY 推定可执行。
- 明确节点持久化不等于用户界面文件可见，最终业务验收必须由用户打开文件核对。

## 4. 回传与下一步

.172 产出本轮专用脱敏报告与 SHA256 清单，不输出凭据/私有批准正文/输入业务数据。
.171 只读拉取、核验、普通提交执行分支并双远端核对；不合并 production、不动标签。
判定最多为 `BUSINESS_NODE_OFFLINE_PASS`，不能写业务全链 PASS 或 M3_READY。

复验后进入受控业务试运行工单：用户实际问题 → 真实 DeepAgent 模型选择工具 →
HTTPS 节点执行 → 工作区落盘 → 清理确认 → 用户文件区回写与可读验证。
该轮须另定新执行材料、一次创建授权、有效窗口和服务启用范围；不沿用旧 A 额度，
不以 B 绕行，不重复追加与业务验收无关的底层矩阵。
