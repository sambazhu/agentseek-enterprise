# 准备首个真实 CSV 沙箱业务全链验收

## 本轮目标与基线

将两端现场输入收敛成一份可供用户批准的执行方案。
基线为归档 a125c636bfad1c555234bb551294e1fdb02e4e5e：BUSINESS_NODE_OFFLINE_PASS。
业务代码候选仍为 5afe44c8accfd96a3f7f01404a32455ed242641c，wheel SHA256 为
bceeb6e372b7dfa8c0d4c2c3a588c5430e94f7b3dbca5b08086ee41087fb8f2a。
本工单只补文档，沿用已验收 44/2、835 与业务清单 1 项结果。

用户已同意两端准备；本轮允许只读核对、合成 CSV 与禁用配置草案写入新的准备目录。
由 .172 在本机独占准备，.171 在本机准备并归档；Codex 审阅配置合同和发现的代码缺口。
服务启动、网关切换、签发/物化凭据、防火墙变更、新监督启用及一次真实创建/执行/终止，
须在最终方案中列出具体范围，交用户批准后执行。生产与既有 R1 状态保持当前值。

## 1. 固定验收任务

输入文件名 `sandbox-business-input.csv`，UTF-8 无 BOM、LF 换行、末尾换行：

```csv
group,amount
A,10.50
B,3
A,-2.25
B,7
C,0
```

固定用户问题（同时用于批准中的 instruction 摘要）：

> 请按 group 分组汇总这份 CSV 的 amount，将结果保存为 summary.csv 返回我的工作区，并告诉我汇总结果。

预期输出 `summary.csv`：

```csv
group,total
A,8.25
B,10
C,0
```

首轮证明真实模型选择工具、固定程序在真实 guest 内执行与文件完整回传。
本候选计算程序固定；模型不生成任意代码，运行时也没有自动安装第三方依赖的能力。
模板需要的 python3/标准库/临时目录写入能力由同一次 CSV 执行证明；失败如实记录，
不另建 guest 补测，不在主机上计算结果冒充 guest。

## 2. .171 先准备网关事实包

在新准备目录完成下列核对，输出一份脱敏事实包供用户转交 .172：

1. 记录网关实际模型 provider/model、现有 spec、Python/依赖解析和当前运行来源。
   选择继续使用的真实模型，确认其工具调用配置；准备候选 spec 的启动与恢复方案。
   本轮不调用付费模型、不切换运行网关、不安装依赖；缺项一次列全。
2. 核对目标用户 zhuchunlin 的可信 tenant/user/session 和上传文件归属的实际映射。
   对外仅报告匹配结论与必要的脱敏标识；私有精确绑定留在受控材料中。
   OA 账号与企微 userid 不相等时，不猜测、不直接替换；交 Codex 修正映射设计。
3. 确认上传文件怎样进入最终提问当轮的 `current_files`，以及何时取得 input_ref。
   grant、permit 与业务 plan 必须绑定同一实际文件 ID、输入字节摘要和固定问题摘要。
   如果先上传后批准会导致下一轮 current_files 丢失，或重新上传改变文件 ID，
   明确报告当前入口缺口，不能由执行 Agent 手工注入 graph 状态冒充用户完整链路。
4. 找到现有用户工作区打开/下载文件的实际入口，说明 LocalFileStore outbound 文件
   怎样可见；只给 file_id、CSV 文本或主机路径不能判文件交付通过。
   若当前产品尚无文件访问入口，先报告接口缺口，由 Codex 补齐后再进入创建窗口。
   本次不增加企微附件上传/发送。
5. 确认候选网关额外依赖、工具 profile grant、文件 TTL、候选进程与生产会话的隔离方式。
   `sandbox_spec.build_spec` 是显式启用入口；最终启动前须固定
   AGENTSEEK_SANDBOX_BUSINESS_CONFIG 及其 SHA256。不得仅以导入成功当作工具可用。
6. 提出 .171 到 .172 的访问源地址、HTTPS 主机名或 IP、CA 信任位置，以及独立 broker
   token 的受控交接方案；Cube API key 留在 .172。不把凭据或完整身份正文写入事实包。

本机可准备 approved=false 草案，字段参照 sandbox_spec 的精确字段集：schema、approved、
endpoint、ca_file、broker_token_file、grants_file、grants_sha256、mirror_directory。
未定值显式标注待补；不以占位值调用 build_spec 或宣称通过生产读取器。

## 3. .172 汇入网关事实后准备节点方案

在新的准备目录记录以下具体选择，每项同时写出证据、拟议变更和恢复办法：

1. 独立业务 venv 的实际绝对路径及隔离验收记录；不将业务包装入 R1 venv。
2. 提议一个未占用的私网 IPv4 监听地址/端口，说明证书 SAN 与网关 endpoint 的匹配、
   签发来源、有效期和 CA 分发方式。列明是否需要防火墙变更及具体源/目的/端口。
3. 拟议业务根目录、business.sqlite 所在 store_directory、workspace_directory 和私有
   config 目录；列出 UID、0700/0600 要求、文件保留策略与停止服务后的只读恢复路径。
4. 新业务 run 的监督/manifest/身份 pins/安装链方案。旧 A run 已消耗额度，相关
   manifest/quota/fence/intent 均保留；如需第二监督实例，列出精确 unit、目录与安装步骤，
   等本轮最终方案批准后启用，不能复用旧状态或因新目录就视为重新获批。
5. 按 business_service 精确字段集准备禁用草案：schema、approved、bind_host、bind_port、
   certificate_file、private_key_file、permits_file、permits_sha256、store_directory、
   workspace_directory、plans。plans 每项为 owner_id/request_id/lifecycle_file/
   lifecycle_sha256/business_file/business_sha256；与 .171 的 request/owner/input 绑定一致。
6. 逐项列出创建链、W0、业务 plan 所需动态值的取得时机和写者。业务 plan 包含
   csv_approved 与 termination_approved，后续用户批准必须覆盖正常主动销毁与监督兜底。
   所有用户批准、精确输入绑定、配置摘要核对在创建前完成；创建后由程序连续推进。
7. 模板/python3 能力保持待活验。列明 guest 内执行预算、监督 120 秒、HTTPS 客户端预算
   与结果读取安排；沿用候选代码，不延长寿命。响应未知时只查结果与监督状态，不重提执行。

本轮草案保持禁用；含敏感字段的正文仅在各自私有准备目录保管。双方交换必要绑定数据
走既有受控路径；脱敏回传只放状态、摘要和非敏感配置选择，不发送完整批准正文。

## 4. 汇总与批准

.172 输出新目录中的脱敏准备报告和 SHA256 清单；通过用户通知 .171 只读拉取核验。
.171 将两端结论汇成一份 `BUSINESS_E2E_PREPARATION` 报告，普通提交执行分支并双端核验。
附一张表，逐项给出明确值或缺项：

| 项目 | 必须落实的内容 |
| --- | --- |
| 版本 | 代码候选、wheel、两端实际解释器/依赖、部署方式 |
| 网络 | 源/目的地址、端口、SAN、CA、拟议防火墙变更 |
| 文件与身份 | 当前轮文件输入方式、真实映射一致性、工作区打开入口 |
| 运行状态 | 新业务目录、新 run/监督与旧运行状态的关系 |
| 模型 | 实际 provider/model、工具可见性与所需配置 |
| 授权 | 一次创建、CSV 执行、持久化、正常终止、监督兜底的批准范围 |
| 凭据 | 分发责任人/受控路径；不记录值 |
| 时序 | 上传绑定→最终材料→用户窗口批准→真实问题；guest 期间无人工往返 |
| 恢复 | 网关/服务恢复办法，UNKNOWN 后只读核对，历史结果保留 |

归档判定为 BUSINESS_E2E_PREPARED_PENDING_APPROVAL，若存在输入或界面接线缺口则逐项列明。
Codex 审阅后先处理必要代码缺口，再给用户一份有具体地址/目录/变更/执行步骤的最终工单。
窗口先作为建议给出 UTC 与 Asia/Shanghai，不能替用户批准或沿用 9 月 17 日旧窗口。

## 5. 下一轮业务验收的固定判定线

执行顺序：普通问题确认不创建 → 用户上传/绑定 CSV 并发出固定问题 → 真实模型选择
run_sandbox_task → 节点创建与登记 → guest 生成 CSV → 节点持久化并读回 →
正常销毁且确认目标不存在 → 网关用户文件区回写 → 用户打开 summary.csv 核对。

记录真实模型/工具调用、一次创建、guest 执行、节点/网关/用户读取三个输出摘要与清理结果。
从预期 CSV 得到标准答案，与真实输出比较。workspace_pending 只补同步，reconciling 只读核查，
均不重复创建。由人工直接调用 broker 或固定模型脚本得到的结果只能作为分层证据。
本轮准备阶段不提前执行上述业务链。
