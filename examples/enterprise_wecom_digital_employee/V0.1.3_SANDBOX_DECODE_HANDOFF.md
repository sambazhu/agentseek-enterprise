## SDK静态核对与差异

开发端读取本地缓存cubesandbox==0.7.0的`cubesandbox/_commands.py`，完整文件SHA256：
`42d2fd5ee482d33c867a57c6d9795a0be60dd3e006ba2d17693734c98be581e6`。
未升级SDK或引入SDK运行依赖。.171可与其受控SDK源码逐字节比较；版本号相同不能代替源码摘要。

| 核对面 | 证据与处理 |
| --- | --- |
| 命令传递 | SDK shell包装使用cmd=/bin/bash、args=[-l,-c,cmd]；业务实际POST直接使用cmd=python3及[-I,-c,CSV_PROGRAM,data]数组。业务shlex只校验上游固定命令，不把带引号整串传给guest。没有证据支持本次shell拆词故障，保持请求不变。 |
| 请求编码 | process/envs/stdin及5字节大端Connect信封相符；端口80、Host路由、认证、超时、单次POST保持不变。 |
| 数据事件 | SDK JSON回退实现读取event.data.stdout/stderr的base64字符串，与业务字段路径相同。不因猜测增加任意信封兼容。 |
| 结束事件 | SDK接受status=exited、exit status N、exited with code N等；旧业务只接受整数exitCode/exit_code。新业务兼容明确status，并拒绝未知、冲突、布尔和缺失退出信息，不默认成功。 |
| Connect结束帧 | SDK允许flag=2且size=0；旧业务强制对空载荷解JSON。新业务接受空结束帧，但仍必须另有明确零退出的进程end，无末帧error且无尾随帧。 |

实测原SDK合成流“status-only零退出+空Connect结束帧”能返回stdout=ok，exit_code=0；
本候选对应测试通过。这是离线协议兼容证据，不是W14响应的重放证据。
SDK宽松UTF-8替换/状态子串搜索/缺结束帧等行为不照搬，业务仍严格完整校验。
R1冻结的m3_probe_protocol源码不修改，兼容层仅在业务worker。

## 16b与取证边界

工单的二分推理不完备：旧`_CommandState.event/data`和`_exit_code`也会抛ValueError。
旧明确非零退出/非空stderr则在应用JSON解析之前被合同拒绝；不能仅凭protocol认定程序异常退出。
本候选将失败拆分为：

- protocol：Connect帧/JSON/base64/事件形状/结束证据缺失或冲突。
- program：明确非零退出、进程error、非空stderr、stdout非法UTF-8、完整stdout不满足CSV结果合同。
- timeout/connect/contract/internal保持原有类别；诊断白名单共7种（含none），顶层8阶段不变。

完整stdout仍交给原decode_csv_result做全量校验，结果结构、base64、大小、CSV头与UTF-8不放宽。
只在业务session可选`diagnostics_enabled=true`时附加失败evidence，默认关闭、成功不附加。
evidence精确8键：substage、frames、frames_truncated、stdout_bytes、stderr_bytes、end_seen、
stream_end_seen、exit_code；
frames最多32项[flag,size]，其余为白名单枚举、布尔、有界整数或null。
不记录输出内容、异常消息、路径、headers、凭据；**十六进制前缀也可还原内容，因此不提供**。
stderr_bytes>0即表示有stderr，不另加内容字段。父进程日志在白名单校验后输出。

通过本候选转换器的parameters可选第15字段diagnostics_enabled透传至session可选第13字段；
旧14字段参数与12字段session兼容，service仍schema2精确12字段，产物仍16件。
只读readback、受控源预期摘要、不覆盖旧输出、所有批准位默认false的规则不变。
启用开关也是批准材料变化，须重钉参数→编译输入→session→service的摘要链，不现场手改。
