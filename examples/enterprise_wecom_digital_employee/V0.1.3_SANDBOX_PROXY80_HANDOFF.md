# 复验业务 HTTP 数据面端口校验修复

## 范围与前提

基线为 060a1fdcbbfd51bed1186f70140c2d67328df576。
执行方案 A：业务 validate_installation 的 proxy_port 精确值从 13080 改为 80。
只有该业务校验的一行运行代码改变；不泛化允许端口、不修改 R1、不改变 schema、预算或授权语义。
HTTP worker 仍由已钉摘要的 control 构造 http://127.0.0.1:80；Host 路由及认证头不变。
方案 D 的现场 HTTP 数据面证据沿用回传，不由本次离线测试冒充。

本工单交付代码、备料及隔离复验；不单独产生创建、清理意图或服务切换授权。
不要求重新做底层矩阵，也不改 .60、下载配置或生产分支。

## 核对调用路径与证据边界

1. BusinessBroker.dispatch 的 result 分支读取 store.snapshot，不构造 provider。
   无记录返回 not_found；不会进入 read_plan 或 validate_installation。
2. 无节点记录的新 execute 构造 provider，经 run_business → backend.authorize →
   provider.validate_request → session_for.validate_installation 校验 control。
   该校验在节点 store.reserve 和 lifecycle create 之前；拒绝不等于消耗创建额度。
3. 网关可能已经 reserve 本地镜像，因此“节点无记录”不代表两端都无意图。
   不得以节点 not_found 为由自动终态化、清库或释放旧执行权。
4. 源码和本轮回归证实旧校验拒绝 80，并解释 result 可通过而 execute 被拒。
   历史 W5/W6/W7 各次是否到达该分支，仍须分别引用当次版本、trace 和复现证据。
   不将其统一推断为所有历史 400 的已证实根因；W6 传输异常继续记未复现、未定因。
5. /health 存在性和 CSV 成功仍待真实执行。400/403/404 不视为就绪成功。
