# 复验 CSV worker 的 PlatformReader 端口兼容修复

## 范围与依据

基线 00ab573f71b219a5ca8cdfbfb50a57f7722cce03。
W11 的创建/attach/session_reconstruct 已通过，run 与 terminate 在 validation 阶段合同拒绝。
源码证实 perform 在两操作分流前构造 PlatformReader(**control)，旧构造函数要求端口>=1024，
必然拒绝业务已批准的80。这不是 broker validate_installation，也不是 supervisor pins 校验。
pins 校验在 run 的 identity 阶段，terminate 不走该段。

上轮13f9114只修了业务安装校验，漏了读取器约束；原worker测试整对象替换PlatformReader，
掩盖了该拒绝。本次承认并修复此测试覆盖缺口，不把测试通过表述成现场全部问题解决。
W11三毫秒日志未含具体行号；该确定性源码缺陷吻合观测，但其余配置仍须最终核验。

## 核对代码变化

1. PlatformReader 允许整数80，保留原1024..65535范围；其他低端口继续拒绝。
   endpoint HTTPS、CA校验、domain/key校验不变，不把控制面改成HTTP。
2. 业务安装层仍精确要求80，不新增任意端口授权；命令仍经本机HTTP CubeProxy。
   schema、预算、凭据、请求绑定、重试、清理和诊断协议均不变。
3. 新11项构造测试覆盖80/13080/边界端口、其他低端口、越界及错误类型。
4. 既有run/terminate/run_timeout三个worker测试改用真实PlatformReader构造函数，
   仅替换合成CA的TLS上下文生成与平台快照采集。网络仍为合成客户端，零真实平台访问。
   两操作能够越过真实构造校验，run检查HTTP80就绪与命令，terminate检查HTTPS DELETE。
   不将这些测试记为真实模板/网络兼容PASS。
