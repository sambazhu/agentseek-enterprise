# 复验 CSV 执行前就绪等待与失败诊断

## 范围与前提

以 W3 归档 48c8107b14cb2d1531f2dd47aba3169b70f76bf1 为基线。
本轮修复创建后立即发送命令、HTTP 全阶段固定 2 秒及子进程错误不可见的问题。
W3 冷启动未就绪是待现场验证的解释，不把时间线推断写成唯一已证实根因。
CubeProxy 关闭 access_log，零日志不能证明命令未发送。

本工单只交付备料、隔离复验及现有工件只读核对；不授权创建、服务切换或新探针。
无需追加 R1 矩阵。沿用工作区回写验收；下载 disabled，.60 不改。

## 核对新行为

1. 身份和密封回执校验后，经同一个 CubeProxy origin、guest Host 和凭据发 GET /health。
   保留原 49983 Host 路由，不把 CODE_INTERPRETER 的 49999 端口当成 envd RPC 端口。
   健康请求不读取正文，不运行命令；200/204 视为可继续。
2. 就绪阶段总预算 5 秒、最多 6 次，每次网络超时不超过剩余预算或 1 秒。
   只在 502/503/504、连接错误、连接/读取超时后再检查；间隔最多 0.2 秒。
   401/403/404、重定向等立即停止；不提供绕过健康检查的降级。
3. Process.Start 只发送一次，不重试 CSV 命令，也不重建 guest。
   HTTP 读取超时改为 15 秒，连接/写入/连接池超时仍为 2 秒。
   读取超时是单次等待预算，不冒充整次命令绝对截止。
4. 命令预算仍 15 秒；run worker 外层仍 25 秒，内部以 23 秒截止预留退出空间。
   就绪等待消耗既有预算；命令前再次核验 worker、guest 120 秒和批准有效期。
   预算不足停止；不延长 guest，不修改监督，不自动执行 B。
5. 子进程通过私有结果信封返回脱敏诊断，由父进程日志落档。
   仅记录 operation、stage、error、elapsed_ms、ready_attempts、http_status。
   stage 区分身份、就绪、命令、流读取、解析、终止等；error 为有限类别。
   不记录异常原文、URL、路径、headers、token、命令参数或 CSV 数据。
   子进程超时/信封不可得记录 worker_unknown，不能宣称已知精确失败点。
6. 有效输入下失败信封可能以子进程 exit 0 返回，但 result=null 在父进程强制拒绝。
   不能用子进程退出码代替业务成功；非法入口输入仍 exit 2。
   终止与 closeout 的原有独立路径保留。
