# 使用显式只读诊断入口查询既有沙箱请求

## 前提与范围

基线 c69ac1ebf931e25c1f9596df45b54ea4cc1b1dcc。
修复旧诊断工单要求只挂结果工具、却没有实际入口的接线缺口，不宣称 W6 传输根因已修复。
普通 build_spec 保持业务模式；原八字段批准配置、摘要校验和 HTTPS 客户端不变。
不新增 diagnostic_only 配置字段，不要求重签 grants 或新 request，不安装新节点 wheel。

## 核对实际限制

1. 新入口为 enterprise_wecom_digital_employee.sandbox_spec:build_diagnostic_spec。
   必须显式选择；失败不回落业务入口。要求 WORK=false 和镜像 business.sqlite 已存在。
   缺镜像即拒绝，不用空库替代旧账本。
2. remote_csv_tools 在此入口只返回 get_sandbox_task_result。
   run_sandbox_task、read_sandbox_csv_result、call_mcp_tool 不注册到图的工具节点。
   不装配 Work、MCP、员工记忆工具或技能；仅使用 StateBackend，不给宿主文件/执行 backend。
3. 保留真实 DeepAgent 图、ToolRuntime、网关身份上下文和 asyncio.to_thread/BusinessHttpClient 路径。
   模型请求在同步/异步两种路径均强制只绑定 get_sandbox_task_result。
   工具分发也只允许此名字；模型伪造 write_file/task/execute 等调用会在 handler 前拒绝。
4. 口径必须准确：DeepAgents 内建处理器仍可能存在于内部 ToolNode；不能写成内部 ToolNode 恰一项。
   它们不向模型暴露且分发被拒绝，另有文件权限全拒兜底；创建工具本身根本未注册。
   不通过现场修改图、篡改 tool 字典或仅靠提示词隐藏工具。
5. 诊断结果不检查或宣传新授权，grant_available 固定 false；不启下载签发。
   无历史任务返回 no_task，不创建请求。既有未决任务沿原 recover 查询节点；
   not_found 不闭合、不释放额度、不重试 execute。
6. “只读”指无创建/执行操作；既有恢复查询可依据节点权威结果更新镜像，
   成功结果还可能补写用户工作区。不能将其描述成整个过程绝对零写入。

## .171 离线复验

接收本候选并普通同步双远端；使用原测试 venv，不安装/升级依赖。
在候选根目录设置 VERIFY_PYTHON 为已有解释器绝对路径，运行：

```sh
PYTHONPATH=contrib/agentseek-files/src:contrib/agentseek-wecom/src:contrib/agentseek-execution/src:examples/enterprise_wecom_digital_employee/src \
"$VERIFY_PYTHON" -m pytest -q \
  contrib/agentseek-files/tests contrib/agentseek-wecom/tests \
  examples/enterprise_wecom_digital_employee/tests/test_sandbox*.py \
  examples/enterprise_wecom_digital_employee/tests/test_agent_harness.py
```

开发端 Python 3.13.3：287 passed（277+10），既有类型的 Pydantic/websockets 警告。
新增测试从公开 build_diagnostic_spec 构图：模型实际绑定名单恰一项、真实 loopback TLS result 查询、
未注册创建/MCP 工具、伪造文件写/委派/执行被拒、WORK 开启拒绝、错误工具集拒绝、
缺批准配置拒绝、缺镜像不建库、无任务不查询 grant。合成节点 create 事件始终为零。
内部处理器拒绝测试使用有效形状参数，不以参数解析失败冒充分发拒绝。
节点代码和 HTTP 专项未改，沿用 bf4602f 对应记录；不重跑节点底层矩阵或重装 .172。

## .171 受控诊断步骤

离线复验通过后，在用户已批准的只读诊断范围内执行；若范围/条件变化则先报告。

1. 切换前只读核验 W6 既有请求与实际 owner/session，以及其仍为 reconciling；
   保留一致性快照。无法唯一定位、账本缺失或已终态则停止，不制造未决状态。
2. 保持原八字段批准配置及凭据受控，四根源码路径统一指向本候选。
   实际运行时 spec 设置为
   `BUB_LANGCHAIN_SPEC=enterprise_wecom_digital_employee.sandbox_spec:build_diagnostic_spec`。
   WORK=false，下载 disabled；不重传 CSV、不发执行问题、不修改 .env。
   此处是配置值说明；实际启动与恢复沿用现场核验的标准命令，本开发轮未启动现场网关。
3. 核验实际加载模块及启动日志：
   `sandbox_diagnostic model_tools=get_sandbox_task_result business_execution_tools=absent other_dispatch=denied`。
   核对公开入口与离线工具集合结果；不得使用普通 build_spec 冒充。
4. 就绪后通知用户只发送一次“仅查询此前沙箱任务状态，不执行新任务”。
   保存实际工具调用次数和白名单 business_exchange 日志，按 exchange_id/attempt/PID/thread_id 对齐。
   提示词要求一次查询不是次数硬门禁；若模型重复查询，必须如实记录，不声称恰一次。
5. 不以 shell 直调客户端代替实际网关图；不挂运行工具，不注入新授权。
   .172 零重启/配置/账本操作。网络阶段未知、not_found 或查询失败均停止报告，不清意图。
6. 结束后恢复原生产 spec 与启动路径，核对健康及 .env 未变。
   记录意图前后状态；已批准恢复查询造成的合法镜像变化须明确列出。
