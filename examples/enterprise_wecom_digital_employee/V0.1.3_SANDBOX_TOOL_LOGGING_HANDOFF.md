# 复验沙箱工具观测日志

用于 W19 成功收口后的日志修复候选。基线为 `6842f5b`。
本轮仅源码与合成离线复验，不授权现场重启、真实工具调用、文件发送或 guest 创建。

## 1. 核对最小改动

`sandbox_remote.observed` 的 start/complete/failed/cancelled 改走应用既有 loguru logger。
格式由 `%s` 改为 loguru 的 `{}`；工具名、event、调用摘要、状态白名单、current 和请求摘要不变。
不添加 sink/handler，不修改 stdlib root、全局日志级别、环境键或应用日志配置。
不把正常观测提级为 WARNING，不使用 exception()/异常堆栈日志。

`src/agentseek/__main__.py` 已使用 loguru 配置 stderr 与 Logfire 接收端，本补丁复用该通道。
loguru 已在既有运行依赖中；无依赖升级、无新业务 wheel、无节点重装。
同模块既有 `gateway_failure` 的 stdlib WARNING 和执行包的 HTTP trace 不在本次修改范围。

## 2. 核对修复证据

新增独立子进程测试复现 stdlib 默认 WARNING、root/module handlers 均为空。
在此条件下，仅配置一个测试用 loguru INFO 接收端，查询两次无效合成 grant：
每次获得一条 start 和一条 complete，合计四条；stdlib 配置前后不变。
该测试在 898130a 基线失败，在本候选通过。

另七个用例覆盖：三工具正常路径、拒绝、取消、未捕获 BaseException、应用接收端级别过滤。
验证事件关联、真实格式化、每个接收端无重复、INFO 级别、原始调用 ID/请求 ID/CSV/凭据/异常正文不入事件。
本轮既有两项观测断言改为捕获真实 loguru 通道，不再用 caplog 人为调高 stdlib INFO。

## 4. 回报范围与停止条件

回传新目录：脱敏报告、完整源码摘要、实际命令和测试结果、接线与日志接收端证据。
判定上限 `TOOL_LOGGING_OFFLINE_PASS`，不宣称现场日志已经实证。
每个事件只由本模块发射一次；若应用主动配置多个 sink，各 sink 接收一次是正常扇出。
若应用禁用模块或将所有 sink 提到 WARNING，INFO 仍按应用配置过滤；本模块不强制绕过。
schema 校验前拒绝、未进入工具、进程硬杀等情况仍可能无完整事件。

现场继续 NFD-only、broker inactive、监督现役，W19 全部历史保留。
采用另批；只需网关源码采用，不动节点 unit/venv/材料或额度。
不得为验证日志专门创建沙箱、重跑 W19、实发文件或打开新业务窗口。
后续自然发生的已批准业务调用可提供现场证据；回退仍重查 NFD 账本/outbox 硬门。
