# 补齐 CSV 工作区文件打开入口

## 本轮交付

在 9487fb39cb8c38e23788238252a10a21124347ad 归档基础上补齐 G2 工作区读取接口。
节点执行代码及 wheel 不变；.172 的 44/2、835 和业务清单通过记录继续沿用。
本候选只涉及网关 examples、agentseek-files 和 agentseek-wecom；零新增依赖。

用户点击模型返回的工作区链接，进入网页后点击“下载 summary.csv”，取得网关文件区的
实际 CSV 字节。网关 HTTP app 承载路由，不调用企微媒体接口、不启用 Work 报告交付。
这是单文件打开入口；不宣称已有工作区列表 UI。

链接在有效期内允许重复下载，默认 600 秒，最长 3600 秒，且不超过文件保留期。
持有链接即可读取该文件，这是短期 bearer 授权，不提供第二次用户登录或防转发保证。
权限范围在签发时绑定可信 tenant/user/session，读取时核对落盘元数据与文件摘要。
失效链接或签发失败由 get_sandbox_task_result 只读更新，不重复执行任务。

## 准备最终部署配置

在禁用草案中补充以下配置建议，不修改当前运行 .env：

```dotenv
AGENTSEEK_WORKSPACE_DOWNLOAD_MODE=signed_link
# 示例域名；替换为用户设备可达且证书有效的实际 HTTPS origin。
AGENTSEEK_WORKSPACE_DOWNLOAD_BASE_URL=https://files.example.com/ai-server/workspace-files
# 示例绝对目录；创建与启用须纳入最终部署批准。
AGENTSEEK_WORKSPACE_DOWNLOAD_GRANTS_DIR=/var/lib/agentseek/workspace-downloads
AGENTSEEK_WORKSPACE_DOWNLOAD_TTL_SECONDS=600
```

该目录需网关 UID 所有、0700；程序在其中创建 0600 的授权 SQLite。
网关 Channel 和 sandbox_spec 必须看到同一环境配置、同一 FilesSettings 根目录。
保持 AGENTSEEK_WORK_ARTIFACT_DELIVERY_MODE 原值即可。

根据现有网关反代填写真实地址：.172:13100 是节点执行端点；用户下载链接应指向
.171 网关的用户可达 HTTPS 地址，两者不得混用。核对反代是否已经转发整个 /ai-server/
或需增加 /ai-server/workspace-files 的 GET/POST 路由，将必要变更交最终工单批准。
不将文件区作为静态目录暴露，不记录链接全文或 redeem 请求体；浏览器 fragment
本身不会进入 HTTP URL，但对话正文中的完整链接仍应视为短期访问凭证。

本轮只做本地回归和草案更新，不启服务、不重启生产、不创建 guest。
最终窗口可先用合成的合法 outbound CSV 验证打开页/下载/摘要，再执行真实业务。
合成下载冒烟不能记为真实沙箱产物交付通过。

## 归档口径补正与准备顺序

G1=上传文件跨轮与身份绑定；G2=用户文件打开入口；G3=SITE_PREP 文档本体；G4=固定任务文件。
资料到货只能解除 G3/G4 或补充 G1/G2 证据，不自动证明 G1/G2 通过。

1. LocalFileStore 的 file_id 是输入 SHA256 的前 16 位：同字节重传不会必然换 file_id。
   重启会丢当前会话内存缓存；仍需重新建立 current_files 并核对完整 scope、记录与输入摘要。
   不凭 file_id 相同推定跨会话授权相同。
2. permit.principal_sha256=SHA256(broker token UTF-8)，不是 owner_id；owner_id 按候选
   scoped_owner 的三键顺序与紧凑 JSON 序列化计算。受控材料直接调用候选函数，不手写近似公式。
3. 显式 sandbox_spec 无配置会拒绝构建；默认 agent spec 才是不挂沙箱工具。
4. 网关 spec 会缓存，启动时批准配置引用的摘要也是固定的。实际上传、取得绑定、最终批准、
   切候选和触发问题的具体顺序必须由 .171 核对；改 .env 不会刷新已启动进程。
   若需重启后同会话重传相同 CSV，必须在创建前验证完整绑定和 current_files；无法满足就
   如实提交接线缺口，不通过修改 graph 内存或跳过摘要检查来凑通过。

旧原件保留；.171 将以上勘正另附到两端汇总，.172 继续原定 11 字段草案核对。

## 最终验收与恢复

最后一轮须看到真实模型选择工具、真实 guest 输出、节点持久化、目标消失、网关回写，
以及用户实际下载文件的摘要与预期一致。工具返回 download.available 只代表链接已签发。
workspace_pending 表示文件回写待恢复；download_pending 表示文件已保存、链接待恢复。
以上状态只使用查询结果继续恢复，不重复创建。

下载开关恢复为 disabled 并按最终工单恢复网关后，路由不再注册；文件与授权账本保留。
本轮不合并 production，不改变 .172 安装/监督，不重跑已通过的节点底层矩阵。
