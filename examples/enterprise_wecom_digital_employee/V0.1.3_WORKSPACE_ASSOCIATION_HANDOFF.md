# I05 工作区产物关联与投递回执合同

## 范围与判定

| 项 | 值 |
| --- | --- |
| 基线 | f3605b3；同内容现状特征化后的四项已确认合同实现 |
| 判定上限 | WORKSPACE_ASSOCIATION_OFFLINE_PASS；非现场端到端验收，非 I01–I07 全完成 |
| 运行面 | 网关工具与原生投递；零业务 wheel、节点、依赖、配置键变更 |
| 现场边界 | 不部署、不重启、不 SSH、不创建 guest、不实发、不清历史；.172 无交付动作 |
| 开发恢复记录 | 前一临时工作树已不存在；本候选在持久工作树重新实现、重新全量测试；不沿用中间版本测试结论 |

## 四项合同

| 项 | 实现 | 不代表 |
| --- | --- | --- |
| 文件级去重 | initial key 仍为 scope/recipient/workspace file_ref；新任务不改变 key | 新任务自动获得第二次发送授权 |
| 不可变归属 | 成功 attempt 与完整 request、scope、artifact_ref、内容摘要、工作区记录快照一同持久化；ready 行不由应用覆盖 | 每个任务都有独占工作区路径；相同内容可多对一 |
| 复用回执 | 重复调用返回原 delivery_id/status，附 reused_receipt=true、delivery_notice=已有投递记录，本次未再次发送 | 原 api_accepted 等于本次刚发送或用户已收到 |
| 查询不续期 | 查询只读关联、元数据和内容；不调用 store_bytes；跨日查询仍读原副本 | 已过期文件重新物化或历史归属自动回填 |

## 关联存储

| 项 | 合同 |
| --- | --- |
| 路径 | 网关 BusinessStore 的 business.sqlite 同目录，新文件 workspace-bindings.sqlite |
| 权限 | 父目录当前用户所有、0700；数据库当前用户所有、0600；符号链接拒绝 |
| 创建时机 | run_sandbox_task 首次提交返回 succeeded 且 cleanup_confirmed 后；查询不建库、不迁移 |
| 行主键 | attempt；identity 含完整 scope/request/attempt/artifact_ref/内容 SHA256 |
| 状态 | pending 先独立提交；文件写入或复用验证成功后 pending→ready；中断不自动重试 |
| 私有字段 | request 可能含指令正文；仅私有数据库保存，不写日志；非对恶意本机管理员的防篡改证据库 |
| 读回 | 业务账本重新核 owner/request/outcome，读 artifact 字节；再核文件记录快照、scope、路径、摘要、大小、期限、实际字节 |
| 公开工具关联 | workspace.association：state/request_id/attempt/artifact_ref/file_ref/sha256；无私有路径、无收件人、无凭据 |
| 同日同内容 | 已存在副本通过验证才复用；不覆盖 created_at/expires_at；新 attempt 另建关联 |
| 并发范围 | 同一关联数据库内 SQLite 写事务串行；不同数据库或外部通用写入者不受此锁保护 |
| 外部文件变化 | 元数据或字节与快照不符即拒绝；不自动修复、不更新旧关联 |
| 不变项 | 通用 LocalFileStore.store_bytes 行为、文件路径/ref 算法、业务账本 schema、NFD 判重键均不变 |

## 兼容性与失败边界

| 情形 | 返回/行为 |
| --- | --- |
| 历史成功但无可信关联 | execution_state=succeeded、state=workspace_pending、workspace unavailable；不依据同名/同 SHA 回填 |
| 已存在映射且有效 | 查询返回关联；数据库内容、文件 metadata 和保留期不变 |
| 过期/缺失/篡改/符号链接/非普通文件 | 工作区 unavailable；不刷新期限、不生成另一副本 |
| 首次写入中断或 ready 回执前崩溃 | pending 或无映射；只读查询不补写；须另行设计并审批恢复流程 |
| HTTP 结果丢失/取消 | 现有执行状态恢复仍保留；没有已完成的发布映射则不自动补写工作区；不得重新执行任务 |
| 明确索取历史工作区文件 | NFD 仍按现有 scope/文件期限/精确选择/可信收件人合同处理；不冒充当前任务产物 |
| 同副本已有失败/uncertain 记录 | reused_receipt=true，原状态保留、零自动重试；文案不暗示已成功 |
| 用户明确重发 | 新真实入站 message_id 参与 key；重复调用同次重发仍判重 |
| 模型呈现 | 工具结果和 docstring 要求明确“本次未再次发送”；本候选不新增 NFD 自由文本确定性输出守卫，不声称模型文案绝对不可违背 |
| 原沙箱输出守卫 | 不变；执行成功、工作区回写、文件投递三者仍须分别核验 |
| 回退 | 采用前另出操作单；旧代码查询会重新写工作区，不能宣称回退仍满足查询不续期；关联数据库须保留，NFD 回退硬门照旧 |
